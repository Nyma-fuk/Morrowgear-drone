# Morrowgear: Drone Command

制御アーキテクチャ、Waypoint/Wing同期、通信断時の挙動、および実ドローンへ展開する場合の設計差分は、[Morrowgear Drone 制御アーキテクチャ・実機化設計指針](docs/architecture/MORROWGEAR_DRONE_CONTROL_ARCHITECTURE.md)を参照してください。

## v0.18.1 Lifecycle and Logistics

- Dockを3段27枠へ拡張し、既存9枠、回収バッファ9枠、共通補給バッファ9枠を一つのサービス拠点として運用する。
- Power Cellと3段階バッテリーに加え、石炭・木炭をDock内蔵発電機の燃料として使用できる。蓄電容量は装着バッテリーに応じて4,000から18,000へ拡張する。
- 推進、センサー、作業系の状態値を追加した。損傷で劣化し、推進は消費電力、Scoutは走査範囲、Engineerは作業間隔へ影響するが、編隊速度は変えない。
- 劣化機は飛行安全と戦闘状態を尊重してDockへ帰還し、銅、鉄、Morrow Alloyを消費して最も劣化した系統から整備する。
- Visorへ集約状態`SYS`、整備対象機数と影響Wing数を追加した。機体格納時も3系統の状態を保持し、旧形式の格納機は健全値として移行する。
- Overworld、Nether、Trial Chambers、Endの段階進行と、かまどを使うMorrow Alloy製造を資源契約試験で固定した。

- 戦術UIの機体一覧を緊急度、Wing、役割、機体IDで固定ソートし、Shift範囲選択と先頭・前頁・次頁・末尾移動を追加した。

## v0.11.4 Field Cargo and Autonomous Recovery

- EXCAVATE・FORESTRY・ORE OPSのCargoは、64個、9スロット、積載開始から5秒、または作業完了のいずれかで搬出を開始します。
- 現場では半径5.5ブロックの任務由来ドロップをまとめて回収し、古いアイテムや別任務のドロップは対象にしません。
- Engineerは対象ブロック中心へ突入せず、周囲の衝突しない作業姿勢を選んで採掘・伐採します。
- 各担当機は依存する作業の完了を確認して自律離脱します。Dock割当機は着艦し、未割当機はプレイヤーへ帰還後、追従警戒へ移行します。
- フィールド実機試験は固定時間で打ち切らず、Cargo搬入、全ロール完了、自律帰還開始を条件として判定します。

## v0.11.3 Autonomous Field Recovery

- EXCAVATEおよびFORESTRYのCargoは、作業台帳と地上ドロップの両方を監視し、回収物が増えない状態を2秒確認してから任務完了と判定します。
- 搬入先が未指定または失われた場合、Cargoは作業地点周辺の読み込み済みコンテナから、空き容量のある最寄り候補を自律選択します。
- Cargoは地上アイテムを回収して指定・自動選択コンテナへ搬入し、積荷が残る場合は完了扱いにしません。
- Wing内の全担当機が完了した後、Dock割当機は自動帰投し、Dock未割当機はプレイヤー位置へ帰還します。

## Minecraft Launcher

- 公式Launcherの起動構成`Morrowgear Drone (Latest)`は専用ゲームディレクトリ`%APPDATA%\.minecraft\morrowgear`を使用します。
- `gradlew.bat build`が成功すると、配布用JARを一時ファイルで完全検証してから、専用`mods`フォルダの`morrowgear-drone-latest.jar`へ原子的に同期します。MinecraftがJARを使用中の場合は既存ファイルへ一切書き込まず、検証済み更新を保留します。Minecraft終了後の次回ビルドで安全に反映されます。
- 過去の`morrowgear-drone-*.jar`は同期時に削除するため、複数バージョンの同時読込を防ぎます。
- Launcherから`Morrowgear Drone (Latest)`を選んで起動すると、最後に成功したビルドを読み込みます。
- 自動同期だけを再実行する場合は`gradlew.bat syncLauncherMod`を使用します。

## v0.11.2 Scout Data Link and Field Choreography

- Engineer単独任務はアンカー近傍の局所調査に限定し、Scoutを含む複合任務ではScoutだけが指定領域全体を走査します。
- Scoutの走査台帳には対象ブロックに加えて空間、固体、流体の調査数を記録し、同一任務IDのEngineerへ対象座標を共有します。
- EngineerはScoutの全域走査が完了するまで`ENGINEER / DATA LINK`で待機し、完了後に共有された全対象を処理します。
- Scoutは走査後も`SCOUT / WORK ORBIT`で作業円を旋回し、Engineer完了後はCargoへ随伴します。
- Cargoは回収物が発生するまで`CARGO / HOLDING ORBIT`で待機し、回収、搬送、完了へ遷移します。
- Securityは複合任務へGUARDとして参加し、Engineer作業護衛からCargo搬送護衛へ引き継ぎます。
- Dock上の機体へ直接フィールド任務を割り当てた際に着艦フラグが残り、飛行中もローターが停止する不具合を修正しました。

## v0.6.6 円錐型の多層哨戒

- 13機以上の地点哨戒で、下層ウイングほど広く、上層ウイングほど狭い独立円軌道を使用する。
- 層間の半径差は1層あたり0.65ブロック、全体で最大7.2ブロックとし、100機規模でも過度に巨大化させない。
- 円弧への進入中から最終旋回まで同じ層半径を維持し、進入完了時の横滑りを防ぐ。
- 1ウイング時の旋回半径、1ウイング最大8機、ウイング間を結合しない制御は維持する。

## v0.6.5 ウイング単位の哨戒進入

- 哨戒開始判定を任務全体や`MOVING`機だけでなく、コホートIDごとの全ウイング構成員から算出する。
- 正常な`MISSION_CONVERGING`機が残るウイングでは、リーダー単機の先行旋回を禁止する。
- 初回集合と到着を完了したウイングを、同じserver tickでまとめて独立旋回層へ移す。
- Recovery中の未合流機だけが残る場合は、ウイングの60%以上が到着すれば先行哨戒を許可する。
- 旧バージョンでリーダーだけが旋回へ入ったウイングは、到着した後続を既存の旋回位相へ直接復帰させる。
- 2ウイング目以降も、最初のウイングが確立した共有位相を使いながら固有の高度層へ進入する。

## v0.6.4 MOVINGと追いつき制御の分離

- `MISSION_CONVERGING`を任務開始時の初回集合専用とし、編隊巡航開始後は距離を理由に戻さない。
- 巡航中にスロットから遅れた僚機は、`MISSION_MOVING`を維持したまま一時的な`CATCH-UP`制御へ入る。
- CATCH-UPはスロット距離7.0ブロックで開始し、3.5ブロック以内で解除するヒステリシスを持つ。
- CATCH-UP機だけ最大1.08 block/tickを許可し、リーダーと通常編隊は最大0.96 block/tickで任務を継続する。
- 後続が11ブロック以上遅れた場合にリーダーを減速・待機させる処理を撤去した。
- 巡航中の僚機は常にリーダー基準の固定隊形スロットを目標とし、距離状態によって別目標へ切り替えない。
- 戦術UIへ`CATCH-UP`を同期表示し、任務フェーズと個体の速度補正を区別できるようにした。

## v0.6.3 独立ウイング空域と遷移安定化

- 大規模任務のウイング同士を結合せず、同一任務IDと目的地を共有する独立コホートとして維持する。
- 任務航路軸を基準に各ウイングへ8.5ブロック間隔の水平アンカーと3.4ブロック間隔の高度層を割り当てる。
- 地点哨戒ではウイングごとに3.8ブロック離した独立旋回層を使用し、同一点への集中を防ぐ。
- 追従時のウイングリングも3.2ブロックずつ高度分離する。
- 合流後100tickは分断再判定を禁止し、その後も6回連続で隊形崩壊を検出した場合だけ再収束する。
- 各ウイングの左右基準を共通の任務航路軸へ固定し、リーダーごとの向きの差で航路が交差しないようにした。
- 8機ウイングの内部隊形を非対称な部分星型からデルタ隊形へ変更した。

## v0.6.2 大規模編隊の階層制御

- 13機以上の任務編隊を最大8機のウイングへ分割し、合流、速度同期、隊形維持をウイング単位で処理する。
- 合流速度の参加数を任務全体ではなく所属ウイング内で算出し、大編隊が永久に未合流扱いになる問題を修正した。
- 複数ウイングの後続機を誤った単一リーダーへ集めず、コホートIDごとに同期合流させる。
- 隊形の実寸を分断閾値へ含め、大きな星型・デルタ隊形を異常散開と誤判定して再収束する問題を修正した。
- 地点哨戒は予定総数分の円周スロットを最初から予約し、後続ウイングを単位として追加する。
- 追従時の9機目以降を8機単位の同心リングへ配置し、各リングの円周全体へ均等配置する。
- 所有機一覧をserver tick単位で共有し、数十機時に同じ512ブロック検索を機体ごとに繰り返さない。

## v0.6.1 同期合流と編隊一斉加速

- 後続機を予約スロット到着順に個別昇格させず、正常な後続機が全て到着するまで`MISSION_CONVERGING`を維持する。
- 全機が2.8ブロック以内へ入った同じserver tickで`MISSION_MOVING`へ一斉遷移する。
- 合流中はリーダーの速度上限を維持し、一部到着による段階加速と再離脱を防ぐ。
- 同期合流後は全機が通常の最高編隊速度で目的地へ向かう。
- Recovery機は同期判定から一時的に除外し、正常編隊を永久待機させず、復旧後に再合流させる。

## v0.6.0 旋回高度の安定化

- 旋回中心だけでなく、旋回円周とその内外0.9ブロックの地形高を事前評価する。
- 同じ任務の全機が共有する安全な旋回面を20tick間保持し、個別機の高度判断の競合を防ぐ。
- 新しい障害物に対する上昇は即時反映する一方、下降は4回連続の安全確認後に0.35ブロックずつ行う。
- 1ブロック以内の地形高変化を不感帯として扱い、木や崖の境界での上下反転を抑える。
- 旋回中に局所回避が必要な場合は同じ高度面の横回避を優先し、上昇は横方向に逃げ道がない場合だけ行う。

## v0.5.9 高速合流と到達可能な追跡監視点

- 通常巡航速度を0.44、長距離追いつき速度を0.96 block/tickへ引き上げた。
- 分散収束機は予約スロットまで16ブロック以上ある場合、最大1.08 block/tickで合流する。
- 8ブロック以内から制動し、7ブロック以内ではリーダー速度に接近速度を加えて予約スロットへ着列する。
- 近距離ではリーダー速度へ明示的に同期し、高速接近後の通過、蛇行、再接近を抑える。
- 地下の追跡対象には直上地表、水中・溶岩中の対象には液面上の安全な観測点を設定する。
- 到達不能な対象座標と流体回避の競合を解消し、安全観測点への到着後に`TARGET WATCH`へ遷移する。

## v0.5.8 収束中の隊形形成と高速旋回進入

- 分散収束機を狭所用の後方列へ集める方式から、完成隊形の予約スロットへ直接収束する方式へ変更した。
- 任務インデックスから固定した隊形順位を使い、接近中の距離変化で合流スロットが入れ替わらないようにした。
- 合流済み機も予定総数のデルタ・縦列・星型を最初から使用し、参加機数の増加による隊形の作り直しを防止した。
- 合流判定後も同じスロットを維持するため、分散収束から隊形移動へ連続的に遷移する。
- 円軌道への展開時間を120tickから50tickへ短縮し、前半で素早く円弧間隔を整える補間へ変更した。
- 地点哨戒の旋回速度を0.038 rad/tickへ引き上げた。

## v0.5.7 旋回進入と隊形視認性

- 隊形移動から地点哨戒へ入る前に、縦隊へ並び直す処理は行わない。
- 目的地へ最初に到達したコホートリーダーを旋回先導機とし、後続機は参加順位どおりに同じ円弧を追う。
- 進入角を全参加機で共有し、約6秒かけて追尾列から均等な円周配置へ滑らかに展開する。
- 追従開始時も同じリーダー先行型の旋回進入を使用する。Recovery機は従来どおり実働スロットから除外する。
- 通常速度を0.38、長距離追いつき速度を0.82 block/tickへ引き上げた。
- デルタ、縦列、星型の左右・前後・高度間隔を広げ、リーダーの待機前進量を1.2ブロックへ短縮した。
- 地点哨戒の旋回速度を0.032 rad/tick、開放空間の追従旋回を0.018～0.038 rad/tickへ引き上げた。

### v0.5.6 リーダー削除時の即時継承

- 機体削除前に同一コホートの後継リーダーを確定する。
- 健全機がない場合も、Recovery段階、プレイヤー距離、バッテリー、機体IDから暫定後継を選ぶ。
- リーダー以外の削除でも残存機の参加順位を詰め直す。
- 権限移譲と順位更新後に、光源除去と機体破棄を実行する。
- 削除済み機体IDがリーダー欄やコホートIDへ残る状態を防止する。

### v0.5.5 追従リーダーの権限移譲

- 追従リーダーがRecoveryへ入った時刻を記録・保存する。
- Recovery開始から5秒以上経過して`RECOVERY-3`の場合、またはRecoveryが12秒継続した場合にリーダー権限を失効させる。
- 健全機のうちプレイヤーに最も近い機体を後継リーダーにする。同距離ではバッテリー残量、機体IDの順で決定する。
- 新リーダーをランク0へ移し、健全機、Recovery機の順にコホートを一括再編する。
- 旧リーダーは復旧後も自動復権せず、僚機として現在の隊形へ再合流する。

### v0.5.2 地点哨戒の部分開始

- 完成編隊が到着した場合は、参加機をまとめて地点哨戒へ移行する。
- 未合流機が残っていても、到着済みコホートが参加機の60%以上に達した場合は地点哨戒を開始する。
- 明示的なRecovery機が残る場合は、到着済みコホートの規模にかかわらず哨戒を停止させない。
- 遅延機は哨戒中のリーダーと隊列スロットへ接近し、到着後に地点哨戒へ追加する。

### v0.5.1 飛行姿勢と任務編隊

- 任務編隊の対象は、一度の地点指定または追跡指示で同じ`missionId`を受け取った機体に限定する。
- 目的地に最も近い機体をリーダーとし、合流済み機は到着順の隊列スロットを維持する。

- 前進時の機首下げ、上昇時の機首上げ、左右移動時のロールを機体座標に合わせた。
- ヨー追従速度を飛行速度に応じて調整し、進行方向に対する長い横滑りを抑えた。

## 操作

- コントローラーを右クリック: 統合戦術管理UIを開く
- フィールドドローンユニットを右クリック: ドローンを展開する
- Dockアイテムを右クリック: 3x3の空間へDockを設置する
- UIのユニット行: 個別選択
- UIの全選択: 所有する全機を選択
- UIの即時命令: 選択機へ任務を割り当てる
- 地図上の生物をダブルクリック、または機体を生物マーカーへドラッグ: 追跡任務を割り当てる
- 地図上の空き地点をダブルクリック、または機体を空き地点へドラッグ: 地点任務を割り当てる
- 一覧の`|< < > >|`: 先頭、前頁、次頁、末尾へ移動する
- `Ctrl`+クリック: 選択を個別に追加・解除する
- `Shift`+クリック: 基準機からクリックした機体まで範囲選択する
- `/morrowgear_base create`: 現在地を中心に防衛基地と32機の着艦済み編成を生成する
