# Morrowgear: Drone Command v0.11.1 総合検証結果

## 1. 結論

2026年8月21日、Minecraft Java Edition 26.2、Fabric Loader 0.19.3、Fabric API 0.156.0+26.2、Java 25のローカル環境で総合検証を実施した。

| 層 | 規模 | 結果 |
|---|---:|---|
| ロジック自動試験 | 40スイート / 1,383件 | PASS 1,383 / 1,383 |
| Minecraft内ランタイム試験 | 33ケース | PASS 33 / 33 |
| セーブ・Minecraft再起動試験 | 4ケース | PASS 4 / 4 |
| 実UI目視試験 | 24機 / 4 Dock / 複数コンテナ | PASS |

現環境で実行可能な正常系、準正常系、異常系はすべて合格した。

## 2. 今回追加した防御策

- クライアント命令を256文字以内へ制限し、未知命令、欠落引数、不正な任務ID、範囲外座標・半径・編成数を拒否する。
- 任務数を1～128、隊列番号を0～任務数-1へ正規化する。
- バッテリー、Wing ID、作業半径、警戒半径をロード時に検証する。
- 欠損機を除いて編成を縮小する際、残存機を安定順に再採番し、編成数より大きい隊列番号を残さない。
- 格納時はサバイバルでDrone Unit、装着モジュール、Cargo内容を返却してから機体を除去する。
- Dock未割当時は無反応にせず、ゲーム内ログへ理由を表示する。
- UI寸法と各スクロール位置を画面サイズ、件数、表示領域から算出し、範囲外へ出ないよう制限する。
- ランタイム試験は各ケースのコンテナを初期化し、同じワールドで繰り返しても前回結果に汚染されない。
- 未読込チャンクの走査位置は破棄せず保留キューへ戻し、読込後に再走査する。Engineerも未読込対象を破壊しない。
- 同じ任務IDでも種別、中心、半径が変わった場合は古い共有走査台帳を再利用せず、新しい条件で置換する。
- フィールド任務の高さはクライアント表示値を採用せず、サーバー側の実地形から再計算する。
- Engineerは指定地点周辺を先行調査して近傍の鉱石・木材を優先処理し、その間も広域走査を継続する。
- 鉱石採掘、範囲除去、森林作業はEngineerを含む選択時のみ有効化し、Scout・Cargoだけでは実行命令を出さない。
- UIは「左で対象選択、中央で状況確認と地点指定、右で命令、下で任務と兵站監視」の操作順へ統一した。
- 役割不一致の任務、未着艦時のモジュール換装を無効化し、理由を画面内へ表示する。
- STOREは3秒以内の再押下を必要とする確認方式とし、誤操作による機体格納を防ぐ。
- `R16`などの省略表記を`半径 16 blocks`へ変更し、任務指定中は対象操作と半径を常時表示する。
- Dock帰投を共通3次元ナビゲーションへ接続し、最終着艦以外は衝突回避経路を使う。
- Dock進入は上空と前後左右の5経路を機体サイズの衝突回廊で評価し、利用可能な入口を自動選択する。
- 局所迂回とRecoveryは前後左右・斜め・上下を対称に評価し、天井下でも下降を含む退避経路を選択できる。
- 標準経路の探索範囲を超える巨大障害物では、左右8～72ブロック、上下最大68ブロックへ段階的に戦略ウェイポイントを展開する。
- 戦略迂回中は選択方向とウェイポイントを保持し、編隊反発で経路から押し戻されないようにする。出口から目的地への直線が開いた後に通常編隊へ復帰する。

## 3. 正常系

- 所有権、機体ID一意性、役割、モジュール、バッテリー表示。
- 待機、追従、帰還、周回、Waypoint、対象追跡、Security警戒、Dock帰投。
- 1～128機の任務割当、最大8機Wing、複数Wingの独立移動と哨戒。
- Scout単独の鉱石・森林走査。
- Scout調査、Engineer採掘・範囲除去・伐採、Cargo回収、植林の連携。
- 複数Cargoによるコンテナ利用調停と、複数複合任務の並行実行。
- Engineerによる損傷機の取得・修理。
- 3x3 Dockへの帰投・着艦、ローター停止、Dock全体の一括撤去。
- Unit/Wing/全選択、地図、任務、Dock、周辺コンテナ、指揮パネルの表示とページ送り。
- FOLLOW、STANDBY、RETURN、DOCK、ORBIT、STORE確認、鉱石走査、範囲除去、森林作業、GUARDの操作導線。
- Wing間移動、Wing離脱、新規Wing作成のドラッグ操作と、Cargo搬出元・搬入先指定。

## 4. 準正常系

- 選択予定機の一部が未読込・欠損した場合の編成縮退と再採番。
- Recovery機を除いた正常機の任務継続、後着機の再参加、リーダー交代。
- 地下・水中の追跡対象を安全観測点から監視し、対象消失時は最終地点監視へ移る。
- 障害物、水、溶岩、低い天井、樹冠、Dock側面進入を含む飛行復旧。
- 任務途中の別任務割当、Cargo一時停止、Field任務から追従への切替。
- 搬入先満杯時に搬出元、機内、搬入先のアイテム総数を維持する。
- Chest、Barrel、Hopper、Shulker Box間で輸送し、搬出元、機内、搬入先の総数を維持する。
- セーブ後のプレイヤー表示名変化を含むシングルプレイ所有権復旧。
- セッション依存のField台帳は再起動時に安全停止し、再開可能なWaypoint、Cargo、Securityは復元する。

## 5. 異常系・境界値

- 空文字、過長文字列、未知命令、引数不足、余分な区切り、不正UUID、不正任務ID。
- 任務数0、1、8、9、40、100、128、129と、各任務数の全隊列番号。
- 作業半径と警戒半径の最小、最大、範囲外。
- バッテリー負値、上限超過、破損Wing ID、保存データ内の不正隊列番号。
- Cargo 0、1、2、8、9スタック、モジュールなし、Creative格納、Survival格納。
- 画面320x180、640x360、1280x720、1920x1080、2560x1440、3840x2160と、0～100機表示。
- 320x180～5120x1440の13画面条件、0～128機、全32種類の役割選択組合せ。
- 全スクロール領域の先頭、末尾、負値、上限超過。
- Dock構成ブロック9個の任意位置からの撤去と、Dock Kit重複ドロップ防止。
- 9機から1機が欠損した場合の8機への安定縮退・再採番と、命令連打時の最終命令優先。

## 8. 実UI確認

1920x1080で24機、5 Dock、複数コンテナ、24件の任務を表示した。Unit、Wing、全選択、Wingボード、地図ズーム、ユニット一覧ページ送りを操作した。FOLLOW、STANDBY、RETURN、DOCK、ORBIT、STORE確認、走査地点指定、役割不一致拒否、Cargo搬出入、Dock割当、Wing加入・離脱・新規作成を実際にクリックまたはドラッグして確認した。大規模選択時の地図ラベル抑制、地図端ラベル制限、選択数整合も確認し、文字切れ、相互重なり、スクロール逸脱は発生しなかった。

## 9. 別環境で行うリリースゲート

次は現PCの単一クライアントだけでは成立しないため、今回の合否母集団から分離する。機能不合格を隠す項目ではなく、配布前に別環境を用意して実施するゲートである。

- 2つの正規Microsoftアカウントを使う専用サーバー所有権・権限試験。
- 60分以上、100機以上を動かす長時間負荷・メモリ・チャンク境界試験。
- 公開済み旧JARと複製ワールドを使う版跨ぎアップグレード試験。
- 異なるGPU、GUIスケール、ウルトラワイド表示での実描画確認。

## 10. 再実行方法

- ロジック試験: `./gradlew test --rerun-tasks --no-daemon`
- 実ゲーム全試験: `/morrowgear_verify all`
- 障害物系5試験: `/morrowgear_verify navigation`
- 再起動準備: `/morrowgear_verify persistence_prepare`
- 再起動後判定: `/morrowgear_verify persistence_check`
- UIシナリオ: `/morrowgear_verify ui`の後に`K`
