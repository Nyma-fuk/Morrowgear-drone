# Morrowgear Drone v0.6.5 検証結果

## 対象

- 最初のウイングだけが地点哨戒へ入り、2ウイング目以降が移行しない問題

## 根本原因

- 哨戒判定が`MISSION_MOVING`機だけをコホート構成員として扱っていた。
- 別ウイングの僚機が初回`MISSION_CONVERGING`中でも、リーダー単機を到着済みウイングと誤認して旋回へ移していた。
- 残った僚機は旋回中のリーダーを集合スロットとして追い続け、初回集合を完了できなかった。

## 実装結果

- コホートIDごとに`MOVING`、`CONVERGING`、`ORBIT_ENTRY`、`ORBIT`をまとめてウイング状態を判定する。
- 正常な初回集合機が残る間はリーダーの先行旋回を禁止する。
- 全正常機の集合後、ウイング全体を同じtickで旋回層へ移す。
- Recovery機だけが残る場合は60%クォーラムを使用する。
- 既にリーダーだけが旋回した旧状態では、到着した僚機を保存済み位相へ直接参加させる。

## 自動検証

- 全86テスト成功
- 失敗0、エラー0
- リーダー単機の進入禁止、全機進入、Recoveryクォーラム、未到着禁止を追加検証
- Minecraft 26.2 / Fabric Loader 0.19.3 / Fabric API 0.156.0+26.2向けビルド成功

## 実機確認項目

- 2ウイング以上を同一地点へ指示し、各ウイングが順番に固有高度層へ入ること
- 初回集合中のウイングリーダーが単機で旋回へ入らないこと
- 後着ウイングが先着ウイングと同じ位相基準を使うこと
- 旧状態の僚機が任務再指定なしでも旋回へ復帰できること
