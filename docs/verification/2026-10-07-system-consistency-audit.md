# 2026-10-07 Morrowgear全体整合性監査

## 1. 監査目的

現行実装を基準に、母艦だけでなく、小型ドローン、Wing、戦闘、Dock、補給網、Cargo、サルベージ、採掘・伐採、命令、UI、マルチ所有権、保存再開、性能境界を一つのシステムとして確認した。

確認単位は個別機能ではなく、次のライフサイクルである。

1. ユーザーまたは自律系が命令を発行する。
2. 対象機と資源を割り当てる。
3. Wing離脱、集合、移動、障害物回避を行う。
4. 戦闘、作業、輸送、回収を実行する。
5. 電力、弾薬、損傷に応じて一時離脱する。
6. 補給後に元任務を再評価する。
7. 元任務が消失していれば安全な次行動へ移る。
8. 保存、再接続、Dock破壊、所有者の次元移動後も同じ意味を保つ。
9. 状態と失敗理由をコントローラー、Dock画面、母艦画面、バイザーへ表示する。

## 2. 今回発見して修正した全体不整合

### 2.1 一時任務終了後の出口が機能ごとに異なっていた

戦闘、Dock整備、電力喪失復旧、サルベージ支援、フィールド作業完了では、元任務が無効になった場合の出口が別々に実装されていた。一部はDockや所有者を再評価せず `STANDBY` に落ちていた。

共通の安全復帰順序を追加した。

1. 同じWingに有効な任務があれば再参加する。
2. 所有者の利用可能なDockがあれば動的に予約する。
3. Dockがなければ所有者へ追従する。
4. 所有者が不在なら現在地上空で安全周回する。

この規則を、戦闘終了後の `REJOIN`、Dock整備終了後、電力喪失からの復旧後、サルベージ用Engineer支援終了後、フィールド作業完了後へ適用した。Solar Link終了後の既存処理も同じ共通規則へ接続した。

### 2.2 Wingの一時離脱判定が不足していた

通常のDock帰還、戦闘、迎撃はWingの集合判定から除外されていたが、Solar Linkによる充電中、電力喪失中、母艦補給ベイで整備中の機体は除外されていなかった。

このため、飛行できない機体を「集合中の健全機」と数え、残りのWingが本ルートや円飛行へ進めない場合があった。これらを一時離脱として統一し、Wing所属自体は維持したまま、リーダー委譲と集合成立数から除外するよう修正した。

### 2.3 母艦船内滞在中だけDock再割当が停止していた

プレイヤーが母艦船内にいる場合、外部ドローンの任務、補給網、チャンク維持は継続できる一方、動的Dock割当だけが停止していた。船内滞在中にDockが破壊または占有されると、帰還機が代替Dockを予約できなかった。

母艦船内から外部運用できる正規条件では、所有者境界を維持したままDock再割当も継続するよう修正した。

### 2.4 フィールド作業の保存再開だけ待機へ落ちていた

採掘・伐採の共有作業台帳はセッション単位であり、再起動後に途中作業をそのまま再開しない設計である。しかし旧処理は台帳を破棄した後、機体を無条件に `STANDBY` にしていた。

再起動後は、Dock予約または駐機情報が残る機体は `DOCK` として再割当を要求し、Dock情報がない機体は所有者追従へ戻す。古い作業地点へ勝手に掘削を再開しない。

### 2.5 母艦の移動と到着後作業意図が分離していた

採掘または攻撃を選んで目的地へ移動しても、到着後の作業意図が画面内だけにあり、画面を閉じる、再接続する、チャンクをまたぐ場合に失われていた。

`MOVE_MINING` と `MOVE_COMBAT` を追加し、目的地と到着後作業をサーバー側で一つの命令として保存するよう修正した。既存saveの移動意図は通常移動として読み込み、到着時は即時破壊せず所有者確認用previewを生成する。

### 2.6 母艦採掘範囲の定義が一致していなかった

runtime、UI、仕様書、受入fixtureで16×16、半径24、256列が混在していた。製品仕様を「選択中心から半径24ブロック、3×3チャンク包絡内の円形範囲」に統一した。深度と貨物収支だけを確認する境界付きfixtureは半径8のまま分離した。

### 2.7 バイザーの警告行数が設計値を無視していた

画面サイズと重要件数に応じて1から3行を計画するpolicyがある一方、描画側が常に1件へ切り詰めていた。描画側をpolicyへ揃え、残件数は「他N件」で集約するよう修正した。

## 4. `STANDBY`を残す正当なケース

`STANDBY`自体を廃止したわけではない。次は任務喪失ではなく、安全または操作上必要な停止である。

- 新規生成直後で命令がない。
- Dockへ物理的に着艦済みである。
- 電力喪失中で、ローター停止後に落下または吊り上げられている。
- サルベージのHOOK中で、牽引物を固定している。
- 定点警戒やフィールド作業の専用状態機械が移動を直接制御している。
- ユーザーが明示的に待機を命じた。

任務復帰先が見つからないという理由だけで `STANDBY` に落とす経路は、今回確認した主要な一時任務から除去した。

## 5. 互換性上維持した事項

- 既存saveの母艦移動意図は通常移動として読み込む。
- 保存中の戦闘波、ミサイルロック、runtime entity IDは復元せず `REJOIN` から再評価する。
- フィールド共有台帳は不完全な世界変更を避けるため永続化せず、機体だけ安全帰還させる。
- Wing所属は整備・戦闘中も削除せず、一時離脱として扱う。
- Dockは固定ホームに戻さず、既存の動的予約方式を維持する。

## 7. 自動試験だけでは完了判定できない事項

1. レーザー、ミサイル、母艦採掘、軌跡、音声の見栄えと聞こえ方。
2. 実際の洞窟、基地壁、複数高度での経路品質。
3. 第3世代Core i3相当サーバーでの長時間tick時間とwatchdog余裕。
4. 実マルチで、所有者が母艦船内、別次元、切断、再接続を繰り返すケース。
5. 母艦の高深度採掘を最後まで実行した際の演出、岩盤境界、回収貨物の一連確認。

この5項目はコード整合性試験の代替ではなく、配布前の実ゲーム受入試験として別に実施する。
