# マウス操作を使わない実ゲーム検証

## 目的

Minecraft の画面を人が開いてチャットへコマンドを入力し、結果を待って終了する反復作業を自動化する。専用試験ワールドへの直接接続、試験開始、完了判定、レポート保存、ゲーム終了までを一つのスクリプトで実行する。

通常ワールドと通常起動では自動化コードは動かない。ドローン試験は `Morrowgear Drone Test`、母艦試験は `MG Carrier V27 Verification` という完全一致のワールド名、シングルプレイ、クリエイティブ、プレイヤー1名をすべて満たす場合だけ開始する。

## 実行

```powershell
./tools/run_mouse_free_verification.ps1 -Scenario regression
./tools/run_mouse_free_verification.ps1 -Scenario salvage_clearance
./tools/run_mouse_free_verification.ps1 -Scenario ui
./tools/run_mouse_free_verification.ps1 -Scenario ui_capture
./tools/run_mouse_free_verification.ps1 -Scenario ui_capture -Width 1920 -Height 1080
```

結果は `build/verification/mouse-free/` に JSON で保存される。PASS 以外はスクリプト自体が失敗終了するため、連続試験やCIからも同じ入口を使える。
Minecraft の詳細ログも同じ場所へ保存し、コンソールには開始・結果・所要時間だけを表示する。調査時だけ `-ShowGameLog` を付ける。
`ui_capture` はコントローラー全11画面を通常の画面遷移で開き、各PNGとページ名付き一覧画像を同じ場所へ生成する。画像レビューではこの一覧を最初に確認し、問題のある画面だけ原寸PNGで再確認する。

## 自動化できる操作

- 専用ワールドの選択と接続
- 検証フィクスチャの準備
- 航行、戦闘、Dock、太陽光給電、サルベージの各実ゲーム試験開始
- コントローラー画面の生成と、通常のナビゲーション処理を通した全11画面の切り替え
- 条件成立までの待機、PASS/FAIL判定、JSON記録
- 試験完了後のMinecraft終了

利用できるシナリオはスクリプトの `Scenario` 候補が正本である。通常の短い回帰確認には `regression`、サルベージ経路除去には `salvage_clearance`、コントローラー全画面初期化には `ui` を使う。

## 人の確認を残す項目

以下は動作自体を自動で再生できても、最終品質の合否は人が一度見る必要がある。

- 光線、粒子、遮蔽、軌跡、機体姿勢の見栄え
- 音の迫力、距離減衰、不快さ、他音との混ざり方
- 文字の読みやすさ、情報密度、操作の理解しやすさ
- マウスで触ったときの選択感、ドラッグ感、誤操作の起きにくさ

この確認もセットアップや試験開始にはマウスを使わず、自動シナリオで目的の状態まで進めてから観察だけを行う。

## HMIの合否

HMIは次の二段階を分離して判定する。

1. **操作成立**: 画面生成、通常のナビゲーション処理、データ取得、例外の有無を自動判定する。
2. **視覚品質**: 自動撮影した一覧と原寸PNGを確認し、文字潰れ、重なり、欠落、過剰な空白、情報優先度、モックとの差を判定する。

PNGが生成された事実だけを視覚品質PASSにはしない。動的データが含まれるため全面の単純なピクセル一致も使わず、解像度、画面領域、主要要素の存在と位置を機械判定した上で、人が一覧画像をレビューする。承認された画面は比較基準として固定し、意図した変更だけ基準画像を更新する。

標準確認解像度は `1280x720` と `1920x1080` とする。通常、複数Wing戦闘、POWER LOST、Dock枯渇、母艦作業中など情報密度の異なるシナリオは別の撮影セットとして扱う。
