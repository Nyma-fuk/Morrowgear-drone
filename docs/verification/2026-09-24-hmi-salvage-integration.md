# 全画面HMIとサルベージ救援の統合確認

## 依頼と適用範囲

承認済みブラウザーHMIをゲーム側へ移植する。サルベージは、上部閉塞時のEngineer援護と、吊り荷搬送中のDock進入往復を修正する。通常ワールド・ランチャー版への反映は検証が終わるまで行わない。

## サルベージの実装方針

- LOST機の上方と機体幅に余裕を加えた柱を走査。上から除去し、落下ブロックを下から掘り抜かない。
- 同一所有者・同一次元のロード済みEngineerを候補とする。電力不足、充電中、他の作業中、交戦中、別救援担当は候補外。
- 元任務を既存タスクスタックへ退避。救援終了・対象消失は既存の再開可否判定へ戻す。
- 岩盤、保護タグ、コンテナ、液体、記録済みのプレイヤー建築、権限拒否は除去しない。Fabricの破壊イベントと保護連携の許可を確認する。自動救援を建築物の無条件破壊にしない。
- 搬送時の目的地を通常のDockゲートから上方の荷物引渡し点へ変更。経路選択後の高度上書きは廃止。
- 搬送時は吊り荷の下端と振れ幅を含めた空間で経路を検査。吊り上げ高度に到達してから水平搬送へ進む。
- 屋根や障害物で搬入できないDockは再割当の候補から除外。全候補が塞がれているときは保持・待機を続ける。

## 追加する実ゲーム試験

専用試験ワールドで `/morrowgear_verify salvage_clearance` を使用する。既存サルベージ試験にEngineer1機と石の屋根を加える。

確認する事実: 屋根25ブロックの除去、LOST機の実在維持、吊り上げ、水平搬送、Dockへの引渡し、充電、元任務復帰。補助試験ではEngineer不在、保護ブロック、担当機の補給・破壊、保存再読込、Dock撤去・全閉塞を確認する。

`salvage_late_engineer` は最初の400tickをEngineerなしとし、石の屋根25ブロック・LOST状態・対象実体を保持してフックへ移行しないことを検査する。その後にEngineer1機をFOLLOW任務で追加し、通常の閉塞除去・回収・充電・元任務復帰とEngineerのFOLLOW復帰を検査する。追加時点ではビルド確認のみであり、実ゲーム結果は下の表に別途記載する。

## 完了判定

コンパイル、単体試験、実ゲーム試験、画面比較を分離して記録する。試験用コマンドを追加しただけで実ゲームPASSとはしない。全画面にはコントローラー、Dock、母艦、バイザー、履歴とその例外状態を含む。

初回の証跡は再起動前に保存した `build/hmi-salvage-live-first.log` の `SALVAGE STATE` と `SALVAGE PASS`。各試験は試験機のみ追加し、終了後に試験機を撤去する。Engineerを使う試験は3機、それ以外は2機。既存機の追加召喚は行わない。

これらは保存再読込、保護された建築物、Engineerが最後まで不在、全Dock閉塞までPASSした証拠ではない。また、テスト用試験場を生成しているため、利用者が報告した元の基地を完全再現した証拠でもない。

岩盤試験の証跡は `build/hmi-salvage-live-second.log`。これは破壊不能ブロックについての確認であり、建築履歴による保護や他MODの保護イベントまで実ゲームで検証したものではない。2回目の起動後に追加したDock待機順位・太陽光充電・アンロード・搬送中の外部命令・Engineer稼働状態の安全修正は、このPASSには含まない。

3回目の証跡は `build/hmi-salvage-game-third.stdout.log`。05:10:10にcanopy、05:11:34以降にverticalのPASSを確認。最新安全修正を組み込んだ通常の回収経路が成立する確認であり、アンロードや外部命令の割込みを実際に発生させた試験ではない。

ゲーム画面ではコントローラーと回収分類を開けたが、承認済みブラウザー案に対して領域配分と操作配置の差を確認した。修正と再確認を継続する。

2回目の起動では、新設Dockを空手の右クリックで開き、ミサイル補給品16パックを予備段に投入した。補給タブは16個、備蓄タブは80発（1パック5発）と表示され、閉じて再度開いても在庫が維持された。回収段への投入は拒否された。機体への補充まで確認した結果ではない。

2回目のコントローラー表示では、全高の機体一覧と右側詳細の配置を確認。ただし機体一覧の状態名、操作名の省略、報告履歴の内部次元名露出、設定の操作部が判別しにくい点を検出し、修正対象にした。

全画面完成、全例外ケース解決、ランチャー反映済みとはまだ扱わない。実ゲームで使用した版の後に追加した安全判定・永続化・UI調整は、再ビルドと再起動後に確認する。

### 3回目の通常UI操作

- コントローラーの機体選択、選択機への地図移動、既存4地点ルートの表示、座標入力画面、キャンセルで未送信のまま戻る操作を確認。
- 設定のチェックボックス、マーカー距離、履歴入口を確認。報告履歴の次元名が内部オブジェクト文字列ではなく表示名になったことを確認。
- 母艦コンソールを範囲内で通常右クリックし、概要・採掘・攻撃・移動・貨物・補給・船内・診断を開いた。採掘区画の選択で範囲枠と座標が更新されることを確認。攻撃や採掘の実行成功を意味する試験ではない。
- 貨物18個の丸石を通常クリックで持ち物へ取り出し、同じ貨物枠へ再収納。持ち物側の取得、母艦収納数0から18への復帰を確認。途中の作業メモの13個は画面の読み違いであり、再収納後の表示は18個。
- 範囲外の母艦コンソールが無反応になることと、船内の招待候補ゼロが空白になることを検出。理由表示を追加したが、この実行中の版にはまだ含まれない。

### 4回目の通常UI操作

- 救助進捗で吊り上げから補給への更新と搬送先64,-30,-84を確認。試験機撤去後は最終確認として保持し、消失を成功と断定しない。戻る操作で元の回収分類へ戻る。
- 同一次元のLOST機が別次元と表示される不具合、文字倍率の自動2倍から増加操作で1倍になる不具合を検出。次回起動版で修正を再確認する。
- 装着HUDの画面端ラベルに背景が付き、空に重なっても判読できることと、作戦地図の地形コントラスト変更を確認。
- 機器一覧から詳細、レシピ、元詳細への往復を確認。未解放時は取得なし、専用ワールドでレシピ解放後は実際のコントローラーレシピ1件、材料と配置が表示された。文章のみの配置表示は使いづらいため、アイコンの格子配置へ再修正する。
