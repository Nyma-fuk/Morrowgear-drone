# Dock帰還と母艦の再点検

## 今回の不具合

1. コントローラーの帰還命令が「既にDockを割り当て済み」であることを要求していた。空きを探す動的予約処理へ到達せず、ドローンより後に置いたDockを使えなかった。
2. 明示的な帰還命令と自動迎撃・ソーラー給電の優先順位が一致していなかった。手動帰還中はこれらの割込みを抑止し、着艦まで要求を保持する。
3. Dockは遠距離でも詳細モデルを描画していた。距離別モデルと、中央ブロックではなくプラットフォーム全体の可視判定を導入する。
4. 母艦の採掘は照射口から各ブロックへの斜めの射線判定だった。チャンク全域の垂直掘削と整合しないため、各列の垂直方向で遮蔽を確認する。
5. 走査光と攻撃光の同期境界で、次の段階の表示に前の段階の照射先が混入する可能性があった。照射先を生成した段階を一緒に同期する。

## 利用上の契約

- Return Dockは固定のホームへ戻る命令ではなく、所有者が同じ利用可能なDockを予約して着艦する要求。
- 空きがなければ順番待ちと上空待機。電力喪失機がこの命令だけで飛行可能になるわけではない。
- 採掘するチャンクは母艦画面の地図で選ぶ。母艦が別の場所にいれば、まず選択地点へ移動し、範囲確認後に採掘を開始する。
- 採掘範囲は選択した16×16の列、上端は母艦直下、下端はディメンション下限。岩盤に到達した列はそれより下を処理しない。
- 連続掘削でも、保護ブロック・味方・収納満杯・未読込・操作権喪失による安全停止は残す。演出のために保護やアイテム保存を無視しない。
- 再起動後に破壊処理を無断再開しない。保存した進捗を確認して再開する。

## 追加の監査観点

| 観点 | 確認内容 |
|---|---|
| Dock破壊 | 予約喪失後も帰還要求を失わず再予約する |
| 満車 | 長時間駐機の譲渡、補給機の優先、着艦待機の重複予約防止 |
| 操作と自律処理 | 手動帰還を自動迎撃が直後に取り消さない |
| 大規模基地 | 描画だけでなく待機機数×艦隊数の割当計算量も測る |
| 走査と実害 | 走査・充填ではダメージや着弾音を発生させない |
| 掘削 | 空洞、液体、岩盤の凹凸、負座標、収納満杯、再開、回収数保存 |
| 攻撃 | 遮蔽、味方混在、標的死亡、対象上限、充填中の標的変更 |
| 画面 | 選択チャンク座標、走査・充填・照射・冷却の段階、拒否理由 |
| 配布 | ゲーム実行中のJAR上書きを避け、検証済み成果物だけを安全に配置 |

## 制約と継続課題

- Dock検索は同所有者・現在ディメンションの読み込み済み候補が対象。無制限距離の未読み込みDock探索を保証しない。
- Dock描画を軽量化しても、帰還待機の割当計算量は別問題。多数機での負荷確認を残す。
- 戦闘は取得対象128体、1パルス最大16体の上限を維持。上限超過は安全停止し、無制限探索しない。
- 同一ダメージコールバック中に新規生成された友軍は次tickで再検索される。既存対象の移動・敵対状態変更・停止は各ダメージ前後に再確認する。
- 新しい母艦モデルは承認前の提案。現在導入したJARに新外観は含めない。
