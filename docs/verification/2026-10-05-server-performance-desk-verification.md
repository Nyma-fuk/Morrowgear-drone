# サーバー性能改善 机上検証記録

実施日: 2026-10-05  
対象: Morrowgear Drone Java Mod  
方式: Minecraftを起動しない単体・契約・計算量試験

## 1. Watchdog原因との対応

提供されたクラッシュレポートでは、サーバースレッドが `DroneNavigator.localDetour` から
`corridorClear` を呼び、長距離のブロック衝突形状を生成し続けてWatchdogに停止されていた。

修正後は次を上限とする。

| 項目 | 修正前 | 修正後 |
|---|---:|---:|
| 1回の精密通路判定距離 | 任務距離に依存 | 96ブロック |
| 戦略迂回の候補照会 | 候補数と比較回数に依存 | 最大96候補 |
| 1判断の理論最大サンプル | 無制限 | 20,544 |
| 1000ブロック以上の任務 | 全距離を精密照会し得る | 24/48/72ブロックの中継点を反復 |

`NavigationWorkPolicyTest` により、任務距離を1000ブロックへ伸ばしても1判断の精密処理量が増えないことを確認した。

## 2. 規模別の計算量

机上条件は64機、敵200体、Dock 16基、Scout 16機、同時ミサイル45発とした。

| 処理 | 修正前の代表的処理量 | 修正後の上限・処理量 |
|---|---:|---:|
| 同一敵群の脅威報告保持 | 64 x 200 = 12,800 | 200接触 |
| level内entity列挙 | センサー数・所有者数に比例 | levelごとに1回/tick |
| サルベージ対応Dock確認 | 64 x 16 x 64 = 65,536 | 64 x 16 = 1,024/tick |
| フィールド走査 | 16 x 384 = 6,144 | 作戦全体で512/tick |
| 同時爆発 | 45件を同一tick | 最大8件/tick、残りは順次継続 |
| 母艦の同一座標高さ照会 | 移動候補数 x 座標数 | 一意座標数 |
| 機体間隔候補 | world検索を各機で実行 | 所有者tickスナップショットの3次元セル |

敵200体・Security 128機の実際の戦域割当は6 msで完了した。これは開発機上の参考値であり、Core i3-3世代U型でのMSPTを保証する値ではない。一方、テスト上限2秒に対して十分な余裕があり、全200接触を保持し、128機を1目標最大8機の規則で割り当てた。

## 4. 互換性確認

- 処理予算不足を任務失敗やSTANDBYとして扱わない。
- 長距離経路は安全未確認を「通行可能」と判定せず、短い中継区間へ分解する。
- 敵性判定は所有者ごとに行い、マルチプレイヤーの所有権を混在させない。
- Dock予約確定は既存の直列処理を維持する。
- 8発以下のミサイル起爆は従来時刻を維持する。
- 9発以上の同時起爆だけを翌tick以降へ繰り越し、処理順を維持する。
- 保存対象の任務・在庫・予約データはキャッシュ解放の対象外とする。

## 5. 実機確認が必要な項目

今回の指示に従いMinecraftは起動していないため、次は未確定である。

- Core i3-3世代U型サーバーでのMSPT p50/p95/p99
- 1000ブロックDock帰還時の見た目と到着時間
- 45発同時弾着を複数tickへ分けた際の音・爆発演出
- 64機密集時の衝突回避と動的ライトの見え方
- 30分以上の混成Soakでのヒープ、チャンクチケット、キャッシュ数

これらは挙動確認であり、机上試験で代替できない。次回実機試験では通常worldの前に複製worldを使い、Sparkまたは同等のプロファイラでMSPTとホットスポットを取得する。
