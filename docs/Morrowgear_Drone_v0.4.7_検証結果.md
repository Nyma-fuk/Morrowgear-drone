# Morrowgear: Drone Command v0.4.7 検証結果

## 検証環境

- Minecraft Java Edition 26.2
- Fabric Loader 0.19.3
- Fabric API 0.156.0+26.2
- Morrowgear: Drone Command v0.4.7
- 検証日: 2026年8月18日

## 目的

全機へ同じ地点任務を設定した際、1機が木や葉ブロックに拘束されても、他機の分散収束と任務完了が停止しないことを確認する。また、障害物を抜けた遅延機が同じ任務へ後着合流できることを確認する。

## 自動テスト

- `clean test build` 成功
- 45テスト成功、失敗0
- `RecoveryPolicyTest`で復旧段階、安定前進判定、復旧継続時間を確認
- `SwarmFormationTest`で分散収束中の個別到着判定を確認

## ゲーム内再現手順

1. 所有ドローン7機を展開した。
2. 1機だけを葉ブロックの閉鎖空間へ配置し、物理的に目標へ直進できない状態にした。
3. 統合戦術管理画面で全7機を選択し、新しい地点をダブルクリックして任務を設定した。
4. 正常な6機と拘束した1機の状態を同時に監視した。
5. 拘束機の上方に脱出口を開け、後着合流を監視した。

## 結果

| 確認項目 | 結果 |
|---|---|
| v0.4.7の読み込み | 成功 |
| 全7機への共通地点任務 | 成功 |
| 拘束機の停滞検出 | `RECOVERY-3 / 分散収束`を表示 |
| 正常6機の独立完了 | 拘束機を待たず`地点哨戒`へ移行 |
| 全隊停止の回避 | 成功 |
| 脱出口開放後の復旧 | 飛行で脱出し、`RECOVERY-3`を解除 |
| 遅延機の後着合流 | 成功。最終的に7機すべて`地点哨戒` |
| テレポートによる復旧 | 使用なし |

## 判定

従来の共有ステージ完了条件による単一障害点は解消された。現在は中央が任務意図を配布し、各機が航法、復旧、到着を自律判断するハイブリッド群制御である。拘束機は群全体を停止させず、経路が再び利用可能になった時点で任務へ復帰できる。

完全に閉鎖された空間からブロックを無視して脱出する機能は持たない。これは物理衝突を尊重する期待動作であり、復旧経路が存在する場合のみ飛行で離脱する。
