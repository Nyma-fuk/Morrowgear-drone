# Morrowgear Drone v0.9.0 検証結果

## 対象

- Minecraft Java Edition 26.2
- Fabric Loader 0.19.3
- Fabric API 0.156.0+26.2
- Morrowgear Drone Command 0.9.0

## Cargoコンテナ利用調停

- 同一コンテナにつき同時利用者を1機へ限定した。
- 待機要求はFIFOで処理し、待機順位を機体同期データと戦術UIへ表示する。
- 利用権はリース方式とし、停止・消失した利用者がコンテナを永久占有しない。
- 役割変更、Cargo経路変更、格納、機体消失時に全予約を解放する。
- 待機機はコンテナ周辺へ半径・高度をずらして退避する。
- 3機、搬出元27スタック、搬入先空の実機試験で、搬出元が空、搬入先が27スタック、全3機が`WAIT SOURCE`へ遷移することを確認した。

## Engineer整備支援

- 待機中のEngineerはプレイヤー周辺18ブロックの損傷所有機を検出する。
- 損傷率と機体IDによる共通順序で、Engineerを損傷機へ1対1割り当てする。
- 対象から3.25ブロックを超える場合は周囲の整備位置へ飛行する。
- 3.25ブロック以内では40tickごとに4HPを回復する。
- サバイバルでは修復1回につき銅インゴット1個を消費し、不足時は`MATERIAL LOW`へ遷移する。
- クリエイティブでは資材を消費しない。
- Engineer状態と対象機IDを戦術管理UIへ同期表示する。
- 地点移動、追跡、追従、Dock帰投中は自動整備を停止し、明示任務を優先する。
- 脅威防御は従来どおり整備移動より優先する。

## 自動検証

- Cargo FIFO、期限切れ利用権、全予約解放を含むコンテナ調停テストを実行した。
- Engineerの1対1割当と余剰機待機を検証した。
- 全テストと配布JARのビルドを成功させた。

## 更新互換性

- 既存のMod ID、Entity ID、Item ID、Block IDは変更していない。
- Cargoの搬出元、搬入先、積荷、状態保存形式は維持した。
- Engineer状態は運用時に再計算する一時状態であり、既存ワールドへ追加保存値を要求しない。
