# Morrowgear Drone v0.16.12 テスト妥当性監査

## 1. 目的

Launcherの`morrowgear-drone-latest.jar`をv0.16.12へ差し替える前に、現行テストが現在仕様を正しく判定できるかを監査した。本書はテスト数だけを合格根拠にせず、各検証層の責任範囲、前提条件、誤判定防止策、実施順を定義する。

## 2. 監査結果

| 検証層 | 最新件数 | 現在結果 | 保証する範囲 |
|---|---:|---|---|
| JUnit | 1,506件 / 63 suite | PASS | 方針、数値境界、状態遷移、Wing、航法、戦闘、Cargo、永続化データ変換、アセット構造 |
| Minecraftランタイム | 49ケース | 48 PASS後、唯一の失敗を是正して対象ケースPASS | 実Entity、実Block、tick進行、任務復帰、Dock、戦闘、作業 |
| 専用スコープ | Navigation 6 / Field 5 / Combat 9 / Adaptive Combat 7 | Navigation 6/6、Adaptive Combat 7/7 PASS | 障害物、複合作業、交戦、増援・再充電・復帰を短い再試験単位で確認 |
| UI・描画目視 | UI 1シナリオ / Effects 1シナリオ | 差し替え後に実施 | レイアウト、光線と弾道の可視範囲、遮蔽、表示品質 |
| 再起動永続化 | prepare / check | 差し替え後に実施 | 所有権、Wing、任務、Dock、Cargo、役割、電力の保存・復元 |

JUnitは失敗0、エラー0、スキップ0である。Launcherの最新版JARを実際に起動して確認した。

## 3. 今回是正したテスト上の問題

### 3.1 非隔離ワールドによる機体混入

従来は検証プレイヤーが所有する通常機が試験空域内にいても試験を継続していた。この場合、戦闘レスポンダー、Wing名簿、Cargo、空域予約へ通常機が混入し、製品不具合と試験汚染を区別できない。

現在は試験開始時に半径160ブロックを確認し、Verifier以外の所有機が1機でも存在すれば`test airspace is not isolated`で即時中断する。初期化失敗後の後続ケースは実行しない。

### 3.2 先行FAILによるケース成否の誤表示

従来は全体の失敗リスト末尾から現在ケースのPASS/FAILを推測していた。現在はケース開始時の失敗件数を保持し、当該ケースで増えたかだけを判定する。

### 3.3 専用スコープの文字列依存

従来はケース名の文字列一致で`navigation`、`field`、`combat`、`adaptive_combat`を抽出していた。ケース名変更により対象試験が通知なく消える危険があった。現在は各`CaseStep`へ検証スコープを明示的に付与する。

### 3.4 光線遮蔽をソース文字列だけで判定

描画ソースに関数名が存在するだけでは、遮蔽物の前後で光線を正しく分割できる保証にならない。`BeamVisibilityPolicy`を純粋ロジックとして分離し、全可視、全遮蔽、中間遮蔽、孤立サンプル、不正解像度を実データで検証する。

クライアントのraycast、深度、発光感はJUnitでは保証しない。`/morrowgear_verify effects`後の目視試験を必須とする。

### 3.5 Dock中を含む複数Wingの任務混線

同じ所有者、同じ任務IDでも`groupId`が異なる機体を同一コホートへ入れないことをJUnitで検証する。さらにMinecraftランタイムへ`manual wing route cohort isolation`を追加し、飛行機とDock中機が混在する2つのWingを実Entityで検証する。

### 3.6 高脅威ターゲット生成失敗の二次例外

Warden生成失敗後にnull個体へ座標やAIを設定していた。現在は型を確認し、生成失敗を当該ケースの単一エラーとして終了する。

### 3.7 ケース間に残るDock状態

全49ケースの初回実行で、Dock検証が設定した`DOCKED`状態が後続ケースへ残り、Field、Cargo、遠隔任務を連鎖的に失敗させることを確認した。共通リセットでDock状態も解除し、各ケースが前ケースの機体状態に依存しないよう修正した。

### 3.8 WingとCohortの境界

- `groupId`は最大8機の永続的なWing境界とする。
- `missionId`は命令の実行単位とし、複数Wingへ同じ操作を出してもWingごとに別IDを割り当てる。
- `cohortId`は集合、Recovery、隊列移動中にWing内で一時形成される飛行単位とし、別Wingを横断しない。
- Dock、充電、戦闘迎撃による一時離脱では`groupId`を維持し、復帰先を元Wingへ固定する。
- 任務中のJoin、Leave、Wing統合では、移籍元と移籍先の`missionExpected`、`missionIndex`、リーダー、Cohortを再計算する。

この境界変更が影響する状態は`MUSTER`、`CONVERGING`、`MOVING`、`ORBIT_ENTRY`、`ORBIT`、追従、地点移動、対象追跡、ルート周回、リーダー移譲、Recovery、Dock帰還・再発進、戦闘一時離脱・Rejoinである。FieldとCargoの作業ロジック自体はWing境界を直接使わないが、作業地点への移動と任務復帰では同じ航法状態を経由するため回帰対象に含める。

### 3.9 遠隔Scout通報の試験安定性

遠隔ターゲット試験では、自然スポーンした近距離敵がPLAYER-GUARD通報を上書きする問題と、遠隔配置した敵がデスポーンする問題があった。試験中は観測対象外の敵を除外し、遠隔ターゲットを永続化して、正しい対象IDを直接観測するようにした。

### 3.10 ケース間に残る航法キャッシュ

全体試験で`regroup and formation obstacle reroute`だけが4機中2機未到達となった。原因は、前ケースの経路、脱出タイマー、停滞判定、戦略迂回点が機体再利用時に残っていたことだった。検証用リセットで航法状態も初期化するよう修正し、対象ケースを含むNavigationスコープは6/6 PASSとなった。この変更は検証フィクスチャ専用であり、通常プレイの飛行制御には影響しない。

### 3.11 機関砲航法の速度連続性

適応戦闘試験で1tickの速度変化が0.3935となるケースを検出した。CASの移動スロット追従で速度ベクトル変更量を1tickあたり0.12へ制限し、専用JUnitを追加した。Adaptive Combatは7/7 PASSとなった。

## 4. 49ランタイムケースの妥当性分類

| 分類 | 主な観点 |
|---|---|
| 前提・識別 | 隔離試験場、所有権、識別子、役割互換、境界値 |
| Wing・任務 | 最大8機、1～24機、名簿縮退、安定index、複数Wing分離、追従、地点、追跡、命令上書き |
| 戦闘 | 敵性判定、3種トリガー、兵装、レーザー群、空域予約、高脅威増援、GUN RUN、飛行／兵装電力 |
| 適応戦闘 | 巡回離脱・復帰、充電交代、HEAT冷却、代替機、遠隔任務継続、速度連続性 |
| フィールド | Scout単独、Engineer単独、鉱石、掘削、伐採・植林、Cargo回収、複合並行作業 |
| Cargo | 搬出入、競合調停、満杯時保存、特殊コンテナ、アイテム総量保存 |
| Dock・航法 | 帰還、直接発進、屋根・側面障害、巨大障害物、Regroup、作業経路、3x3一括撤去 |
| 保存・UI | 機体収納、ターミナル用実データ、最終Fleet不変条件 |

各ケースはコマンド成功表示ではなく、ケース固有のEntity状態、距離、速度、対象ID、Block、Container、電力、観測継続tickをassertする。時間切れでready条件を満たさない場合もassertへ進み、未達をFAILとして記録する。

## 5. 差し替え後の実施順

1. v0.16.12 JARをLauncherへ差し替え、起動ログで読込バージョンを確認する。
2. 通常機が存在しない専用スーパーフラットで`/morrowgear_verify all`を実行する。
3. FAILがある分類だけ専用スコープで再現する。
4. `/morrowgear_verify ui`後に統合画面を開き、リスト増加、Wing選択、地図操作、重なりを確認する。
5. `/morrowgear_verify effects`でレーザーと弾道を確認する。遮蔽物の手前は見え、遮蔽物の裏側だけ消え、再び見通せる区間は表示されることを確認する。
6. `persistence_prepare`後にMinecraftを終了し、再起動後に`persistence_check`を実行する。

## 6. 合格条件

- JUnit 1,506件が失敗・エラー・スキップ0件。
- ランタイム49ケースが全件PASSし、試験中に`ERROR`、`Exception`、`FATAL`がない。
- UIの一覧、カード、地図、選択状態が件数増加で重ならない。
- 光線と弾道は見通せる区間で十分に見え、遮蔽物を透過しない。
- Dock中・飛行中を問わず、別Wingの機体が任務へ混入しない。
- 再起動後に所有機、Wing、Dock、任務、Cargo、役割、電力が保持される。

この全条件を満たすまで、v0.16.12を検証完了版として扱わない。
