# Morrowgear: Drone Command v0.5.0 検証結果

## 変更目的

分散収束中の機体群が明確な隊列を作らないまま目的地へ到着する問題を解消し、ユーザーがコホート、リーダー、参加状況、合流先を戦術UIで把握できるようにする。

## 制御契約

1. 目的地に最も近い機体を固定リーダーとして選ぶ。
2. リーダーだけを参加順位0で先行隊へ登録し、他機は同じコホートの未合流機とする。
3. 未合流機はリーダー後方の空きスロットへ飛行し、2.8ブロック以内で合流する。
4. 合流順に参加順位を追加し、参加済み機だけで通常隊形を構成する。
5. 先導隊は参加率に応じて速度を上げ、全機合流後に最高巡航速度へ移る。
6. 全機合流前は地点哨戒への遷移を禁止する。
7. 分断した機体だけを同一リーダーへの分散収束へ戻す。
8. 分断復旧の凝集範囲は固定リーダーを起点に評価し、より大きい後続クラスターが存在してもリーダーを交代しない。

## UI表示

- コホート識別子
- 固定リーダーIDとマップ上の`L`記号
- 隊列参加順位、または`JOIN`状態
- 現在の移動式合流座標
- 未合流機から合流スロットまでのアンバー色航路

## 自動検証

- Minecraft本体コード、クライアントUI、配布Jarのビルド成功
- 53テスト成功、失敗0、スキップ0
- 目的地最寄り機の選出と同距離時の決定性を確認
- 参加率1/4、2/4、3/4、4/4の速度上限を確認
- 目的地直前かつ未完成時の0.22 block/tick制限を確認
- 合流距離2.8ブロックの境界を確認
- 未完成隊列と分散収束機が地点哨戒へ移らないことを確認
- 従来の隊形間隔、地下用コンパクト隊形、航法、脅威評価、Dock制御の回帰テスト成功

## 更新互換性

既存の機体ID、所有者、Dock、任務、コホートID、リーダーID、参加順位は変更しない。新規の移動式合流座標は保存データに存在しない場合`未設定`として読み込むため、v0.4.9以前のワールドをそのまま更新できる。

## Minecraft実機確認

既存の`Morrowgear Drone Test`ワールドへv0.5.0を上書きし、保存済みの5機が消失せず読み込まれることを確認した。管理画面から通常の地点指示だけを使用し、テレポートや速度変更は使用していない。

1. 5機を異なる地点へ個別移動させ、散開状態を作成した。
2. 全5機へ共通目的地を設定すると、目的地最寄り機をリーダーとする同一コホートが形成された。
3. 未合流機に`分散収束`、`JOIN → 座標`、アンバー色の合流線が表示された。
4. 合流した機体は参加順位表示へ切り替わり、全機合流後に合流線が消えた。
5. 完成隊列へ遠方地点を再指定し、参加済み隊列と未合流機が同じ移動式ランデブーを使用することを確認した。
6. 初回確認で、最大凝集クラスター判定による意図しないリーダー交代を検出した。凝集判定を固定リーダー起点へ修正した。
7. 修正後の再確認では、任務開始、分散収束、地点到着の全段階でリーダー`MG-DRN-9D4632`が維持された。
8. `MG-DRN-813DDB`が`RECOVERY-1`へ入った状態でもリーダー交代は発生せず、全5機が地点哨戒へ遷移した。

配布Jarと導入済みJarのSHA-256はともに`0C19F5296CEDB292686DC09C620AA1541ADE05BD4C9107CFEE689E8A5AC296F1`で一致した。
