# 母艦UI V25: 地図から採掘する

2026-09-22。**独立したレイアウト設計図。実画面未検証。視覚承認待ち。runtimeへの採用なし。**

## 改訂の範囲

母艦V24の2枚は、情報が細かすぎる、操作場所と区画の選び方が分からない、言葉の意味が伝わらないという理由で却下された。[却下記録](../operations-ui-v24/CARRIER_REJECTED.md)を残し、元画像は変更しない。小型機controller・Dock・HUD提案は今回変更しない。

V25は「地図で16×16の区画を選ぶ → 範囲を確認する → この範囲の採掘を開始する」に絞った母艦の新案。全情報と90枠の同時表示をやめ、貨物は専用タブへ分ける。説明文や新しい商品名で補わず、現在の状態・選んだ場所・次に行う操作を大きく表示する。

## 入口と日本語

全体の主ナビは従来提案どおり「作戦 / 部隊 / 基地・補給 / 履歴 / 設定」。母艦は「基地・補給 > 母艦」から開く船固有の画面で、6つ目の主ナビにはしない。

母艦内のタブは「採掘」「敵への攻撃」「移動」「貨物・補給」「船内」。下端の「停止」は全タブ・確認画面に常設する命令でありタブではない。「戻る」は上端左の固定位置。狭幅ではタブ5本を詰め込まず、現在のタブ名から同じ5項目を選ぶ。

待機中で停止すべき処理がない場合は停止を無効表示し、場所は変えない。採掘・攻撃・移動・補給が動いていれば有効にする。画面に表示した時点の古い状態だけで無効化を続けない。

世代、generation、nonce、TTL、予約内部ID、接続未取得、サービス予約、View、Menu等は通常画面に出さない。必要な開発情報は右上の設定内「診断」にのみまとめ、既知の情報だけを表示する。APIに存在しないnonceやACKを作らない。

期限や更新が切れたときだけ、確認欄に「範囲をもう一度確認してください」と出す。残り秒数や世代番号の意味を理解させない。通信できない場合は「通信できません」、満杯は「貨物がいっぱいです」、安全に降りられない場合は「安全な下船先がありません」と具体的な短文にする。

## 地図の操作

- 母艦の現在位置はシアンの丸と進行方向の矢印。選択区画はアンバーの四角。位置が重なっても役割を区別できる。
- 地図に16×16ブロック単位の太い境界を重ねる。カーソルを置いた1区画を強調し、クリックでその区画を選ぶ。チャンク番号入力欄は設けない。
- 選択区画だけ細い16×16のブロック目盛を補助表示する。地図の施設・地形・対象の輪郭が読める濃度を保つ。
- ズーム/パン、画面とワールド座標の逆変換、地形・Entity等の既存キャッシュを継承する。クリック位置は現在の投影からワールドx/zに戻し、負座標を含め床除算で区画を決める。
- 地図クリック、ダブルクリック、カーソル移動では命令送信・採掘開始をしない。Enter押しっぱなしや次の画面へ持ち越されたクリックで開始しない。
- 採掘中のハイライトは稼働中の範囲に固定する。別区画の選択だけで稼働中の範囲を変えない。

## 状態遷移

| 状態 | 地図と表示 | 単一の主操作 | 次の状態 |
| --- | --- | --- | --- |
| 未選択 | カーソルが乗る区画だけ仮強調 | 選択後に有効 | 区画を選択 |
| 現在直下の区画を選択 | 母艦の丸と選択枠が同じ区画 | 採掘範囲を確認 | サーバーの範囲を受信して確認へ |
| 別区画を選択 | 母艦の丸、別の選択枠、移動経路の案 | 母艦をここへ移動 | 移動要求を送信。採掘は要求しない |
| 移動中 | 現在位置と行き先を保持 | 「移動中」の無効表示 | 到着を確認したら下の状態へ |
| 選択区画に到着 | 母艦の丸が選択枠へ到着 | 採掘範囲を確認 | 到着後の新しい範囲確認へ |
| 範囲を確認 | 採掘する区画、16×16、高さ両端、破壊あり | この範囲の採掘を開始 | 別の明示入力で開始要求 |
| 開始の応答待ち | 対象を保持し「開始を確認中」 | 二重送信を無効化 | 稼働を示すViewを受信して採掘中へ |
| 採掘中 | 同じ範囲と進捗 | 常設の停止、必要なら貨物・補給へ | 停止後は手動で再確認 |
| 確認が失効 | 範囲をもう一度確認してください | 採掘範囲を確認 | 新しい範囲で最初から確認 |

別区画からの移動では`MOVE`だけを送り、到着してもプレビューや採掘を自動開始しない。到着はサーバーの`navigation.exterior()`が選択区画内、`moving=false`、行き先なし等の状態から確認する。停止しただけ、航路障害で止まっただけ、応答がないだけを到着と扱わない。現バックエンドは母艦直下の区画しかプレビューできないため、この移動段階を省略しない。

MOVEの目的地は選択区画中央のx/zと現在の航行高度を基本とし、確認対象を地図で明示する。128ブロック以内、読込済み、安全空域などの可否はサーバーが判断する。拒否された地点へ勝手に代替移動しない。海抜・障害で高度調整が必要なときは「移動」タブの高度欄で別に指定し、採掘確認へ紛れ込ませない。

## 誤操作を防ぐ確認

確認画面に入った直後は「範囲を確認しました」を未チェックにする。PNGはチェック済みで開始が有効になった状態を示す。選択・範囲・高さ・次元・船・モードが変わる、戻る、期限切れ、通信断ではチェックと確定参照を破棄する。

確認時は返ってきた範囲をそのまま表示し、推定地表だけで採掘深さを隠さない。高さは両端を含む。現在のbackendでは下限から船の高度-6までとなる。表示したものと同じgeneration、menu.containerId、shipIdを内部で保持し、開始には正確なUUIDを使う。初期Viewのmenu=-1は送らない。

通常幅では「地表から下へ / 岩盤は残す」を主表示にし、実際の高さ範囲を補助表示する。サンプルのY=-64を他ディメンションへ固定適用しない。小画面では高さを範囲詳細へ収め、実装時にも確認対象の下限を調べられるようにする。

確認の期限切れは「範囲をもう一度確認してください」に置き換え、開始を無効にする。再確認の受信で勝手に再チェック・再送しない。技術語を隠しても安全性を隠さない。

「区画を選び直す」または確認画面の「戻る」は草稿を捨てて選択へ戻るだけ。採掘の停止を意味しない。常設「停止」は確認なしでSTOPを送り、採掘・攻撃・移動と一時補給を停止する。サーバーの通常操作間隔制限でSTOPを待たせない。所有者以外へ送信権限を付けない。

停止理由や読込後に自動再開しない。保存範囲から続ける場合は採掘タブの「前の採掘を続ける」から新たに範囲確認を開く。RESTOREを装った開始ボタンは作らない。

## 採掘と敵への攻撃

2つは排他的な稼働モード。タブを開くだけでは稼働切替しない。採掘が動いているときに攻撃を選んだ場合、まず「採掘を停止」を明示操作し、停止が反映されてから攻撃範囲を確認する。逆も同じ。PREVIEW要求自体が現backendで作業を止めるため、稼働中にタブ表示だけで送らない。

攻撃画面には「地形は壊しません」を常時表示し、「この範囲の敵を攻撃」を実行名にする。採掘用の破壊警告・ブロック進捗を再利用しない。最大5秒の稼働時間は攻撃そのものの仕様として表示してよいが、内部プレビュー期限と混同しない。友軍・保護・遮蔽の判断は現backendを維持する。

## 貨物・補給と船内

主画面には使用枠数と補給品の状態だけを表示する。単なる在庫有無を作業完遂保証にせず、「補給品あり」は実Slot内の該当資源から分かる範囲に限定する。必要量を算出できなければ「十分」と断定しない。詳細な残量は貨物・補給へ分ける。

貨物タブではバニラ54貨物+36所持品の実Slotをそのまま使用する。貨物0-53はx8+列×18、y18+行×18。所持品54-80はx8、y140から9列3行、ホットバー81-89はy198。18pxピッチ、16pxアイテム領域、番号、Shift移動、ドラッグ、分割、数字キー、カーソル保持、サーバー同期を変更しない。

タブ切替で隠したSlotを操作できないようにし、画面側の描画・ヒット判定を同じ表示状態へ結び付ける。`CarrierMenu`の座標を画面都合で変更しない。保持中のカーソルStackを捨てない。旧案の「90枠を主画面に常時表示」は取り下げる。

飛行用電力と採掘・攻撃用電力は別々に表示・補給する。小型機への補給は同タブの下位ビュー。最大4機の対象を名前で選び、取り消せる。APIには各機の補給進捗がないため、架空の百分率・完了表示・接近中表示は作らない。通常画面へUUIDや「個別進捗未取得」を並べない。必要な識別情報は選択時の詳細と診断へ置く。所属Dock/Wing/元任務は変更しない。

船内タブには「船内へ入る」「外へ出る」と招待者一覧を置く。破壊済み所有船は「残った荷物を取りに行く」を表示する。招待はオンラインのプレイヤー一覧から選び、UUID手入力を通常操作にしない。安全な下船先がなければ理由を表示して船内に留まる。

## 全15操作の対応

| backend action | 場所 | 操作名・意味 |
| --- | --- | --- |
| PREVIEW_MINING | 採掘 > 区画選択 | 採掘範囲を確認 |
| PREVIEW_COMBAT | 敵への攻撃 > 区画選択 | 攻撃範囲を確認 |
| ACTIVATE | 採掘 / 敵への攻撃 > 確認 | この範囲の採掘を開始 / この範囲の敵を攻撃 |
| RESUME_PREVIEW | 採掘 > 停止後 | 前の採掘を続ける。範囲確認から再開 |
| STOP | 全タブ・確認画面の固定下端 | 停止。確認なし |
| BOARD | 船内 | 船内へ入る |
| EXIT | 船内 | 外へ出る |
| MOVE | 地図で別区画選択 / 移動 | 母艦をここへ移動 |
| REFUEL | 貨物・補給 > 母艦に補給 | 燃料を補給。所持power_cell 1個で飛行電力1,000 |
| CHARGE_WEAPON | 貨物・補給 > 母艦に補給 | 電力を補給。所持laser_cell 1個で採掘・攻撃用電力1,000 |
| RESERVE_BAY | 貨物・補給 > 小型機に補給 | 機体を選ぶ |
| RELEASE_BAY | 貨物・補給 > 選んだ機体 | 取り消す |
| ALLOW_GUEST | 船内 > 招待する | プレイヤーを選ぶ |
| REVOKE_GUEST | 船内 > 招待者 | 招待を取り消す。搭乗者の安全を維持 |
| RECOVER_CABIN | 船内 > 破壊後 | 残った荷物を取りに行く |

Actionの識別子は仕様・診断用であり通常画面のラベルにしない。送信には既存`CarrierClientApi.send`を使い、voidの戻りを成功通知にしない。guestフィールドは招待操作ではプレイヤーUUID、ベイ操作ではドローンUUIDなので選択元を混同しない。サーバーの所有権・距離・全4機/32名制限・拒否規則を保持する。

## 小画面

320×180では採掘の選択・確認・実行中を独立した画面にする。共通の戻る、現在タブ、停止、次の主操作を固定し、主画面にインベントリは出さない。必要時に拡大地図から確認へ移る。狭幅で全タブを一列に縮小せず選択メニューへ切り替える。使用枠の要約は残すが、詳細残量は専用画面に分ける。

貨物90枠だけは176×222以上の領域が必要で、320×180には固定座標の全枠を表示できない。この物理制約は分割によって消えない。貨物画面では必要なGUI高さを明示し、読めない縮小や架空のページ式Slotで解決済みにしない。実効GUIが320×240なら貨物だけを単独表示し、補給操作は同タブの別ページへ分ける。GUI倍率は自動変更しない。

文字の長さ、Minecraftフォント、GUI倍率、Slotの切替とヒット判定、保持中Stack、地図の逆変換、実際のクリック・誤連打・期限切れ・移動失敗は承認後の実機QAで確認する。図と純粋テストだけでruntime合格を宣言しない。
