# Morrowgear 全体デザイン見直し V1
日付: 2026-09-20 / 状態: 提案、未承認、ゲーム未反映

## 対象と根拠
現行Java Modのアイテム登録、textures/item、DroneRole、TacticalDashboard、VisorHudPolicy、VisorClientConfigおよび各Rendererを棚卸し対象とした。登録アイテム23種、ロール6種を確認。通常機の既存共通モデル数とロール数は同一ではないため、6種類の独立モデルが現在実装済みとは扱わない。

今回はMod全体の外観と操作体験を再設計する提案。画像は内蔵画像生成ツールによる概念図であり、Minecraft実行画面でも、寸法・対称性を検証した正本メッシュでもない。世界観、名称、造形、UI、演出、音を同一方針にそろえる。機能、レシピ、性能、識別子の変更は今回の承認に含めない。

## 共通方針
A精密工業型を仮基準とし、ScoutにB航空機型、作業・回収系にC開拓重機型の機能的な特徴を展開する。Aを承認済みとは扱わない。
- 低い輪郭、埋込バイザー、厚みのあるローターダクト、実用的な脚。
- 外装は黒鉛色、荷重部は銀色金属、整備接点は小さな橙色。素材は素地を見せる。
- 共通接続面、ラッチ、分割線、ねじの寸法系列を正本モデルで定義し、アイコンと装着モデルで共有する。
- シアンは友軍・通信・選択、アンバーは注意、赤は敵・危険、緑は成功。文字・記号を併記し色だけに依存しない。
- 作業ビームは細い青緑、給電は青白、攻撃は橙白。全てのビームを同じ形・輝度にしない。
- ロゴと英語コピーは画像中の仮表現。新しい正式ロゴやタグラインの承認ではない。

現行TacticalDashboardにはUNIT/WING/ALL、ソート処理、Wing/Dock/コンテナ一覧が存在する。提案図のMap/Wings/Missions/Serviceは再構成案であり、現行画面と同じとは扱わない。

| 画面・操作 | 提案 |
|---|---|
| 戦術地図 | 左が選択、中央が地図、右が命令、下が任務。地図の中心を一覧更新で動かさない |
| 機体一覧 | 検索、ロール・状態・Wingフィルター、IDで安定ソート。距離ソートは明示選択時のみ |
| 複数選択 | チェック、範囲選択、追加選択を同じ規則に。全機と絞込結果の全選択を区別 |
| Wingボード | 各Wingは必ず8枠。空き、占有、参加予定を区別。ドラッグ中の自動並替禁止 |

| 任務一覧・詳細 | 進行中、割込、復帰予定、完了、失敗を区別。現在目標と中断理由を表示 |
| ルート編集 | 点番号、順序、起点、巡回方向、閉ループを表示。下書きと確定ルートを区別 |
| 採掘・林業・走査 | 範囲、対象ブロック、必要ロール、調査済み範囲、残作業を地図と一覧で一致 |
| Cargo輸送 | 搬出元、搬入先、運搬量、予約・競合・満杯を表示 |
| 戦闘割当 | 目標別の投入数、増援、補給離脱を表示。Wing所属と一時攻撃群を別列に |
| Dock一覧・補給 | 帰属Dock、利用中Dock、設備種別を区別。飛行電力・武器電力・弾薬・修理資源を別表示 |

| サービス充電 | 3枠の予約・接続・給電・離脱、蓄電量、対象値、推定待ちを表示 |

サーバー応答前の状態は実行済みと表示しない。選択は行番号ではなく永続IDで維持する。
スクロールは領域ごとに閉じ、モーダル中に背後の地図へ命令が漏れない。
小画面では右詳細を開閉式にし、文字縮小で詰め込まない。日本語、長い任意名称、大きいGUIスケールを評価する。

## HUDの優先度とスケール
現行VisorHudPolicyは8機以下、32機以下、128機以下、それ以上の密度区分を持つ。これを活用し、表示枠の増殖を抑える。以下は改訂提案であり未実装。
1. 即時対処: プレイヤー危険、電力喪失、操作失敗。
2. 注視・固定対象: 機体ID、状態、飛行電力、武器、体力。
3. 進行作戦: 戦線別の敵数・投入数・増援・補給・回収。
4. 通常運用: Wingと任務の集約。必要時に詳細へ展開。

固定表示と警告は別枠。新警告が固定対象を置換しない。各枠は原則3秒保持し、重大度上昇時のみ即時差替えする提案。解除は短時間の揺れで点滅しないよう実データで調整。
- 平常: 集約1行、注視対象だけ詳細。中央とホットバーを保護。
- 多機: 機体→Wing→作戦単位へ集約。ラベルを全機に出さない。
- 複数戦闘: 安定した戦線IDで最大3行を提案。敵数、投入数、増援、充電離脱、追加戦線数を表示。距離だけで順番を変えない。
- 作業と戦闘混在: 作業進捗を維持し戦闘を別行へ。全機COMBAT表示に潰さない。
- 長距離回収: Beaconの距離、上下差、次元、情報の鮮度。遮蔽マークを付け、見えている実体と混同させない。
- 3Dマーカー: 描画補間後の機体位置、同フレームのカメラ・投影行列、GUI座標変換を使用。画面外、背面、遮蔽、削除時を個別に処理。

## 演出・音
| 動作 | 視覚 | 音 |
|---|---|---|
| 通常飛行・巡航 | 後部同一原点の細い連続軌跡。翼数に応じ密度を抑制 | 重い機械的ローター、距離減衰、同時音量上限 |
| 作業 | 対象ブロックへ細い作業ビーム、必要な接触粒子だけ | 小さな駆動・加工音、反復通知なし |
| 給電 | 子機から対象接点へ青白ビーム、完了時自然消灯 | 静かな通電音、機体位置から聞こえる |
| レーザー充填 | 射出口内部へ集約。外に無関係な線を出さない | 低音から密度が上がる充填音、不快な周期ピッチ変調なし |
| レーザー照射 | 橙白の連続コア、壁は深度で遮蔽、実照射先に一致 | 安定した持続音、高音帯と多機合成の音量を抑える |
| レーザー終了 | 射出口の残光、排熱 | 短い金属音と冷却音。過去に不評な余計な音を機関砲へ流用しない |
| 機関砲 | 前方への途切れた曳光、線状の小さい着弾 | 発射機の連射音を主体、着弾音は位置・距離を分離 |
| ミサイル | 発射口、離脱、誘導、着弾を区別 | 発射と飛翔、距離に応じた着弾 |
| 戦闘進入 | 一度の短いフレアと状態灯変更。近接戦闘では帯を消す | 状態変化ごとの過剰な通知を避ける |
| POWER LOST | ローター停止、姿勢と落下、回収ビーコン | 飛行音停止。Beaconは常時音を鳴らさない |
| 回収・牽引 | 巻上げ、荷の小さい揺れ、接地余裕 | ウインチと荷重に応じたローター |
| 着艦・発艦 | 接地、ローター減速、充電接続の順序 | 回転と停止へ同期 |

音の変更は方向性の設計のみ。今回音源は生成していない。

## 画像レビューで見つかった不一致
- 01-items: パワーセルと標準バッテリーが似すぎる。パワーセルを円筒へ改訂。サービスDockは中央が穴の形で、02-fleetの中央ハブ形を正とする。
- 01-items: ミサイル筒数は実装容量の証拠ではない。実装と照合して正本を定義する。
- 03-ui: ALPHA表示数と枠数が一致せず、8枠規則にも反する。Assault/Repair等の仮名称は現行6ロールに置換する。地図の重複番号も修正対象。
- 03-ui: HUDのナビゲーション、見出し、解説文は概念図のラベルでありゲーム内に表示しない。
- 03-ui: 格納庫状のDock画像、FE表記、矢弾薬、固定50%再出撃条件は採用しない。通常Dock正本と現行資源・再出撃ポリシーを使う。
- 04-effects: 機体とステーションが02-fleetから変形している。演出位置と色の参考に限定し、モデル正本には使わない。
- 全画像: ロゴとコピー、細部寸法、左右対称は未確定。画像生成だけで同一形状・操作整合を保証しない。

## 次の制作と評価
1. 全体方針の承認後、形状寸法・接続部・原点を単一メッシュで確定し7方向を確認する。
2. 同一正本からアイコンを生成。32/64px、暗明背景、名前なし識別を確認する。
3. UIは決定論的なレイアウトと模擬データで作成し、0/1/8/32/100/128超機、空きなし、削除、通信遅延、混成任務で検証する。
4. HUDはGUI倍率、解像度、昼夜、水中、地下、急な視点移動、画面外、複数戦線、長距離Beaconで確認する。
5. 実装差し替え後、起動版と素材ハッシュを照合。視覚検証と既存動作回帰試験を別に記録する。
現時点の検証は実装棚卸しと概念図目視レビューのみ。実装・ゲーム内試験PASSの報告ではない。
