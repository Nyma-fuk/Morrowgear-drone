# 承認済み音源のゲーム接続

## 現行仕様

2026-09-22、0.20.4。ユーザーの「ここまでの内容反映」を受け、試聴済みの音を採用する。
旧0.20.3の全合成セットではなく、以下の組合せが現行版。

- 飛行: 7層のハイブリッド案。ローター、圧縮機、燃焼部を想定した低音、タービン、排気、機体共振、吸気。
- 機関砲: V3のA-10録音由来の開始・連続掃射・停止。音の密度を高める演出であり、実弾の発射頻度は変えない。
- レーザー: V3の充填・放電・冷却に、V4の固定2200 Hz成分を控えめに加えた照射音。
- ミサイルと着弾: V2の射出・点火・噴射・衝突・爆発・破片。

この変更では威力、消費エネルギー、弾数、飛行や攻撃の状態遷移は変更しない。
飛行の燃焼部は音の世界観であり、燃料消費機能の追加ではない。
屋内外の反響試聴は設計検討用。地形に応じた音響伝搬・遮音・ドップラーのシミュレーションは未実装。
音源内部の共振や録音由来の反響と、ゲーム空間の動的反響を混同しない。

## 採用音源

全て48 kHz、mono、Ogg Vorbis。ゲーム側の音源位置と距離減衰を利用する。
正本は src/main/resources/assets/morrowgear_drone/sounds 内。
audio-approved.json に試聴元・SHA256・長さ・ループ用途・減衰距離を記録する。
再圧縮せず採用Oggをコピーしたため、試聴元と同一バイトである。

連続音は同じ機体・同じ再生枠を維持し、毎tick再スタートさせない。

機関砲の着弾音を小さくし、発射側の連続音が聞き分けられる構成にする。

## 再生責務

### クライアント

DroneAudioController が機体に追従する飛行、レーザー、機関砲とミサイル噴射を所有する。
MorrowgearDroneClientから一度だけ登録し、クライアントtickと切断時停止を接続する。

- 飛行は最大8機、レーザー4機、機関砲8機、ミサイル噴射12発。短い尾音は最大32件。
- 距離と既存音源の優先保持で選択し、選択機数の平方根で音量を割る。音源上限は攻撃参加数の上限ではない。
- 飛行は速度に応じてidle/cruiseを線形クロスフェード。持続音量の最大係数は0.24、音程係数は0.94から1.04に小さな個体差を加える。
- 機関砲はGUN_RUNだけでは鳴らさない。同期された直近の実発砲時刻が3 tick以内の場合に連射音を維持する。
- 掃射開始と停止は一度ずつ。2 tick間隔の射撃では音が途切れず、最後の弾の後は期限で止まる。攻撃状態を離れた場合は即座に止める。
- ミサイル噴射は同期された点火状態から開始し、着弾・死亡・silent・追跡圏外で止める。機体ではなくミサイル本体を追う。
- 全てSoundSource.PLAYERS、相対再生なし、線形距離減衰あり。音量はプレイヤーの設定に従う。
- 着艦・電源喪失・死亡・silentで機体音を停止。ワールド変更・切断時に全再生枠を破棄する。
- 一時停止中は状態を保持。リソース再読込で消失したループは20 tick以上の間隔で再試行する。
- 古い充填・放電開始は追跡開始時に再演しない。途中の持続照射には参加できる。
- LASER_FIREからLASER_CHARGEに移る場合も、停止側の冷却音と新しい充填は独立する。

機関砲の発砲時刻をレーザー等の別兵器と共用しているため、音を鳴らす際は必ず戦闘状態も検査する。
音声側が新しい攻撃指令やダメージを発生させてはならない。

### サーバー

DroneEntity は機関砲とレーザーの実着弾音のみを再生する。
旧機関砲の短音反復、旧飛行音、旧レーザー持続音のサーバー再生は併用しない。

MorrowgearMissileEntity は射出・点火・衝突・実爆発を再生する。
点火には専用IDを使用し、射出音の低音再生で代用しない。
爆発音はlevel.explodeの既存音声引数に接続したままとし、sounds.jsonのvolume: 0.24でバニラ側の大きな係数を補正する。
着弾後の信管12 tickは変更しない。

MissileAudioController は実爆発成立後に破片音を7 tick遅延で予約する。
ワールド単位で最大64件。重複ID、古い時刻、時刻巻き戻り、停止時の残留を抑制する。
単なる対象消失や破棄では予約しない。爆発音やダメージをこの予約処理から発生させない。

## 出典・保守

飛行とレーザーの装置音は独自合成。機関砲とミサイル系の一部はCC0表示の録音を加工している。
「全て外部素材なし」という旧仕様は現行版には当てはまらない。
収録元、作者、加工内容、原本との違いはJAR内の licenses/AUDIO_SOURCES.md に同梱する。
音源ページに記載された来歴と、独立に確認できた事実は分けて記録する。

tools/audio/install_approved_audio.py は、全試聴元のハッシュ・形式を確認してからリソースへコピーする。
試聴元はbuild/verification内の保存済み出力。そこがない環境ではリポジトリ内の採用Oggを正本として使用する。
試聴を再生成してもVorbisのファイル識別情報等でバイト列が変わることがあるため、自動的に承認ハッシュを更新しない。

旧generate_drone_audio.py / generate_laser_sounds.pyは、承認マニフェストがあるゲーム音源を上書きしない。
新案は別フォルダーで試聴してから承認版の一覧を更新する。
登録は既存IDを維持し、sounds.jsonとtools/audio/sounds.integration.json、日英字幕を同期する。

## 検証と導入

依存はPython、numpy、soundfileと既存のGradle/JDK環境。
音源試験の閾値は採用した各案の仕様に合わせる。旧版の特定倍音や秒数を新音源へ適用しない。
ただし、変更を通す目的で壊れた音の閾値を緩めてはならない。

1. 音源系の全試験: python -m unittest discover -s tools/audio -p "test_*.py" -v
2. build -x syncLauncherModで、テスト失敗時の自動差し替えを避けてビルド。
3. 成功後にsyncLauncherModを明示実行。
4. 成果物と導入先JARのSHA256、内部バージョン、18音源のハッシュ、登録・字幕・出典を照合。
5. 起動権限があるときのみ実ゲームで定位、距離、多数同時発音、着艦・破壊時の停止を確認。

今回の自動試験結果:
- 音源系56件PASS。採用18IDの形式、秒数、同一性、ピーク、RMS、DC、ループ境界、無音欠落、固定高音、登録・字幕を含む。
- Java1954件PASS、失敗0、スキップ0。発砲状態による再生の開始・継続・停止、ミサイル点火・着弾の全真偽組合せ、既存回帰試験を含む。
- 実ゲームは今回起動しない。上記PASSはゲーム内聴感、遮蔽、最終ミックスの評価を意味しない。
