# Morrowgear Tactical Visor UI意味設計・スケーリング仕様

更新日: 2026-08-24  
状態: 承認用。実装前の情報設計。

## 1. 設計上の問題

機体やWingが増えるほど、個体の状態変化、任務開始・終了、交戦、充電、Recoveryも増える。重要度だけで表示対象を自動選択すると、左右のパネルやフォーカス対象が短時間に何度も入れ替わり、プレイヤーは情報を読めなくなる。

したがって、UIの目的を「全機の状態を順番に見せること」ではなく、次の3点へ限定する。

1. 群全体が正常かを一目で判断できること
2. 異常がある場合に、規模と影響範囲を判断できること
3. 必要なときだけWing、任務、個体へ掘り下げられること

## 2. 全体構造

従来のCompact、Wing、Combatを画面全体の排他的なモードとして扱わない。表示骨格は固定し、必要なレイヤーだけを追加する。

| 領域 | 意味 | 自動切替 |
|---|---|---|
| 上端 Fleet Strip | 群全体の健全性と即時リスク | 数値と色だけ更新する。配置は変えない |
| 左 Command Context | プレイヤーが管理中のWing・任務 | ユーザー操作時だけ切り替える |
| 右 Inspection Context | 固定または注視中の対象 | 固定中は自動切替しない |
| 中央 Spatial Overlay | ワールド内の位置関係 | 距離と優先度で間引く |
| 下端 Action Rail | 対応が必要な警報と結果 | 自動更新するが同種を集約する |

Combatは左右パネルを別対象へ強制切替するモードではない。Fleet Stripへ脅威を追加し、中央へ敵対対象、Action Railへ迎撃状況を追加するレイヤーとする。

## 3. 各表示の意味

### 3.1 Fleet Strip

「今、群全体が任務を継続できるか」を示す。

- `ONLINE`: データリンクが有効な所有機数
- `ACTIVE`: 任務、追従、哨戒、作業、戦闘中の機数
- `DOCK`: 着艦、充電、整備中の機数
- `RTB`: 帰還命令が確定している機数
- `REC`: Recovery中または経路復旧中の機数
- `LOST`: 直近一定時間内に破壊または通信喪失した機数
- `OPS`: 同時進行中の任務数
- `THREAT`: プレイヤーに対する現在の危険度
- `ALERT`: 未解決P0/P1警報数
- `LINK AGE`: 最新テレメトリからの経過時間

Fleet Stripは個体名を表示しない。機数が増えても同じ幅で数値だけ増える。

### 3.2 Command Context

「プレイヤーが現在管理対象として選んだ命令」を示す。自動では切り替えない。

- 選択中のOperation、Wing、任務
- 目的、進捗、ETA、Formation
- 参加Wing数、稼働機数、離脱機数、Recovery数
- 完了、失敗、保留理由

選択中のWingから一部機体が戦闘へ一時離脱しても、パネル自体は元のWingを表示し続ける。離脱は`DETACHED 3 / INTERCEPT`として集計表示する。

### 3.3 Inspection Context

「プレイヤーが詳しく見たい対象」を示す。

- 個体: HP、飛行電力、兵装電力、弾薬、Heat、役割、任務、Dock、リンク
- Wing: Leader、構成、任務、Formation、平均値、最小値、異常機数
- 敵: 敵自身の脅威、プレイヤー危険度、割当戦力、推定撃破時間
- Dock: 空き、使用中、待ち行列、充電能力、進入異常

固定した対象はP0が発生しても勝手に置き換えない。P0はAction Railと方向インジケータへ出し、プレイヤーが選択したときだけInspection Contextへ展開する。

### 3.4 Spatial Overlay

「情報がワールド内のどこに存在するか」を示す。

表示対象は次の順で選ぶ。

1. 固定対象
2. P0対象
3. 選択中任務の目的地と対象
4. 選択中WingのLeader
5. P1対象
6. 視線上の対象

すべての機体へラベルを表示しない。同じ方向に複数機がある場合は、`ALPHA-03 x8`のようにクラスタ化する。

### 3.5 Action Rail

「今、プレイヤーが知るか判断する必要がある事象」を示す。

- P0: プレイヤー危険、墜落余力、機体破壊、Dock進入不能
- P1: RTB、充電交代、Recovery長期化、兵装継続不能、任務失敗
- P2以下は原則として自動表示せず、Command Context内へ記録する

Action Railは警報を1件ずつ高速に切り替えない。同じ原因の警報を集約し、最大3行とする。

例:

- `FLIGHT RESERVE x4 / ALPHA-03 / RTB ASSIGNED`
- `RECOVERY x7 / 2 WINGS / LONGEST 18s`
- `HOSTILE T4 x2 / 12 SECURITY ASSIGNED / DEFICIT 3`

## 4. 表示対象を安定させる規則

### 4.1 固定文脈

- Command Contextはユーザーが選び直すまで固定する。
- Inspection Contextは固定解除まで維持する。
- 自動処理は固定パネルを書き換えず、バッジとAction Railへ追加する。

### 4.2 最低表示時間

- Focus候補の成立: 同じ対象を0.25秒注視
- 一時Focusの最低表示: 1.2秒
- Focus解除待ち: 視線が外れて0.8秒
- Action Railの最低表示: P0は2.0秒、P1は3.0秒
- 並び替え間隔: 2.0秒に1回まで
- Combat表示解除: 脅威が解消して3.0秒後

### 4.3 ヒステリシス

警報への昇格は速く、解除は遅くする。

- P0昇格: 1回の確定イベントまたは0.25秒継続
- P0解除: 2.0秒安定
- P1昇格: 0.5秒継続
- P1解除: 3.0秒安定

残量が閾値付近で上下しても`LOW POWER`と正常表示が点滅しないよう、発生閾値と解除閾値を分ける。

## 5. 情報量のスケーリング

機数だけで段階を決めず、画面サイズ、GUIスケール、異常数、選択対象を含む表示予算で決定する。ただし基本形は次のとおり。

### 1～8機

- 選択中Wingの全個体を表示可能
- 個体ごとにHP、飛行電力、状態記号
- 詳細値は固定中の1機だけ

### 9～32機

- Wing単位を標準表示
- 個体表示は固定機、Leader、P0/P1対象
- 同一警報はWing内で集約

### 33～128機

- Operation単位を最上位にする
- 選択中Operation内のWingを最大4件表示
- 正常Wingは`NORMAL 8 WINGS`へまとめる
- 異常機は最大3件と残件数を表示する

### 129機以上

- Fleet Strip、Operation、異常クラスタを中心にする
- 個体ラベルは固定機とP0だけ
- 同一地点・同一任務・同一状態を1クラスタとして扱う
- `RECOVERY 17 / 3 WINGS`のように影響範囲を優先する

## 6. 表示予算

画面ごとに次の上限を設定する。

- 左パネル: Operation 1件、展開Wing最大4件
- 右パネル: 固定対象1件、関連異常最大3件
- ワールドラベル: 通常6件、Combat 8件、P0は上限外
- Action Rail: 最大3行
- 画面外方向インジケータ: 最大4方向。近い方向はクラスタ化

上限を超えた情報は消さず、`+12`のような残件数と最悪値を表示する。詳細は統合戦術管理画面で確認する。

## 7. 警報の集約キー

警報は次の組み合わせで同一事象と判定する。

`severity + type + operationId + wingId + targetId + locationCluster`

個体ごとの低電力が同一Wingで発生した場合はWing警報へ、複数Wingで発生した場合はOperation警報へ昇格集約する。機体破壊、Dock進入不能、プレイヤーへのP0脅威は集約後も個別へ展開できるよう元IDを保持する。

## 8. 大規模群で必ず表示する情報

機数に関係なく次は省略しない。

- プレイヤーに対するP0脅威
- 機体破壊と通信喪失
- 任務を継続できない電力・弾薬・役割不足
- Dockへ到達できない機体
- 命令失敗、Wing混入、所属不整合
- テレメトリの古さ
- 選択中対象の状態

ただし表示形式は個体一覧ではなく、件数、影響範囲、最悪値、最長継続時間へ集約する。

## 9. 自動切替を許可する範囲

| 変化 | 自動切替 |
|---|---|
| Fleet Stripの数値・色 | 許可 |
| Action Railへの警報追加 | 許可 |
| 画面外P0方向表示 | 許可 |
| Command Contextの対象変更 | 禁止 |
| 固定済みInspection Contextの対象変更 | 禁止 |
| 一時Focusの候補変更 | 最低表示時間後のみ許可 |
| Combat情報の追加・解除 | ヒステリシス付きで許可 |

## 10. 例

### 96機・12Wing・7任務・異常なし

- 上端: `ONLINE 96 / ACTIVE 72 / DOCK 18 / RTB 6 / OPS 7 / ALERT 0`
- 左: 選択中Operationと、その配下の最大4Wing
- 右: 固定対象がなければ閉じる
- 中央: 選択中任務の目的地とLeaderだけ
- 下端: 非表示

### 96機・低電力12機・Recovery7機・強敵2体

- 上端: 機数は維持し、`ALERT 3 / THREAT CRITICAL`
- 左: 選択中任務を維持
- 右: 固定対象を維持
- 下端: 低電力、Recovery、強敵を3行で集約
- 中央: 強敵2体と最寄りのP0機だけ

画面全体を12機、7機、2敵の間で切り替えない。

## 11. 実装単位

1. `TelemetrySnapshot`: 個体、Wing、Operation、Dock、Threatの生データ
2. `AlertFingerprint`: 警報の同一性と集約キー
3. `HudPriorityEngine`: P0～P3の優先順位
4. `HudStabilityController`: 固定、最低表示時間、ヒステリシス
5. `HudDensityPlanner`: 表示予算と集約階層
6. `WorldLabelClusterer`: 距離・方向・任務によるラベル集約
7. `VisorHudRenderer`: 固定された各表示領域の描画

## 12. 必須試験

- 1、8、9、32、33、96、128、129、512機
- 0、1、4、20、100件の同時警報
- 同一Wing、複数Wing、複数Operationでの同種警報集約
- P0連続発生時にも左右パネルが切り替わらないこと
- 閾値付近の電力・Heatで点滅しないこと
- 100機が任務と充電を頻繁に往復しても並び替えが2秒より速くならないこと
- GUIスケール、画面比率、チャット、ボスバーとの競合
- テレメトリ遅延、欠落、順序逆転、再接続
