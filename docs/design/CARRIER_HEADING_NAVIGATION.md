# 母艦の方位と航行

## 座標と描画契約

- 船体は幅26X・高さ11Y・全長50Z、原点は船底中央。ローカル機首は-Z、右舷は+X、船尾は+Z。
- `CarrierEntity.toWorld(Vec3)` は位置に正Y軸の `getYRot()` 回転を加える。`toLocal(Vec3)` はその逆変換。
- 描画も同じ正Y回転を使い、方位は `yRotO` と `getYRot()` の最短角補間を行う。
- 巨大船体の安全を優先し、今回は水平のyaw旋回のみ。`getXRot()` と同期FLOATの `flightRoll()` / `flightRoll(float)` は0。描画だけの傾斜は付けない。
- 通信位置・方位は既存ミサイルと同じ `InterpolationHandler(this, 2)` をクライアントtickで更新する。サーバーの移動判定をクライアント補間で代替しない。

## 航行と停止

- 最大速度0.5 block/tick、加速0.015 block/tick²、減速0.025 block/tick²、旋回2度/tick。
- 別方向を指定すると旧進路のまま減速し、停止してから進路へ旋回、その後前進する。横滑り・後退による目的地追従は行わない。垂直移動時も船体は水平を保つ。
- 到着前に離散的な制動距離で減速する。距離の二乗が `1e-16` 未満で到着扱いとする。
- 通常の到着・進路変更は加減速するが、STOP、電力喪失、障害物、所有者不在、未ロード待ちでは安全のため即座に移動を止める。保存済み目的地を保持し、停止後の再出発は明示MOVEのみ。
- 船体のyaw回転を含む包絡AABBを使い、両端形状に加えて角の回転弧長も安全側に含める。障害物を削除せず、角度のついた船体の余白では保守的に停止する場合がある。
- 全包絡のロード状態・地表余裕・ワールド境界・衝突を毎移動tick確認する。既存 `flightMetrics()` の回数・最大時間・高さ照会数で負荷を観測できる。
- 保持上限は変更しない。4隻、各2 tickets、半径3。8 ticketsを8 chunksとは扱わず、full chunk影響上限392と生成周辺範囲を区別する。

## ベイと搭乗

- 既存4ベイのローカルXYZは変更せず、`bayPosition` / `bayApproachPosition` が同じyaw変換で世界座標を返す。
- `bayVelocity(slot)` は並進に加えてその点の1tickの回転変位を含む。`bayServiceReady()` がfalseの間は補給せず、船底の待機点へ退避する。
- 回頭は予約ドローンが船底の安全余裕より下に退避し、回転包絡に生存者がいない場合のみ行う。退避待ちは最大100tick、失敗時は目的地を残して安全停止する。
- 搭乗投影と退出時の船尾判定もローカル座標へ統一。yaw次第で船尾投影が採掘チャンクに重なるため、その稼働列は搭乗・退出候補から除外する。
- 描画用安全足元は従来の `Optional<BlockPos> visualBoardingPad()` を使用する。許可判定や実際のテレポートはサーバーで再検証する。

## 受入検証の出航待ち

- `travel_start` / `combat_start` は通常補給セルを入れ、燃料2000以上・6tick以上を待ってから通常MOVEを送る。充電待ちは120tickで打ち切る。待機中に別の移動・作業が始まった場合は上書きしない。
- 自然な航行停止で `TRAVEL_PAUSED` になった場合、同じサーバー起動中に限り `travel_resume` が元のRun・原点・累積移動距離を継続する。船、停止位置、保存目的地が不変であることが条件。通常MOVEの再送以外の移動手段は使わない。
- 停止中の手動MOVE・移動、サーバー再起動では継続資格を失う。未観測の移動を検証済みとして数えない。元Runの総時間上限16000tickは延長しない。
- `CarrierHeadingTest` に544ブロック往復、加減速、方位、回転包絡、ベイ／搭乗逆変換、有限ticket範囲の試験を追加。`CarrierAcceptanceDepartureTest` に燃料待ちと停止位置の異常系を追加。
- この変更担当ではビルド・試験実行・ゲーム起動を行っていない。統合試験は親担当。描画の滑らかさや実機航行を確認済みとは扱わず、`release_ready=false` を維持する。
