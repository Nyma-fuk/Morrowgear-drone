# Morrowgear 戦術HMI設計規約

## 1. 目的

MorrowgearのUIは装飾ではなく、プレイヤーが次の3点を短時間で判断するための装置とする。

1. いま何が起きているか。
2. 誰が何を担当しているか。
3. なぜ出撃・任務復帰・補給が進まないか。

画面を情報で埋めることは目的ではない。通常時は静かに、異常時は原因と次の行動だけを強く表示する。

## 2. 採用する視覚言語

4つの潮流は画面ごとに役割を分ける。

- **ダークモード／高コントラスト**: 全画面の基盤。背景は黒に近い無彩色とし、情報色を目立たせる。
- **ダイエジェティックUI**: バイザーHUDと機体マーカーに使用する。画面中央のプレイ領域を占有しない。
- **グラスモーフィズム**: HUDの情報層に限定して使用する。透明度は背景を読める範囲に留め、文字の背後だけを暗くする。
- **ネオ・ブルータリズム**: Dock、コントローラー、母艦コンソールに使用する。直線、区切り線、固定幅文字、明確な操作領域を優先する。

角丸カードの多用、装飾目的の発光、意味を持たない斜線は使用しない。

## 3. 色の意味

同じ色はすべての画面で同じ意味を持つ。

| 色 | 意味 |
| --- | --- |
| シアン | 飛行電力、通信、選択、正常なセンサー情報 |
| 青白 | レーザー電力、充填、エネルギー系統 |
| グリーン | 任務遂行可能、補給完了、正常 |
| アンバー | 弾薬、待機、供給不足の予兆、確認が必要 |
| レッド | 出撃阻害、敵、破壊、電力喪失、即時対応 |
| グレー | 参考情報、無効、未選択 |

色だけに依存せず、必ず短い文字ラベルを併記する。

## 4. リソースを統合しない

`WPN`や「兵装残量」の単一表示は禁止する。次を独立して表示する。

- `FLT`: 飛行電力
- `LZR`: レーザー電力
- `GUN`: 機関砲弾数／搭載上限
- `MSL`: ミサイル数／搭載上限
- `HEAT`: レーザー熱
- `STR`: 機体構造
- `SYS`: 最低サブシステム健全度

装備していない兵装は通常表示から除外する。AUTO機だけは全兵装を表示する。

## 5. 出撃可否の表示

残量の列挙より先に、判断結果を1行で表示する。

- `SORTIE READY`: 通常出撃可能
- `SERVICE ACTIVE / READY CHECK`: 補給中または任務復帰判定中
- `SORTIE BLOCKED / FLT + GUN`: 飛行電力と機関砲弾が不足
- `DOCK LINK LOST / REBIND QUEUED`: Dock破壊後の再割当待ち
- `DOCK HOLD / QUEUE n`: 空きDock待ち

阻害理由は複数あれば省略せず列挙する。プレイヤーが補充すべき品目を推測させない。

## 6. 情報階層

### 常時

- 機数、稼働数、着艦数、RTB数、Recovery数
- 現在の脅威段階
- 重大アラート数

### 選択・注視時

- 機体ID、役割、Wing、任務、対象
- 出撃可否
- 装備に関係する個別リソース
- Dock割当、Queue、Holding状態

### 複数戦線

- 敵総数
- 被覆済み目標数 `COVER x/y`
- 戦線数
- 投入Wing数、投入機数、予備機数
- 各戦線の `敵数H / 被覆目標数T / 投入機数U`

未割当の敵を、投入機数の多さで隠してはならない。

## 7. 規模に応じた縮約

- 1〜8機: 個体を表示する。
- 9〜32機: Wing単位を基本とし、異常機と選択機だけ個体表示する。
- 33機以上: 作戦・戦線単位を基本とし、未被覆目標、RTB、Recovery、電力喪失を例外表示する。
- 同じ原因の警告は集約して件数を出す。表示対象を高速で切り替えない。
- プレイヤーがPinした機体・Wing・作戦は自動で切り替えない。

## 8. 戦闘割当の表示契約

Scoutの報告は敵1体ごとのContactとして扱う。割当は次の順序とする。

1. 実行中の攻撃パスを維持する。
2. 未被覆の敵へ最低1機を割り当てる。
3. 脅威度、プレイヤー危険度、体力、損耗率から増援数を決める。
4. 全需要を満たした後だけ予備を残す。

敵数が使用可能なSecurity数以上なら、正常な機体を固定割合で予備に残さない。

## 9. Dock再割当の表示契約

Dockは固定の所属先ではなく、予約可能なサービス資源である。破壊・撤去時は、駐機、帰還、Queue、Holdingの依存状態を保持して再予約する。新設Dockはキャッシュ更新を待たず即座に候補へ追加する。

着艦済みフラグと実際の接点が一致しない場合、補給済みとして扱わず、`ALIGNING SERVICE CONTACT`を表示して最終進入をやり直す。

## 10. 完了条件

UI変更は次を満たして完了とする。

- 1920×1080と小さいGUIスケールで文字が読める。
- 通常時に照準周辺を遮らない。
- 100機、複数Wing、複数戦線でも表示が切り替わり続けない。
- 出撃できない機体について、原因を1画面で説明できる。
- Dock破壊、新設、再予約、着艦、補給、任務復帰が連続して表示される。
- 色覚だけに依存せず、状態名と数値が併記される。
