## 階層と対象

主ナビは「作戦 / 部隊 / 基地・補給 / 履歴 / 設定」の5つを維持する。「基地・補給 > 母艦」から対象船の専用Menuを開き、外装・船内コンソールから開いても同じ船UUIDへ固定する。6番目の主ナビを増やさない。

専用画面の下位ビューは「運用 / 貨物 / ベイ / 乗艦権限」。通常幅の図は主要情報を並置した運用ビュー。狭幅では右側のビュー選択メニューで詳細を切り替える。母艦ID、所有者/訪問者、最新の停止理由、緊急停止を切替領域の外に残す。長いIDは詳細で全文確認でき、異なる船を暗黙に切り替えない。

Dashboard側の機体・Wing選択は戻るまで保持するが、その選択への命令ボタンを母艦操作に流用しない。専用Menuでは機体選択サマリーに代えて船の対象帯を置く。小画面では上位5ナビを専用Menu内へ無理に押し込まず、閉じると元の基地・補給の文脈へ戻す。

## 実インベントリ90枠

`AbstractContainerScreen<CarrierMenu>`相当の画面を承認後に接続する。アイテムはバニラのSlot同期に従い、独自転送packetや装飾枠で代用しない。

| 区分 | Menu Slot | 左上座標 | 行・間隔 |
| --- | --- | --- | --- |
| 母艦貨物 | 0-53 | x=8、y=18 | 9列×6行、18px |
| プレイヤー所持品 | 54-80 | x=8、y=140 | 9列×3行、18px |
| ホットバー | 81-89 | x=8、y=198 | 9列×1行、18px |

全枠を同じ原点に置き、スクロールで枠を隠したり、詳細ビューで別座標へ移動したりしない。標準パネルの寸法案は176×222。Shift移動、右クリック分割、ドラッグ配分、数字キー交換、カーソル保持、ツールチップ、閉じる際の扱いはMenuとバニラに委譲する。

貨物の出入れは所有者のみ。訪問者は貨物を閲覧できても操作できず、その理由を示す。訪問者の自分の所持品操作まで独自に禁止せず、`CarrierMenu`の権限を正とする。貨物の試作配置を「燃料専用枠」等に変えない。飛行/兵装の補充命令は所持品から消費するため、貨物内の同種アイテム数だけで補充可能と断定しない。

## 表示と同期

`menu.view()`を読み、`shipId`と`containerId`を固定する。`acceptView`は異なる船・Menuの更新を拒否する。Viewは初期受信後10tickごとに同期される。送信に初期Viewの`menu=-1`を使わない。

| 表示 | Viewの根拠 | 注意 |
| --- | --- | --- |
| 現在状態・停止理由 | mode / stop / destroyed / owner | 未知enumは不明表示。作業開始を許可しない |
| 確認中の対象 | previewMode / generation / dimension / chunkX/Z / minY/maxY / previewTicks | 現在modeとは別のプレビュー。世代が変われば古い確定を失効 |
| 採掘進捗 | cursor / total | total=0は進捗なし。0除算や100%完了を作らない |
| 航行 | moving / navigation.exterior / navigation.destination | 船内プレイヤーの座標を外装座標に使わない |
| 対生物照射 | navigation.combatTicks | 最大100tickの残時間。採掘進捗率と区別 |
| 飛行電力 | energy | 現試作容量100,000。兵装と合算しない |
| 兵装電力 | weaponEnergy | 現試作容量100,000。採掘・対生物・ベイ兵装給電で共有 |
| ベイ予約 | bayUsed / drones | 最大4。UUID配列の順番を物理ベイ番号にしない |
| 招待者 | guests | 所有者以外では非開示の空配列。0名とは断定しない |

`CarrierClientApi.send`は送信可能な場合だけ送るvoid API。呼出し直後に成功・着艦済み・給電済みへ変えず、次のViewと実Slot同期を待つ。未接続や更新不能なら理由付きで新規命令を抑止し、送れていないSTOPを成功表示しない。スクリーン側が独自の定期requestや船の保存状態を書き換えない。共通登録は親タスクが担当する。

## 採掘と対生物

モードは排他的に選ぶ。「採掘 16×16」はブロック破壊あり、「対生物」は地形破壊なしと明示する。色だけで区別しない。開画面、モード選択、範囲プレビューだけでは稼働しない。

1. 外装の属するチャンク内のx,zで`PREVIEW_MINING`または`PREVIEW_COMBAT`を送る。
2. 返ったViewの対象次元、チャンク、X/Z各16ブロック、Y下端/上端、世代、期限を確認欄に固定する。負座標も床除算に従う。例: chunk(3,-2)はX48..63、Z-32..-17。
3. 採掘は高さ両端を含む。例: Y-64..64は129層。世代の短縮表示だけを送らず、実UUIDを保持する。
4. 確定は表示したgenerationをそのまま`ACTIVATE`へ渡す。200tick以内、所有者・距離・読込の再検証はサーバーに委譲する。期限切れ、別世代、船変更、通信断では確定不可とし再プレビューへ戻す。
5. `RESUME_PREVIEW`は保存範囲・cursorの再確認だけ。再度の明示的ACTIVATEが必要。満杯、再読込、緊急停止から自動再開しない。

プレビューの「取消」はローカル確認を閉じて古い確定参照を捨てるだけ。中断を表す`STOP`と同一視しない。Viewに古いpreviewが残っていても取消後に開始ボタンを自動復活させない。確認は同じgenerationとpreviewModeに対して成立する。

対生物は最大100tickの照射で、採掘のブロック進捗ゲージを再利用しない。稼働状態を表示したまま新プレビューを開く場合も、現在の稼働modeと確認中modeを両方判別できるようにする。保護を回避できる操作は設けない。

## 操作対応

すべて`CarrierCommandPayload(menu.containerId, menu.shipId, action, generation, x, y, z, guest)`を通す。未使用UUIDは`NONE`、未使用座標は0。enumを任意の文字列命令へ変換しない。

| 操作 | action | 条件・確認 |
| --- | --- | --- |
| 採掘範囲確認 / 対生物確認 | PREVIEW_MINING / PREVIEW_COMBAT | 外装所属チャンク、新世代、未稼働の確認状態 |
| 範囲を確認して開始 | ACTIVATE | 表示世代と期限、破壊有無を確認 |
| 保存地点を再確認 | RESUME_PREVIEW | 保存進捗を再提示後に明示確定 |
| 緊急停止 | STOP | 所有者のみ、確認なし、通常命令の間隔待ちなし |
| 乗艦 / 安全下船 | BOARD / EXIT | 所有者・招待者。安全地点なしの拒否を保持 |
| 航行点を指定 | MOVE | 絶対x/y/z、現位置から128以内、読込済み・安全空域。無限航路は提案しない |
| 燃料補充 | REFUEL | 所持power_cell 1個で飛行電力1,000 |
| 兵装電力を充填 | CHARGE_WEAPON | 所持laser_cell 1個で兵装電力1,000 |
| 招待 / 招待解除 | ALLOW_GUEST / REVOKE_GUEST | guest=プレイヤーUUID、最大32。安全退出不能な搭乗者の即時剥奪は不可 |
| 残された船内へ | RECOVER_CABIN | 破壊済み船の所有者のみ。破壊前の作業再開ではない |
| 機体を予約 / 予約解除 | RESERVE_BAY / RELEASE_BAY | guest=ドローンUUID。招待者選択と異なる対象ピッカー |

航行指定ダイアログでは対象船、外装現在地、行先、取消を常設する。地図を併用する場合も「母艦の航行先指定中」を明示し、機体Waypointモードと共有しない。指定やクリックだけではMOVEを送らない。

## ベイ・権限・停止

ベイは4機までの一時サービス予約として表示する。現ViewはドローンUUID一覧のみで、物理ベイ位置や個別の接近/充填/完了フェーズは含まない。図の「予約1-4」は一覧の行番号で、実ベイ0-3への割当を意味しない。個別情報が未取得なら「個別進捗未取得」とし、100%や完了を捏造しない。名前・役割は一致する既存クライアント状態から取得できる場合のみ表示し、それ以外はUUIDにする。

所属Dock、恒久Wing、元任務を維持する。未接続DronePortは予約成功にしない。予約解除後の任務復帰もサーバー状態を待つ。再読込後の保存予約は失効し、自動出撃・自動再予約しない。

緊急停止は通常幅の下端固定帯、小画面の右下固定領域に置き、貨物・ベイ・招待者一覧のスクロールから独立させる。確認ダイアログが入力を占有する場合はその内部にも同じSTOP操作を置く。二重確認、長押し、5tickの通常操作制限で遅らせない。訪問者には停止状態と所有者限定の理由を示すが、STOP送信権限を付与しない。

停止理由はREADY/PREVIEW/RUNNING/EMERGENCY/RELOAD/OWNER_ABSENT/FULL/PROTECTED/UNLOADED/OBSTRUCTED/NO_POWER/COMPLETE/DESTROYED/EXPIRED/FRIENDLY_IN_AREA/LEASE_LIMIT/NO_SAFE_EXITを漏れなく区別する。特に満杯、保護対象、範囲内の友軍、安全下船地点なし、読込枠不足を単なる「停止」に潰さない。原因解消は自動再起動の許可を意味しない。

## 小画面と未解決条件

320×240論理GUIでは左176pxに固定90枠、右144pxに母艦文脈と切替式の操作を置く。停止ボタン案は(x182,y216)-(x312,y237)で、枠と重ならない。本文は論理9pxを基準とし、図は3倍文字を用いるがMinecraftフォントの可読性は未検証。項目が増えたら右側詳細をスクロールし、全体縮小や小文字化で押し込まない。

**320×180では、y198のホットバーを含む固定90枠を全表示できない。** 座標維持・全枠同時表示・高さ180の3条件は同時には満たせない。この案は320×180の合格を主張しない。承認後の実機確認で実効GUI寸法を測り、必要解像度/GUI倍率の案内か、別途承認された条件変更を親と決める。設定を自動変更しない。誤操作を避けるため、成立しない寸法で在庫枠を別位置に見せかけない。

## 承認後の確認

- 90枠の番号、座標、通常転送、Shift移動、分割、ドラッグ、ホットバー交換と訪問者の貨物拒否。
- 船内/外装から同じ船を開くこと、menu=-1を送らないこと、別船更新の破棄。
- 負チャンク、上下端、世代変更、期限切れ、取消、再プレビュー、採掘/対生物の誤確定防止。
- すべての下位ビューとモーダルからのSTOP、連続操作中でも停止できること、拒否を成功表示しないこと。
- 飛行と兵装の別消費、所持品と貨物の区別、4予約上限、再読込後の予約失効、Wing/Dock/任務の維持。
- 通常乗下船、安全下船失敗、破壊後復旧、招待解除の安全条件、通信断・更新遅延。
- 320×240を含む実効解像度とGUI倍率、長い日本語、ツールチップ、カーソル保持、クリック領域、文字や停止帯の重なり。

上記は未実施。PNGの目視と座標試験は実Slot・クリック・転送・描画の検証を代替しない。母艦runtime画面の実装ファイルと共通登録は、視覚承認後に親が担当境界を確定する。
