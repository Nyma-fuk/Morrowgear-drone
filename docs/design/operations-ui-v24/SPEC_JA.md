## 選択と対象

主ナビの直下に選択サマリーを常設する。選択機数、完全Wing数、部分Wing数、未所属数、フィルターで隠れた対象数を示す。小画面では選択機数・接続状態・詳細ボタンを残し、詳細に全対象を表示する。

- 主ナビ、下位ビュー、並び順、フィルター、ページ移動で選択IDを消さない。
- 消失・権限変更・次元変更で無効となった対象は既存の再検証規則に従う。別機体を自動選択して同じ命令を継続しない。
- 単機、Wing、全機を区別する。全機はロールフィルターの表示行だけを意味しない。
- Ctrl追加・解除、Shift範囲選択、明示的選択トグル、先頭・前頁・次頁・末尾を残す。
- Wing行の所属判定はフィルター前の全メンバー集合で行う。未所属機を暗黙の1Wingにまとめない。
- 恒久Wingは最大8機。9機目は理由付き拒否。Task Forceや戦線集約によって`groupId`、Wing境界を変更しない。
- ドラッグによるWing作成・編入・解除に加えて、キーボードから選べる明示的な編入・解除操作も残す。HTML提案ではメニュー操作のみを示し、ドラッグは未実装。

## 地図の対象指定

通常は「閲覧中」。地図のダブルクリックだけで暗黙の命令を送らない。命令を選ぶと、命令種別・対象機数・半径・現在指定値を含む対象指定帯を出す。取消ボタンを常設する。

1. 命令を選び、対象ID集合と命令種別を固定する。
2. 地点・追跡対象・巡回点を指定する。クリックは草稿だけを変更する。
3. 「確定」で既存送信処理へ渡す。選択・所有権・次元・通信・対象を再検証する。
4. 成功・取消・別命令・対象変更・ページ移動・画面終了で対象指定を解除する。

Escはまず対象指定を取り消す。確認ダイアログが開いている場合はダイアログを閉じる。取消後のクリックから古い草稿を再送しない。巡回指定中はWaypoint/Field/Guard送信を同時に行わない。確定時に無効な対象だけを黙って除いて成功扱いにせず、受付結果と除外理由を示す。

地図の投影計算、実座標からの逆変換、zoom、地形DynamicTextureの破棄、地形・Entity・Dock・コンテナの既存キャッシュを維持する。PNG/HTMLの地形座標は配置用サンプルで、ゲーム座標変換の検証資料ではない。

## Dockの実インベントリ

`DockScreen`は`AbstractContainerScreen<DockMenu>`相当の既存コンテナ画面として実装する。装飾ボタンをスロットに見立てる方式を使わない。Shift移動、右クリック分割、ドラッグ配分、ホットバー交換、カーソル保持、アイテムのツールチップ、サーバー再同期、閉じたときの戻しはバニラとDockMenuに委譲する。

### 枠と座標

| Menu slot | 意味 | Menu内の相対座標 |
| --- | --- | --- |
| 0 / 1 / 2 / 3 | 機体 / 装着電池 / 役割 / 兵装 | `8 + slot % 9 * 18`, `18 + slot / 9 * 18` |
| 4 / 5 / 6 | 燃料 / 整備 / 弾薬・兵装電力 | 同上 |
| 7 / 8 | 単体回収出力 / Dock蓄電池 | 同上 |
| 9-17 | 回収出力バッファ9枠、挿入不可 | 同上 |
| 18-26 | 共通補給バッファ9枠 | 同上 |
| 27-53 | プレイヤー所持品27枠 | x=8開始、y=85開始、18pxピッチ |
| 54-62 | ホットバー9枠 | x=8開始、y=143、18pxピッチ |

計27+36枠。番号も個数も変えない。小画面でも9列を保ち、インベントリそのものをスクロールで隠さない。第一段の短ラベルは機体・電池・役割・兵装・燃料・整備・弾薬・出力・蓄電とし、完全名・受入条件はツールチップと詳細に置く。別担当の`DockMenu`や`DockBlockEntity`を書き換えて画面都合に合わせない。

HTMLの27枠は操作感を示すローカル模型で、実Slotではない。左クリック移動、右クリック分割、投入不可表示だけを試作。完全なバニラインベントリ操作、Shift移動、ドラッグ配分はMinecraft実装で検証する。PNGは拡大配置図であり、実スロットの18pxピッチ図ではない。

### 確定済み同期API

`DockMenu.TYPE`、`register()`、クライアントctor `(int, Inventory)`、`value(field)`、`supplyCount(kind)`、`available(kind)`、`shortage(kind)`を使用。クライアントctorは`SimpleContainer(27)`と`SimpleContainerData(40)`。`value`で復元済みの32bit整数を使い、生の16bit片を直接表示しない。

| field | 値 |
| --- | --- |
| 0 / 1 / 2 | FLIGHT_POWER / FLIGHT_CAPACITY / FUEL_CREDIT |
| 3 / 4 / 5 / 6 | WEAPON_POWER / WEAPON_CAPACITY / GUN_CREDIT / MISSILE_CREDIT |
| 7-11 | STOCK_START + SupplyKind.index() |
| 12 / 13 | AVAILABLE_MASK / SHORTAGE_MASK |
| 14 / 15 | DRONE_ID / READINESS |
| 16 / 17 / 18 / 19 | DRONE_FLIGHT_PERCENT / DRONE_WEAPON_PERCENT / DRONE_GUN_ROUNDS / DRONE_MISSILES |

SupplyKindはFUEL/GUN/LASER/MISSILE/REPAIR。配列ordinalを推定せず`index()`と`mask()`を使用。READINESSはEMPTY=0、SERVICING=1、READY=2、BLOCKED=3。DRONE_ID=-1は空きであり、Entity検索に失敗したときも未知と空きを混同しない。

「空き」「整備中」「準備完了」「出撃保留」と不足資源を分離して示す。SHORTAGE_MASKを理由の正とし、容量0の除算・在庫個数を電力量として表示する誤りを避ける。サーバーが理由を供給していない故障・経路閉塞を推測しない。系統状態やDock名・位置・容量上限などMenuにない情報は安全に関連づけられた既存データがある場合のみ補足し、なければ「未取得」。

補給品は`autocannon_magazine`=120発、`laser_cell`=1,000兵装電力、`micro_missile_pack`=5発、各最大スタック16。パック在庫数・開封済み残量・機体搭載量を別値にする。燃料とレーザー電力を同じ残量ゲージにしない。Slot 6は3種の兵装補給を受ける。出力7/9-17は持ち出しのみ。入力の可否とスタック数は`DockSupplyPolicy`/`Slot`を正とする。

登録と画面の結線は親タスクが`MorrowgearDroneClient`へ行う。UI担当は`DockScreen`の提供だけを行い、共通登録・ネットワーク・アイテム・言語を変更しない。

## 補給網と母艦

補給網は「供給元」「要求」「予約」「配送中」「不足理由」を同じ一覧行で示す。利用可能数と総在庫を混同しない。要求数と優先度は確定前に対象Dock・供給元・資源を明示する。取消、通信断、供給元消失、古い更新、権限不足、空、読込、受付拒否を区別する。Supply APIは親からの確定契約に合わせ、画面側が登録台帳や在庫を直接書き換えない。未接続時は「未接続」とし成功を捏造しない。

### 受領済みSupply API

- `SupplyNetworkClient.register()`は親が接続済み。UIで重複登録しない。
- `request()`は補給ビューが開いている間のtickからのみ呼ぶ。内部で1,200msに制限。毎描画フレーム・通常プレイ中・HUD常設更新からは呼ばない。
- `docks()`、`dock(long)`が返す`DockStatus`の`source`、`dock`、`enabled`、`status`、`stock`、`deliveries`を利用する。
- `Stock.rule()`のkind/minimum/priority、available/incoming/missingは別列。available/missingの`-1`は未知として表示する。総在庫や予約数がこのAPIにない場合、availableから逆算して表示しない。
- `Delivery`はdrone UUID、kind、remaining、statusを持つ。通信イベントのUUIDやEntityの数値IDと混同しない。
- スナップショットは所有者・次元・要求番号を検証済みで、5秒で失効する。現APIは未取得・失効・本当に0件のいずれも空リストになり得るため、UIだけで「登録なし」と断定せず「データなし / 更新待ち」とする。失敗理由を推定しない。
- 設定送信は`new SupplyNetworkConfigPayload(source.asLong(), dock.asLong(), enabled, rules)`。5種それぞれ1Ruleが必要で、`SupplyNetworkPolicy.defaults()`を初期値にする。最低在庫0-576、優先度0-100。初期値の列順とwire順を同じものと仮定せずkindで対応させる。
- 初期値はFUEL 16/100、REPAIR 8/90、GUN 8/80、LASER 8/70、MISSILE 4/60（最低在庫/優先度）。単なる一回の「32個発注」として設定送信しない。HTMLの単品要求ダイアログは初期概念案であり、**承認後に5種の最低在庫・優先度を編集する経路設定へ接続**する。
- 供給元設定はプレイヤーが倉庫の近くにいること、所有Dockであること、経路長256以内が条件。倉庫・Dockの座標と有効/停止、全5Ruleを確認して確定する。サーバー応答前の成功表示はしない。現行拒否通知はサーバーのメッセージ経由であり、構造化ACKを捏造しない。
- DISABLED/READY/IN_TRANSIT/RECHARGING/WAIT_CHUNK/NO_IDLE_CARGO/SOURCE_SHORTAGE/SOURCE_LOST/DOCK_LOST/DOCK_FULL/RESERVATION_INVALID/ASSIGNMENT_LOST/CARGO_MISMATCH/CANCELLED/LOAD_RETAINED/RUNTIME_UNAVAILABLE/ACCESS_DENIED/CAPACITY_LIMITを、状態と対応理由へ漏れなく割り当てる。

母艦は同じ主ナビ内の下位ビューとする。航路、採掘範囲、進捗、内部収納、電力、兵装、搭載機、サービスベイ、乗艦権限、緊急停止の区分を確保する。まだAPIのない項目は未取得表示・実行不可。既存小型機を母艦に見立てた新モデルは作らない。

母艦の所有権・サービス予約・帰属Dock・恒久Wing・一時Task Forceは別物。帰投先の変更でWingを再編成しない。掘削・照射は別モード、範囲・危険・資源・対象の確認を経て開始し、画面を開いただけでは開始しない。移動中ベイ、保護地域、収納満杯、船消失時の退避はサーバーが決める。

### 受領済み母艦メタデータ

`carrier.CarrierMenu`と`CarrierViewPayload`を読み取り確認済み。実行時のコンソールビューは承認後に別途接続する。`CarrierMenu.view()`、`shipId`とmenu IDで現在の母艦を固定し、`acceptView`により異なる船・メニューの更新を採用しない。貨物Slotと所有者権限はMenuを正とする。

Viewはowner/destroyed/mode/stop/generation/dimension、対象chunkX/chunkZ/minY/maxY、cursor/total、energy/weaponEnergy、bayUsed、previewTicks、guests/drones、moving、previewMode、navigationを含む。`navigation.exterior()`は船内から見た外装座標、`destination()`は航行先、`combatTicks()`は対生物照射の残時間。現在modeと確認中previewModeを混同しない。total=0では進捗率を除算しない。

実`CarrierCommandPayload`と`CarrierClientApi`、[バックエンド契約](../CARRIER_BACKEND_INTEGRATION.md)を確認済み。初期Viewのmenu=-1を送信せず、`menu.containerId`と`menu.shipId`を使う。採掘16×16の範囲・世代・期限を提示してから確定し、対生物モードでは地形を壊さないことを明示する。緊急停止は全下位ビュー・確認ダイアログで到達可能とし、所有者のSTOP送信を確認操作や通常命令の間隔制限で遅らせない。詳細は[母艦UI仕様](CARRIER_UI_JA.md)を正とする。画面都合でCarrierMenuを編集しない。

## 通信・履歴の結線

UI担当は`Operation*`ファイルを編集しない。確定済みの次のアクセサを参照する。

- `OperationCommunicationsClient.history()`: 新しい順の不変履歴。最新128件、所有者境界を維持する。
- `subtitle()`: 現在の一時字幕。過去履歴を順番に読み上げるためには使わない。
- `queuedCount()`: 最大8件の待機数。HUDへ複数の文章を増やさない。
- `setSelectedContext(Predicate<OperationEvent>)`: 選択Wing・注目機との関連を伝える。画面破棄・切断時に古い参照を保持しない。
- `OperationEvent.messageKey()`と`messageArgs()`を`Component.translatable`へ渡す。任意名と翻訳キーを直結して別のキーを作らない。
- sourceUnit/wing/sourceName/voiceNumber/count/dimension/座標/occurredAtMillis/kindを詳細に使う。集約件数は変化が確認できた機数であり「Wing全機」の意味ではない。

履歴は主ナビから常時利用し、検索・種別・対象による絞り込みと全詳細への到達性を持つ。再接続snapshotは過去履歴として復元し、現在通知・音声を再発火させない。画面側に別の永続履歴ストアを作らない。

親の最新要求は「字幕・履歴を常時利用でき、音声ON/OFF・独立音量」。音声は専用OS標準Narratorを親が所有し、MinecraftアクセシビリティNarratorと共有しない。UIは音声を再生しない。音声利用不可でも字幕・履歴を利用可能とする。

現行`OperationRadioSettings`はOFF/IMPORTANT/STANDARD、既定IMPORTANT、音量0.7、subtitles=true。ON/OFFは既存モードを消さず、OFF→ONで直前の有効モードへ戻す。IMPORTANT/STANDARDは副設定で保持する案。字幕設定の既存falseと「常時利用」の扱いは親の確定指示待ちであり、UIだけで既存値を勝手に上書きしない。

## 最小HUD

常設は集約戦線・交戦機数・要対応件数の短い帯。右側は注視または固定した1機だけ。下側は最優先の文章1件だけ。詳細対象の自動巡回、時間によるWing切替、機体ごとの通知大量列挙を行わない。

- 通知優先度: 電力喪失・危険 > 作戦停止・防衛 > 選択部隊の開始・復帰 > 通常開始 > 完了。
- 同順位は安定順で保持。危険割込は許すが、毎フレームの並び替えで文章を点滅させない。
- 重大な持続警告と一時通信字幕は1つの表示枠で調停する。履歴の古い警告を無条件に永続再表示せず、現在有効な状態と照合する。
- 1件の文章が長い場合は最大2行。発信元と原因を保持し、全文と座標は履歴詳細へ。
- 通常完了のHUD通知は既定OFF。履歴収録まで消さない。
- 注視の既存12tick滞留、ピン固定、近接距離0/24/48/96、視線遮蔽、遠近投影、offscreen方向、照準safe zone、クラスタのヒステリシスと描画予算を維持する。
- 100機では機体ラベルを100個出さず、Wing/戦線集約と例外優先。1/8/9/32/33/100/128/129機の密度境界に回帰試験を置く。
- 注目機の飛行電力、兵装電力、弾数、系統、所属、現在状態、任務、リンクを詳細に保持。小画面は情報量を段階的に畳み、注目機を別の機体へ自動切替しない。

## 小画面・GUI倍率

物理解像度とMinecraft論理GUI座標を区別する。最低論理幅320を対象にする。320×180は既存Policy試験の厳しい下限ケース、320×240も別途確認する。GUI倍率を変えてもヒット領域と描画の座標変換は1箇所で整合させる。

| 条件 | 配置方針 |
| --- | --- |
| 幅960以上かつ十分な高さ | 一覧・地図・命令の3区画 |
| 幅640-959 | 地図を主とし、一覧・命令を切替。情報を縮小して詰めない |
| 幅320-639 | 5主ナビ、選択機数、下位ビューを保持。一覧・地図・命令は1面ずつ |
| 高さ240以下 | ブランド補助語・副指標を畳む。下位ビュー/区画切替は同じ行またはメニューへ統合。内容領域の高さを確保 |
| Dock 320×180 | 18pxピッチの176×166インベントリを優先し、状態・不足理由は幅残部または独立詳細。枠を隠す縮小は禁止 |
| HUD 320×180 | 集約帯、注目ID、通知1件を優先。詳細ゲージはユーザー操作で開く |

Minecraftフォントは整数画素整合を守り、全画面を960×540から一律縮小して読めなくする方式を改める。省略はID・長い名称に限り、ツールチップ/詳細で全文へ到達可能とする。状態や実行不可理由は重要語を隠さない。本文サイズを下げて列数を保たない。

HTMLは14px本文・12px補助文字の固定サイズ。固定高さの領域ごとにスクロールし、選択帯を内容と一緒に流さない。ただし最小320×180での実表示、低高さ時の切替統合、Dockと状態詳細の同時表示は**未検証・要調整**。PNGからこの条件の合格を主張しない。

## 承認後の受入試験

1. 既存8画面からの機能到達表を5主ナビと全下位ビューで照合。従来命令IDと送信条件を確認。
2. 空/単機/8/9/32/33/100/128/129機、フィルター外選択、部分Wing、全機、削除・切断・次元変更、Ctrl/Shift、確認期限を確認。
3. 閲覧時の誤送信なし、対象指定→取消→再指定、別命令への移行、巡回8地点、選択変更、無効対象、再送防止。
4. Dock実63Slotの通常クリック・分割・Shift・ドラッグ・ホットバー・満杯・投入不可・切断・閉じる・再接続。個数保存と32bit残量を確認。
5. 補給不足、予約競合、供給元消失、権限不足、古い同期、API未接続。未知を準備完了として見せない。
6. HUDの遮蔽、前後左右、照準、画面端、ピン消失、持続警告と一時字幕、100機同時イベント、音声OFF、完了OFF。
7. 320×180/320×240/640×360/854×480/960×540/1280×720/1920×1080とGUI倍率1/2/3/4/Autoの実到達条件を記録。無理な組合せは対象外理由を書く。
8. ユーザー承認された設計図との比較、低解像度原寸画像、クリック領域、文字欠け、文字重なり、キャッシュ更新、フレーム時間を通常Minecraft操作で確認。

既存テストの期待値を単に緩めて合格させない。8主タブ→5主タブや複数通知→単一通知に関する古い形状検査は、承認済み新仕様の全機能到達性・優先順位・失敗時挙動を検査するテストへ置き換える。ブラウザー、実ゲーム、音声の未確認をロジック試験のPASSに含めない。
