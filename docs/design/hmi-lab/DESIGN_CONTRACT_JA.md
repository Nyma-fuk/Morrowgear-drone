# Morrowgear 全画面HMI設計契約

更新: 2026-09-24。全画面移植の設計基準。利用者による「ＯＫこれで全画面を作り直して」の承認に基づいて移植を進める。承認と実装完了・検証完了は区別する。

|成果物|役割|限界|
|---|---|---|

|design-review.html|全36画面・操作状態の目的、データ、操作、例外、戻り先、受入条件|仕様一覧。全状態の実動作再現ではない|
|visor-worn.html|実ゲーム画像上で6状況を比較する装着時案|位置は仮配置。3D投影、遮蔽、実FPSは未検証|

ゲーム側の変更は承認範囲に沿って行う。仕様網羅、操作試作の網羅、実装網羅、試験網羅は別に記録する。移植中の差分と検証結果は `docs/verification/2026-09-24-hmi-salvage-integration.md` に記録する。

## 2. 基本構成と役割

コントローラーは「指示する画面」、バイザーは「状況に気づく表示」、現地Dockは「物を入れ、補給を確認する画面」、母艦は「大規模作業と船内を管理する画面」とする。全機能をバイザーへ詰め込まない。

コントローラーの固定ナビゲーションは作戦地図、Wing編成、任務、Dock・補給、補給網、機体回収、母艦、バイザー、機器、報告履歴、設定。詳細から地図へ戻ると選択UUID、スクロール、中心、拡大率を復元する。

作戦地図では左に対象一覧、中央に地形と目的地、右に選択詳細と命令を置く。複数選択時は1機の詳細ではなく「選択対象の共通情報・相違・実行可能数」に切り替える。右欄を開いても選択対象が隠れた場合は地図を必要最小限だけ移動する。

## 3. 情報の意味

|項目|意味と表示規則|禁止事項|
|---|---|---|
|正式Wing|ユーザーが編成した所属。任務中も所属は保持|一時戦闘群を所属として上書き|
|一時戦闘群|同一目標に対する臨時の共同攻撃|Wingカードへの自動移籍|
|任務|復帰可能な目的。巡回、採掘など|現在行動と同一視|
|現在行動|充電へ帰還、射撃位置へ移動など|任務を上書きして表示|
|飛行電力|飛行用エネルギーの現在量/容量|武器と合算|
|機関砲・ミサイル|個別残弾/搭載上限|両方をWeapon%に合算|
|レーザー|使用可能な蓄電量/容量と熱状態|冷却中を弾薬不足と表示|
|機体・システム|耐久、損傷・故障状態|電力不足と故障を混同|
|Dock資源|実在庫と処理中、予約分、供給可能量|空き枠があるだけで補給可能と表示|
|受信鮮度|最後に受信した時刻と現在との差|通信断をHP0・破壊と決めつける|
|出撃阻害理由|現行判定の具体的な条件・不足量|UI独自の閾値で可否を決める|

未知の値は「不明」、未受信は「未受信」、無限期間の任務は「継続中」。0%、完了、待機で代用しない。名称変更後も同一UUIDを参照する。別次元、権限外、未受信はそれぞれ区別する。

## 4. 命令の契約

1. 対象集合をUUIDで確定する。ソートやフィルターで集合は変えない。「表示対象を選択」と「全機」を別操作にする。
2. 下書きはローカル編集であり、現行任務を変えない。地点、範囲、経路、対応役割を確認できるようにする。
3. 確認には対象数、実行範囲、次元、地形変更の有無を出す。対象/範囲/revisionが変わったら確認を失効させる。
4. 送信中、受付済み、拒否、実行中、完了、結果未確認を区別する。送信できたことを任務成功として扱わない。
5. 部分拒否は受付機と拒否機を分離し、拒否理由を表示する。再送は拒否機のみ。危険操作はタイムアウトで自動再送しない。
6. 画面を閉じても命令IDで履歴へ追跡可能にする。取消は下書きを消す操作。既存任務の停止には別の明示操作を使う。

Wing移籍は元・先の構成revisionと定員を検査し、8機超なら変更全体を拒否する。D&D以外に選択式の移籍も用意する。正式所属と一時離脱を同時に表示するため、戦闘や充電で一覧の機体が消えたように見えない。

## 5. バイザーの判断規則

背景を覆う大型の常設パネルは置かない。左上に艦隊と作戦の要約、右上に注視/固定した1対象、左下寄りに緊急通知。中央40%×40%は詳細パネル禁止領域とし、下端19%は標準HUDと手持ち表示を優先する。実際の画面占有率は移植時にMinecraftのGUI倍率ごとに再検査する。

|優先度|条件|表示|解除条件|
|---|---|---|---|
|P0|プレイヤー直近の危機、電力喪失・回収不能|緊急通知1行＋残り件数|解消/確認後は履歴に残す。継続中なら件数は残す|
|P1|ユーザーが固定した対象|詳細1対象。未知値もそのまま表示|明示解除。対象消失時は理由を残し別対象へ勝手に切り替えない|
|P2|注視対象|250ms継続で詳細、外れて600msで閉じる|固定中は注視で上書きしない|
|P3|進行中作戦と変化|最大3作戦。残りは件数|同優先度の更新だけでは並び替えない|
|P4|正常機体の常時情報|近傍マーカー。ラベルは注視/選択対象中心|密集時は集約|

新しい緊急事象は即時反映。同順位は初回表示順を保つ。警報が解消しても最低3秒は行を保持してから除去し、重複イベントは同一原因IDでまとめる。固定対象はこの自動順位から除外する。

表示上限案: 通常マーカー5、詳細1、作戦3、緊急1。狭幅は通常マーカー2・作戦1に減らすが文字は縮小しない。画面外のLOSTは距離無制限の方向表示対象だが、全機の矢印を個別に並べず方向別に集約する。次元が異なる場合は方向矢印でなく次元名を表示する。

### マーカー投影と遮蔽

実装時は描画フレームの補間済み機体座標と、同フレームのカメラのview/projectionから画面位置を求める。2D座標だけを補間して機体を追いかけない。画面背面の点を前方として描かない。画面端は方向指示へ切り替える。遮蔽中の対象を見えている機体と同じマーカーにせず、破線・最終確認ラベル等で区別する。

文字の重なりは優先順位で抑制し、位置の基準点まで変えない。遮蔽判定の間引きはマーカー位置更新とは別に設計する。専用シェーダーは発光表現の手段であり、投影誤りや情報選別を直す手段ではない。

複数戦線では戦線ID、場所、敵性数、味方参加数、増援不足を要約する。選択した戦線のみ「誰がどの敵を攻撃しているか」を展開。全戦線の関連線を同時に表示しない。HUDからコントローラーへ移る際は選択した戦線を引き継ぐ。

## 6. 補給・回収・母艦

Dock画面は上部に駐機機と不足理由、中央に補給在庫とプレイヤー在庫、側部に入出力と待機列を置く。ゲージには単位、実値、容量を伴わせる。27スロットの実メニューを前提とするが、スロット番号と種別は実メニュー定義の監査で確定し、絵に合わせて変更しない。

在庫操作は通常クリック、右クリック分割、Shift移送、カーソル保持、満杯時の戻し、画面終了、切断まで含める。ブラウザー試作の「補給」ボタンはこのネイティブ在庫操作の代用ではない。遠隔詳細は閲覧用とし、許可なく現地在庫へアクセスできる設計にしない。

補給網は出発地→目的地→品目→最低在庫→優先度→確認の流れ。配送中の資源を両拠点に二重計上しない。拠点喪失は配送中断理由と再搬送先を表示する。

回収は発見→手配→接近→吊り上げ→搬送→補給/修復→任務復帰。回収機の任務と被回収機の任務を分離する。元任務がなくなったら現行フォールバックの結果を表示する。Dock喪失時に機体を消す挙動は受入不可。

母艦は概要、掘削、攻撃、移動、倉庫、補給、船内、診断。掘削では16×16の対象チャンクを地図で選択し、次元・座標・上限/下限・保護領域・収納余力を確認する。未観測範囲を掘削可能と断定しない。予告/走査/充填/降下/掘削/回収/完了を区別する。

攻撃は対象と範囲、味方や建造物への影響を先に表示する。操作名は「攻撃を指示」であり、送信直後に「攻撃成功」にしない。船内は承認済みの専用空間とし、入退艦・権限・退避先・母艦消失時の救済を別項目にする。未確定の救済手順は実装前の必須判断事項とする。

## 7. 見た目と可読性

基本色: 背景 #121514、面 #1a1e1c、区切り #343c36、本文 #e1e7e0、補助 #99a59d、選択 #7cdec8、正常 #a5d391、注意 #e7bd79、危険 #f28d83。色だけで意味を伝えず、語・アイコン・形を併用する。

ブラウザーの本文基準は14px、補助12px。文字サイズをウィンドウ幅に比例して縮めない。Minecraftへ移す際は最終表示ピクセルで可読性を評価し、GUI倍率によって以前のように字形が潰れないことを確認する。HTMLとMinecraftのフォントは同じではないので、同一見た目の達成をコード上の寸法一致だけで判定しない。

980px以下では詳細を切替パネルに、650px以下では一覧/地図/詳細を単独表示にする。命令の対象数と主要操作は保持する。ホバーに頼る説明にはフォーカス時の表示も用意する。アイコンは既存体系を継承し、意味が曖昧な命令は短い日本語名を併記する。

常設の全面Blurや常時アニメーションは採用しない。既存のFPS問題を増やさず、半透明背景と細い境界を基準にする。通知アニメーションは移動量を小さくし、無効化可能とする。

## 8. 全画面の検証と承認ゲート

全36項目をdesign-catalog.jsのIDで追跡する。8つの共通状態は観点の候補であって、36×8をそのまま有効な試験数と称しない。

|状態|適用先|確認事項|
|---|---|---|
|通常・対象なし|一覧、詳細、地図、HUD|0件と未受信、対象なしでの命令無効化|
|受付待ち・一部拒否|送信を伴う命令画面|二重送信、個体別結果、拒否機のみ再選択|
|鮮度低下・消失|サーバー状態を参照する画面|現在位置との区別、権限、同名別UUIDへの誤接続|
|実行不可|条件付き操作|具体的条件、数量、解決できる移動先|
|100機・狭幅|一覧、地図、Wing、HUD、履歴|固定対象、文字サイズ、重なり、表示外選択|

数値条件は0/1/8/32/100機、0/1/4戦線、0/1/複数Dock、資源0/不足/充足/不明。表示条件は1920×1080、1280×720、狭幅、昼/夜、GUI倍率全選択肢。操作はマウス、キーボード、D&Dの代替、Esc、未保存、二重クリック、タブ変更、再接続を含む。

移植に進む前に必ず以下を完了する。

1. 36仕様の未決事項と実コードの対応表を埋める。既存情報で不足なら同期項目を明記する。
2. ネイティブ在庫、母艦喪失時退避、狭幅切替など現在の試作で未再現の操作を試作または明示的な画面遷移図でレビューする。
3. 装着時案と全体導線をユーザーが確認する。未承認のものを承認済みにしない。
4. 自動試験と目視試験を別記録にする。DOMテンプレート試験をブラウザー操作試験、ゲーム内試験と言い換えない。
5. 移植後は専用ワールドで通常操作から送信、受理、実機行動、復帰まで確認する。実画面と承認案を同じ寸法で比較する。

現時点ではローカルページのブラウザー自動表示が制限されているため、新規ページの実ブラウザー目視確認は未完了。ゲームへの反映・起動は行っていない。
