# 基準画像から高品質な3Dモデルを再現する標準手順

**対象:** Morrowgearのドローン、Dock、ツール、装置など、画像を基に立体モデルを制作する作業  
**基準事例:** Family A Scout V2  
**更新日:** 2026-08-22

## 1. 目的

コンセプト画像の雰囲気だけを模倣するのではなく、画像内の形状、比率、部品、接続、可動状態、素材、発光を分析し、正面・後面・上面・底面・左右側面で矛盾しない3Dモデルへ変換する。

この手順では、斜視レンダーが格好よいことだけを完成条件にしない。単一のメッシュから出力した全周画像が、基準画像の各方向と整合することを完成条件とする。

## 2. 今回の作業で品質を上げた重要な観点

### 2.1 画像を一枚の絵ではなく部品表として読む

最初に次の情報へ分解する。

- 中央構造と外周構造
- 固定部品、可動部品、発光部品
- 左右対称部品と意図的な非対称
- 部品同士の接続位置
- 前後、上下、機首方向
- 展開、格納、回転、停止などの状態
- 外装、内部機構、整備部、センサーの素材差

Scoutでは、中央艇体、左右ダクト翼、ローター、尾翼、脚、バイザー、顎部センサー、後部整備・冷却ユニット、後方灯火ポッドへ分解した。

### 2.2 識別要素を最優先する

機体をその機体らしく見せる要素を先に特定する。Scoutでは次の順序だった。

1. 左右2基の角張ったダクテッドローター
2. 機首先端から側面へ回り込むシアンのバイザー
3. 低い中央艇体
4. 後傾した尾翼
5. 細い関節脚と前後方向のスキッド
6. 後部整備・冷却ユニット

小さな傷やボルトを先に追加しても、これらの形状が違えば同じ機体には見えない。

### 2.3 部品の「有無」だけでなく状態を定義する

部品ごとに次を記録する。

| 観点 | 例 |
|---|---|
| 固定・可動 | ローターは回転、尾翼は固定 |
| 通常・着艦 | 飛行時は回転、Dockでは停止 |
| 展開・格納 | 脚は今回の基準画像では展開状態 |
| 点灯・消灯 | バイザーと灯火は点灯、整備パネルは非発光 |
| 接続 | バイザーは前面から側面まで外板に沿って連続 |

状態を定義しないと、脚の向き、ローターの停止位置、灯火の配置などが視点ごとに変化する。

## 3. 基準画像の扱い

### 3.1 複数視点を優先する

利用可能なら最低限、次の視点を集める。

- 斜視
- 正面
- 後面
- 上面
- 底面
- 左側面
- 右側面

画像生成によるターンアラウンドは、視点ごとに部品数や向きが変わる場合がある。矛盾がある場合は次の順序で判断する。

1. 複数視点で共通して確認できる形状
2. 機能上成立する構造
3. ユーザーが明示した方向・状態
4. 斜視画像のデザイン意図
5. 不明部分は勝手に確定せず、暫定として記録

### 3.2 座標系を最初に固定する

Scout V2では次を使用した。

- `+X`: 機体右
- `-Y`: 前方
- `+Y`: 後方
- `+Z`: 上方
- 原点: 中央艇体の幾何中心

座標系はスクリプト、Blender、エクスポート、ゲーム内実装で統一する。

### 3.3 比率を測る

実寸がなくても、中央艇体最大幅など一つの寸法を`1.00`として相対値を定義できる。

最低限測る項目:

- 全幅、全長、全高
- 中央艇体の最大幅と最大高
- ローター中心間距離と開口径
- ダクト外径と開口径の比
- 機首からバイザー終端までの長さ
- 胴体下面から接地面までの距離
- 尾翼の高さ、後傾量、左右間隔
- 後面ユニットの幅と高さ

## 4. モデリング方式

### 4.1 Blenderのポリゴンメッシュを正とする

最終形状の正本は`.blend`とする。画像生成結果、Three.jsの簡易形状、Minecraft用の低ポリゴン変換物を正本にしない。

推奨用途:

| 手法 | 用途 |
|---|---|
| ロフトメッシュ | 断面が連続して変化する艇体 |
| 明示的なポリゴン輪郭 | 角張ったダクト翼、フェアリング |
| Mirror Modifier | 左右対称部品 |
| Boolean / 凹部メッシュ | 埋め込みセンサー、吸気口 |
| 薄いリボンメッシュ | 外板に沿うバイザーや発光線 |
| 独立メッシュ | ハッチ、ラッチ、灯火、脚、ローター |
| Bevel Modifier | 金属外装のエッジ |

箱を多数重ねただけのモデルは、面のつながりとシルエットが崩れやすい。中央艇体や翼は輪郭を定義したメッシュから作る。

### 4.2 左右対称は目視で作らない

- 世界原点に共通のミラー原点を置く。
- 片側だけを作り、反対側はMirror Modifierで生成する。
- 左右の寸法、材質、回転角を別々に入力しない。
- 傷や塗装剥離だけを非対称にしてよい。

### 4.3 埋め込み部品は外板との関係を作る

バイザーなどのセンサーは、発光線だけを置かない。

1. 外板上の黒い凹部またはベゼルを作る。
2. 凹部の内側へ細い発光面を置く。
3. 機首角をまたぐ場合は、前面と側面を連続させる。
4. 側面図で外板から浮いていないことを確認する。
5. 発光強度を下げても形状が読めるようにする。

### 4.4 脚は接地状態から逆算する

脚は「棒を斜めに置く」のではなく、次の順に定義する。

1. 接地面とスキッド方向
2. 接地点間隔
3. 下部ナックル
4. 支柱の角度と長さ
5. 上部ヒンジ
6. 胴体への接続位置

Scoutのスキッドは機体前後方向へ伸びる。正面では短い矩形、側面では長いバーに見える。この投影関係を各ビューで確認する。

### 4.5 後面も独立したデザイン面として作る

後面を一枚のグリルで済ませない。Scoutでは次の層を分離した。

1. 胴体後端
2. 外装ハウジング
3. 金属ベゼル
4. 奥まった整備面
5. 上部サービスパネル
6. 冷却ベント
7. 下部バンパー
8. 左右灯火ポッド

前面と同程度の情報密度を持たせる。ただし、前後を誤認するほど強い後方発光は使用しない。

## 5. マテリアルとディテール

### 5.1 素材の階層

- 主装甲: 中間グレーの低反射金属
- 暗色装甲: 機構部、凹部、底面
- エッジ合金: 外周やベゼルへ限定
- 整備色: 小面積のオレンジ
- 発光: バイザー、内周灯、灯火だけ

全体を黒くすると輪郭が消え、金属度を上げすぎると左右の照明差で片側だけ白くなる。色、metallic、roughness、照明を一緒に調整する。

### 5.2 ディテールを追加する順序

1. 外形
2. 大きな部品境界
3. 接続部
4. 凹部とベゼル
5. ハッチとパネル
6. ラッチと灯火
7. 摩耗、傷、ボルト

傷やノイズは最後に追加する。形状不足をテクスチャで隠さない。

## 6. 実施手順

### Phase 1: 解析

1. 元画像を正しいローカルパスで読み取る。
2. 各方向を切り出して拡大する。
3. 機首、後方、上下、左右を確定する。
4. 部品表と状態表を作る。
5. 比率表を作る。
6. 不明点と画像間の矛盾を記録する。

### Phase 2: ブロックアウト

1. 中央艇体のロフトを作る。
2. ローター中心とダクト開口を置く。
3. 翼の外周輪郭を作る。
4. 尾翼と脚を配置する。
5. 正面、上面、側面だけをレンダーする。
6. 外形が一致するまで細部へ進まない。

### Phase 3: 識別要素

1. バイザーや主要センサーを埋め込む。
2. ダクトと胴体の接続部を作る。
3. 脚のヒンジと接地形状を作る。
4. 後面ユニットを多層化する。
5. 左右対称性をModifierで保証する。

### Phase 4: 表面と素材

1. 大型装甲パネルを分割する。
2. エッジ合金と暗色凹部を分ける。
3. 整備ラッチを追加する。
4. 発光範囲を限定する。
5. 摩耗と粗さを追加する。

### Phase 5: 全周検証

同一メッシュから次を出力する。

- `hero`
- `front`
- `rear`
- `top`
- `bottom`
- `left`
- `right`

基準画像と同じ方向を切り出し、横並び比較PNGを作る。比較時は次を順に見る。

1. 全幅、全長、全高
2. 中央艇体と翼の面積比
3. ローター開口比
4. 機首と後端の幅
5. 脚の接地位置
6. 尾翼の数、向き、高さ
7. バイザーの長さ、太さ、外板への密着
8. 後面の情報密度
9. 材質の明暗差
10. 発光の位置と強さ

### Phase 6: 承認と実装

1. PNGをチャットへ直接プレビューする。
2. ユーザー承認前にゲーム用モデルへ反映しない。
3. 承認後、正本`.blend`からゲーム用形式を生成する。
4. 低ポリゴン化後にも全周比較を行う。
5. ゲーム内で静止、飛行、旋回、着艦、ローター停止を確認する。

## 7. 自動検証項目

- 必須部品が存在する。
- Mesh Object数が想定範囲内である。
- 左右部品に共通Mirror Modifierがある。
- 機首軸と上方向が仕様どおりである。
- 尾翼が後傾している。
- ローターが左右2基である。
- 脚の接地面が同じ高さである。
- バイザーが前面と左右側面へ連続している。
- 後方灯火が左右対称である。
- `.blend`と`.glb`が最新レンダーと同時刻に生成されている。
- Blenderログに`Traceback`がない。

自動検証PASSは見た目の一致を保証しない。必ず比較PNGを目視する。

## 8. 失敗しやすい進め方

- 画像生成した全周図を、そのまま正確な三面図として扱う。
- 斜視画像だけを見て完成と判断する。
- 箱を積み重ねて複雑さを出そうとする。
- 左右を別々に作る。
- バイザーを発光する棒として外板へ貼る。
- 脚の足先を決めずに支柱から作る。
- 翼端のフェアリングを尾翼と誤認する。
- 後面を単純なグリルだけで終える。
- 明るい発光と銀色エッジを増やして情報量を代用する。
- シルエットが違う段階で傷、ボルト、テクスチャへ進む。
- ソース検査だけでレンダー成功を宣言する。

## 9. 次回開始時の入力テンプレート

```text
この基準画像から3Dモデルを作成する。

最初に以下を実施すること。
- 正面、後面、上面、底面、左右側面、斜視を識別する
- 座標系と機首方向を固定する
- 部品表、部品状態、左右対称性、接続関係を定義する
- 全幅、全長、全高、主要開口、脚、センサーの比率を測る
- 画像間の矛盾を記録する

Blenderのポリゴンメッシュを正本とし、中央構造はロフト、左右部品は共通ミラー原点、埋め込み部は凹部と内側面に分けること。

細部の前にシルエットを検証し、同一メッシュから斜視・正面・後面・上面・底面・左右側面をPNG出力する。基準画像との横並び比較PNGを作成し、差を修正すること。

承認前にゲームへ反映しないこと。PNGはチャット内で直接プレビューできるように提示すること。
```
