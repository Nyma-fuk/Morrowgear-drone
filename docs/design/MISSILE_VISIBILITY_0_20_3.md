# ミサイル視認性と音源明瞭度の調整

## 目的と変更範囲

赤く点滅するマイクロミサイルを、射出から着弾まで追いやすくする。誘導、弾数45、3～5発の連射、付着、12 tickの信管、威力、味方判定、地形保護の条件は変更しない。変更は描画、音源、初期の見た目の姿勢に限定する。

## 本体と軌跡

- 旧表示は長さ約0.45の板状の光。新表示は長さ1.05、胴体直径0.20、安定翼幅0.48の8角断面の本体とする。赤い本体、細くなる弾頭、4枚の安定翼、ノズル、赤い点滅帯を設ける。
- 当たり判定は従来の0.28のまま。表示上の長さを理由に早く衝突・起爆させない。
- 射出時は上向き、移動時の姿勢は既存の機首方向を補間する。付着後も対象の移動に追従する既存処理を維持する。
- 点火後のみノズルから明るい芯と橙色の排気を描く。飛行履歴に沿って淡い灰白色の排気と暖色の芯が残り、18 tick（約0.9秒）で減衰する。目標まで直線を引く表示ではない。
- 履歴は各機最大20点、クライアントのみ。着弾後は新しい点を作らず、残った軌跡を減衰させる。起爆でエンティティが消えた後は描画しない。テレポート相当の位置飛び、時刻の巻き戻り、大きな更新欠落では履歴を切る。
- 本体も軌跡も深度判定を使用し、遮蔽物越しの最前面描画にはしない。画面外判定には軌跡の範囲も含める。

従来はEntityの標準距離判定が小さな当たり判定を使用し、通常の表示倍率1では約17.92ブロックで描画対象から外れる計算だった。通信の追跡距離とは別の制約である。今回は描画基準を128ブロックとし、ユーザーのエンティティ表示距離倍率を適用する。上限は通信設定に合わせ192。チャンクやエンティティが未受信なら遠隔描画できるわけではない。

## 音源

[音声接続資料](DRONE_AUDIO_INTEGRATION.md)の「0.20.3の明瞭度調整」を参照。飛行、機関砲、レーザー充填・照射・放電・着弾・冷却、ミサイル発射・衝突・爆発・破片の全12音源を再生成した。ピーク増大だけで迫力を出さず、歪みと持続ノイズを整理する。

比較試聴は `build/verification/missile-audio-clarity/flight-before-after.wav` と `laser-before-after.wav`。どちらも前半が旧音、後半が新音。ゲーム内の音量・距離減衰・同時発音を再現したものではない。

## Dock補給の操作

所有する通常Dockに補給品を入れると、着艦接点にいる機体へ自動で供給する。専用の充電開始ボタンは不要。

| 補給するもの | Dockに入れるアイテム |
| --- | --- |
| 飛行電力・武器電力 | 石炭、木炭、各種バッテリーパック |
| 機関砲弾 | 鉄塊。1個で不足分を最大24発補充 |
| ミサイル | ロケット花火。1個で1発補充 |
| 修理 | 鉄インゴット、銅インゴット、Morrow Alloy |

補給品を手に持ってDockを右クリックすると、空きのある下段9枠に投入する。通常のDockインベントリーから入れることもできる。モジュール用・蓄電容量用・組立用の専用枠と、消費する補給品の枠は区別する。自動投入は持っているスタックから空き容量分を預けるので、1回のクリックが1個だけの投入とは限らない。

レーザー用に別の弾薬アイテムは不要だが、武器電力が必要。ミサイルと機関砲も弾薬だけでなく武器電力を使うので、燃料も補給する。飛行電力ゼロでもDock接点にいれば充電できる。空中のソーラー式サービスDockは通常Dockの弾薬補給を代替しない。

## 確認範囲

自動試験では点火前の非表示、曲がった履歴、件数上限、着弾後の減衰、不正座標・位置飛び・時刻逆行、表示距離境界、音源の形式・帯域・ピーク・ループを確認する。描画のコンパイルと全Java試験も実施する。

2026-09-22: 全Java試験1,948件（失敗・エラー・スキップ0）、音源試験8件PASS、ビルド成功。完成JAR内の12音源と `sounds.json` が検査済みの素材と一致することを確認した。旧版のLauncher用JARは変更していない。

ユーザーの「修正とビルドだけ」の指示を継続し、ゲーム操作、Launcherへの差し替え、再起動は実施しない。実ゲームの視認性、壁による遮蔽、聴感、複数斉射時の負荷は未確認とし、自動試験の成功だけで合格扱いにしない。
