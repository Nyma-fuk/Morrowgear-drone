# 機関砲・レーザー音 V3

2026-09-22。試聴案。ゲーム未接続・未反映。承認済み飛行音、V2のミサイル、ゲーム内の発砲周期・威力・消費弾数は変更しない。

## 要求と前案の問題

ユーザー要求は、機関砲をA-10やF-35の回転砲のような密度にすることと、正体が分かりづらいレーザー音を見直すこと。

V2の機関砲はショットガン録音を毎秒10回並べたため、ゲームの命中判定周期に合わせすぎて、一体になった掃射の質感が出しにくかった。レーザーは純音を減らす際に広帯域のノイズを主役にしてしまい、持続する光線の識別音が弱かった。これらは音割れやファイルの自動検査に合格しても防げない、聴感上の設計課題である。

## 今回の作り方

### 回転砲

- 単発録音の繰り返しではなく、A-10の飛行・射撃として公開された録音の、最初の連続したバースト区間を使用。
- 立ち上がり、持続、停止を独立した音に分ける。持続部分に0.4秒ごとの無音を作らない。
- 低域のうなりと中域の発砲密度を残し、金属が転がるような独立した効果音を追加しない。
- 試聴は0.8秒の短い掃射と2.4秒の長い掃射。着弾音を混ぜない。
- 音響上の密度をゲームの弾数として数えない。DPS、弾薬消費、命中判定の回数は据え置き。

録音は [A-10.ogg / qubodup](https://freesound.org/people/qubodup/sounds/205582/) 。個別ページのCC0表記を確認し、公開HQ MP3プレビューを使用した。作者は米国政府映像からの抽出と説明しているが、その原映像の権利関係まで独立確認したわけではない。F-35の実録音は使用していない。屋外録音なので、残響や機体音が完全に分離された音源とは言えない。

出典、確認日、SHA-256、使用区間は `tools/audio/source-recordings/rotary-source.json` に記録する。射撃区間は約0.8〜2.5秒、持続部分の抽出開始は1.12秒。実録の質感を使用するもので、実銃の発射数や性能の再現を主張しない。

### レーザー

「低く集約される充填 → 一度の放出 → 一定の切断音 → 遮断と排気」に整理する。

- 充填だけ110 Hzから880 Hzに一方向に上昇し、終盤は照射音の高さで保持する。
- 照射は880 Hzを芯に、同期した倍音と低い機構音を加える。複数の微妙にずれた発振器によるうなりや、周期的なピッチ変調は使わない。
- 空気の音は薄い補助層にとどめる。前案のように広帯域ノイズで光線の芯を覆わない。
- 停止時は下がる電子音を使わず、一度の遮断と短い冷却音にする。
- 今回の試聴では対象側の焼ける音を重ねず、機体から出る音だけを確認する。

これは架空装置の音響デザインであり、880 Hzが実際のプラズマやレーザーの物理的周波数という意味ではない。固定した音程でも不快に感じる可能性はあるため、人による聴感確認は必要。

## 成果物

`build/verification/rotary-laser-v3/` に次を出力する。

| ファイル | 内容 |
|---|---|
| `gatling.wav` | 短い掃射、間、長い掃射。6秒 |
| `laser.wav` | 充填から照射・冷却まで。11秒 |
| `*-with-flight.wav` | 承認済み飛行音を同じ割合で加えた試聴 |
| `*-v2-v3.wav` | V2、1秒の無音、V3の順。RMS合わせ。知覚上の同じ音量は保証しない |
| 7個のOGG | 回転砲3状態、レーザー4状態の接続前素材 |
| `report.json` | 波形指標、時系列、出典、既存音源の不変確認 |

```powershell
python tools/audio/propose_rotary_laser.py
python -m unittest discover -s tools/audio -p 'test_*.py' -v
```

生成にネットワークは不要。依存はnumpyとsoundfile。旧試聴が存在しなければ比較ファイルだけ省略する。出力先は新しい検証フォルダーに限定し、旧試聴やゲーム音源への書き込みを拒否する。

## 接続時の注意

承認後は、回転砲の発砲状態に合わせて開始・持続・停止を駆動する必要がある。現在の0.4秒ごとの単発サウンド通知に長いループを重ねて再生してはいけない。中断、目標消失、帰還、破壊、画面外の機体でも、停止と音源位置の追従を確認する。これらのランタイム変更は今回まだ行っていない。

レーザーの充填と照射の移行は現行の戦闘状態を使い、音を鳴らすために照射条件を変更しない。多数機の重畳、距離減衰、実際の発射映像との同期もゲーム接続後の確認項目。

## 検証範囲

新規10テストは、出典ハッシュ・完全なデコード、再生成一致、ピーク・RMS・DC、短い発砲の隙間がないこと、充填の単調上昇、照射中の音程安定、ループ継ぎ目、開始停止時刻、旧素材の保護、書き出しを検査する。ゲーム内の確認および人による試聴の代わりではない。

実施結果: 新規10件と既存41件、計51件の音声関連自動テスト PASS。生成前後で承認済み飛行音、V2ミサイルを含む旧試聴、ゲーム音源のハッシュが一致。インストール済みJARも変更前のハッシュと一致した。主観的な音の良さや実ゲームでの発音は未確認。

## V4：細い高音を少量追加

ユーザーの「この音にキィーンを少し混ぜる」という指定に対し、V3を作り直さず照射ループだけに2200 Hzの固定音とごく薄い3300 Hz成分を追加した。追加層のRMSは元の照射音の18%で、音量を全体的に上げたり低音を削ったりしない。音程の揺れや周期的な強弱は付けない。充填・放出・冷却、飛行音・機関砲・ミサイルはそのまま。

`python tools/audio/propose_laser_edge.py` で `build/verification/laser-edge-v4/laser.wav` と比較用 `laser-before-after.wav` を生成する。比較は前案11秒、無音1秒、今回11秒の順で共通の音量倍率を使う。元のV3はハッシュ照合して読み込み、書き換えない。

追加層の量と周波数、固定音程、継ぎ目、照射以外の区間の一致、既存素材の保護を確認する5テストがPASS。高音の感じ方は数値検査では保証できないため、今回も試聴案でありゲーム反映はしていない。
