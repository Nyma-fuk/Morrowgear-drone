# V23 コントローラー・HUD調整の引継ぎ

## 対象

2026-09-21。既存の承認済み配色・記号・8ページを維持した小規模な操作性調整。
実装変更は `TacticalDashboard.java`、`HmiArt.java`、`VisorHudOverlay.java` のみ。
飛行・兵装・描画資産・通信形式・翻訳ファイルは変更していない。

## 変更内容

- 複数選択の概要に役割別機数、全員選択したWing数、一部選択したWing数、手動Wing未所属機数、フィルターで隠れた選択機数、Dock未登録機数を表示する。
- `RETURN TO ME` と `TO DOCK` で帰還先を区別する。送信する `return`、`dock` 等の命令IDは変更しない。
- 自動作業の対象を `FLEET TASK FORCE`、手動作業を `SELECTED` として区別する。サーバーの新状態は追加しない。
- STOREの再確認を最初に選択した機体集合に限定する。選択変更、別の飛行命令、期限切れで再確認が必要になる。
- 作業・GUARDの地点指定を選ぶと巡回ルート編集を解除する。巡回編集中のダブルクリックで通常の地点命令を送らない。
- Wingカードの名前・任務・電力欄を互いの幅内に収め、選択スロットを既存シアン枠で示す。
- HUDの上部情報は実際の文字幅で補助項目を省略する。狭い画面では注視・固定対象を優先し、中央の任務概要が左右パネルに重なる場合は表示しない。
- 長い警告は二段で表示する。救難ビーコンだけが残る場合も最低1件を表示する。低電力機がすべて帰投中であるかのような固定表記をやめ、実際の帰投・着艦数を表示する。
- 近接マーカーは緊急機を含め既存の優先順と件数上限を使用する。集団の常時ラベルは機数だけにし、詳細ラベルの上限を迂回しない。
- 電力・Recoveryから算出した割合を通信品質として表示していたHUDの `LINK %` を撤去し、実際のRecovery件数を表示する。

## 自動確認

`node --test tools/test_hmi_usability.cjs` : 8件合格。
Node.jsとJDKの `jshell` を使用し、Gradle・ゲームの起動、JAR生成、インストールは行わない。

実ソースから取り出したJavaメソッドで文字省略、Unicode境界、320〜3840pxの横配置、Wing集計、STORE確認、8機上限を検査した。STORE送信先はテスト用受信記録で確認し、ゲームには送信していない。
対象3ファイルのJava構文解析と、命令ID・選択・8ページ・D&D経路・排他的な地点指定・警告表示のソース契約を確認した。
構文解析はMinecraft依存を含む型チェックではなく、ソース契約は実際のマウス操作試験ではない。

既存の実ゲーム証跡 `verification/in-game/wing-management.png` を調査したが、今回の変更後の実画面を撮影・検証したわけではない。
