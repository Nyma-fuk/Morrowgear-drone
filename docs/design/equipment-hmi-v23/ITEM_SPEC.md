# V23 アイテムとモデルの設計契約

## 正本とサイズ

形状正本は各 `models/<id>/<id>.blend`。表示用交換形式をGLB、アイコンを正本から描画したPNGとする。FieldユニットとDockはV22のBlend/GLBを参照し、アイコンだけ別の生成画像にしない。機器模型の寸法は制作座標であり、そのままMinecraft内の手持ち倍率を表すものではない。

機体幅3ブロック、水平外形3×3以内、Dock5×5、推奨中心間距離7ブロックの定義はV22を維持する。**これらは設計寸法であり、現行ゲームの当たり判定が既に更新された意味ではない。**

追加の非アイテム構成物は `charging_relay` と `service_light`。同じダクト・駆動部を共有し、充電子機は下面光学口、照明子機は拡散発光面で区別する。機能の割当て数や給電能力は外形から推測して変更しない。

## 描画と可動

- 全構造をX=0で対称化する。回収ツールは開閉時も両側を同時に検査する。
- コントローラーのLCD面は、構造の対称化処理から分離する。文字と地図を反転複製しない。
- 回収クランプは独立した左右ヒンジを持つが、GLBでは同一シーンクリップとして書き出す。片側だけ再生される構成にしない。
- 肉厚、関節、下面のバス・フィンもモデル化する。上から見た静止画だけを正本にしない。
- 手続き型の表面粗さはBlend側の表現。Minecraftへはベース色・粗さ・法線・発光の必要成分をベイクし、使用するレンダラーに合わせて分離する。
- 発光帯は構造形状と別に扱い、通常色と戦闘色の切替はゲームの確定状態を入力にする。

## アイコン・記号

アイテム画像は周囲に余白を取り、同一カメラの立体投影を各解像度へ変換する。24pxでは細いねじやフィンまで読む前提にせず、レンズ・シャッター・層数・開放骨格など大きい特徴を優先する。

HMIの操作記号はLucide、役割記号はV22の役割記号を継承する。SVGは正本、PNGはゲームへ取り込めるラスタ形式。95個それぞれの出典とサイズは `hmi/symbols/manifest.json` に記録し、Lucideのライセンスを同梱する。

役割記号、状態記号、機影、立体アイコンは異なる用途。狭いHUDで立体画像を極小表示して役割を判断させず、役割記号を用いる。色だけを唯一の区別にしない。

## 保持・装着確認の限界

左右の保持姿勢画像、LCDの向き、回収クランプの向き、バイザーの頭部プロキシ上の位置を制作空間で確認した。Minecraftの一人称・三人称、左手・右手、GUI・地面・額縁の表示変換は未設定。画像の正しさだけを根拠に、ゲーム内の背面表示・手への埋まりが直ったと報告しない。
