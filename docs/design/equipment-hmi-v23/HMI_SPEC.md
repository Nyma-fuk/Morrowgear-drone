# V23 HMI: 情報・操作・実装境界

## 基本方針

機体の戦闘的な造形と、画面の情報密度を分離する。操作端末は静かで読みやすい計器とし、地形、役割、任務、必要な判断を優先する。黒い装甲飾り、巨大な常設パネル、過剰な点滅、意味のない英数字を足して「軍事的」にしない。

通常時は少量、注視時は個体、全体状況は戦線・任務の集計、危険時は具体的な不足理由を表示する。サーバー状態の確定前に、受理されたような色やメッセージを出さない。

## 情報の所有者

| 情報 | 意味と同一性 | 禁止する混同 |
| --- | --- | --- |
| 機体ID | 永続的な機体識別 | リスト位置や表示順を識別子にしない |
| 所属Wing ID | 手動・自動編成の所属 | 一時的な戦闘参加で別WingへJoinした扱いにしない |
| 任務ID・版 | 指示された目的と更新順 | 現在の飛行状態だけで任務終了を推定しない |
| 一時群・戦線ID | 同じ目的に対する戦闘上の協調 | 所属Wing、旋回レーン、敵個体を一つのIDにしない |
| 目標ID | 現在攻撃・追跡・回収している対象 | 近くの別目標を描画だけで差し替えない |
| 中断任務・復帰先 | 割込終了後に再検証する候補 | 「中断前と同じ行動を必ず再実行」と解釈しない |
| ホームDock | 所有・登録先、主な補給施設 | 浮遊サービスDockの給電枠と同じ扱いにしない |
| 受信時刻・鮮度 | 最終確認と現在確認の区別 | 通信断の値を最新の確定値として表示しない |

ゲーム側の主な接続先は `TacticalScreen`、`VisorHudOverlay`、`VisorHudPolicy`、`WingMembershipPolicy`、`WingEditPolicy`、`MissionDataLink`、`FleetThreatNetwork`、`DockServicePolicy`、`SalvageMissionRegistry`。このプロトタイプはそれらを呼んでおらず、既存コードに同じフィールド・通信経路がすべて存在するとも断定しない。接続時に型と更新契約を照合し、不足値は「不明」とする。

## 8画面の責務

| 画面 | 主な情報 | 操作と失敗時 |
| --- | --- | --- |
| 作戦地図 | 地形、機体、経由点、選択、任務・戦線集計 | 絞込、ID/役割/電力順、ページ送り、地点移動、即時指示。未選択・権限なし・通信断では拒否 |
| Wing管理 | 8枠、所属、任務、リーダー表示 | 個別/複数選択、新規Wing、編入、離脱、戻す。満員なら一括拒否し元所属を維持 |
| 任務 | 任務目的、担当、進捗、割込・復帰 | 作業/輸送/ルート、詳細、一時停止/再開。対象の有効性を再検証する契約を表示 |
| Dock・補給 | 登録先、着艦、電力源、弾薬資源、再出撃理由 | 1機と未登録Dockの組合せを割当て。サービス給電3枠は別欄。コンテナ搬出/搬入指定 |
| 回収 | 救難ID、距離、最終確認、担当、搬送先 | 救難回収計画。利用可能Salvageなしでは拒否。消失時は回収を取り消し復帰先を再検証 |
| バイザー | 集約戦線、注視機、近接機、救難 | 3Dカメラに基づく位置投影。遮蔽・画面外と実視認を区別 |
| 機器・アイテム | 全23種、分類、識別形、正本 | 各7方向、実寸アイコン、Blend/GLBを確認。ゲーム資産と設計候補を明示 |
| 設定 | 情報密度、本文サイズ、視認性、通信設定 | 自動/最小/詳細、14/16/18px、マーカー、コントラスト、動き、字幕。音声は設定確認のみ |

別画面に分けるダイアログは、ルート編集、作業アンカー、コンテナ輸送、迎撃戦線、回収計画、機体詳細・Dock時の役割変更、格納確認、Dock割当・補給理由、任務詳細、戦線詳細、アイテム方向図。

サンプル地形は設計用画像であり、サーバーの地形取得結果ではない。回収画面の距離もサンプル値。実データの更新速度や長距離通信を検証したものではない。

## 選択と所属

1. 選択集合はIDで保持する。ソート、絞込、ページ変更で別の機体に化けない。
2. 「表示分」は現在ページ、「絞込全機」は検索結果全体、「全機」は管理対象全体。対象範囲を混同させない。
3. Checkbox、Ctrl、Shiftの範囲選択を用意する。Wing画面はタップでも追加選択できる。
4. 複数Wingを選んだ際は「複数Wing」と表示する。任務・Dock・復帰先は集合を要約し、最初の機体の値を全機の値にしない。
5. Wingカードは最大8枠。D&D中に7pxを超えたらドラッグとして扱い、クリックと区別する。満員なら途中まで移動しない。
6. カード外のWing管理領域へのドロップは未所属へ移す。画面外・操作キャンセルは所属を変えない。
7. 任務のあるWingへ編入したら、その任務を参照してREJOIN表示へ移る。任務のない新Wingや未所属へ移っただけなら、個別任務を消さない。
8. 所属と任務の受理はゲーム側で原子的に検証する。プロトタイプの「編集を戻す」はローカルサンプルの復元であり、実ネットワークの巻き戻し機能ではない。

## 指示のライフサイクル

`下書き → 送信前検証 → 応答待ち → 受理 / 拒否 / 結果未確定` とする。

- 送信時に対象IDと版を固定する。応答までに選択が変わっても、別の機体を変更しない。
- 応答待ち中は二重送信を拒否し、成功演出を先に出さない。
- 受理時に版、対象の存在、権限を照合する。版不一致や消失は拒否する。
- 通信断時は実行結果が未確定であることを示す。見えない成功を推定して再送しない。
- 結果は何機に適用されたかを表示する。部分適用が必要なら、ゲーム側から機体別の結果を返す契約を追加する。

現在のプロトタイプは400ms後のローカル応答で検証する。実際の再送、永続コマンドID、サーバー再起動後の照会、タイムアウトの重複排除は未接続。通信版の挙動は接続時の必須試験とする。

## 各任務で隠してはいけないもの

| 任務 | 必須表示 | 条件・フォールバック契約 |
| --- | --- | --- |
| ルート | 対象ID、点順、座標、高度、現在区間 | 1～8点。空・非有限・範囲外座標を拒否。最近点から進入。1点旋回、2点往復、3点以上周回 |
| 作業 | アンカー、作業種別、調査と作業と回収の区別 | Scout調査、Engineer作業、Cargo回収を同じ「WORK」のみで隠さない。実制御接続時は詳細状態を展開 |
| 輸送 | 搬出元、搬入先、内容、満杯・利用権 | 同一コンテナ、消失、満杯を拒否。利用権取得と物品移動の原子性はサーバー責務 |
| 迎撃 | 所属Wing、一時群、戦線、敵ID、実交戦数 | 違う戦線の機数を加算しない。復帰候補と代替機の引継ぎを可視化 |
| 補給 | FLT/WPN/弾薬/HEATを別表示、停止理由 | 資源枯渇を充電中と表示しない。再出撃の安全量と任務遂行条件を説明可能にする |
| 回収 | 対象ID、鮮度、Salvage、出発Dock、荷 | 牽引時の荷の最下面を考慮。対象・Dock消失は代替先や元任務を再検証 |
| 復帰 | 中断任務、現在需要、候補先、不可理由 | 目標消失なら同任務残作業、Wing最新任務、安全帰投の順を候補にする。UIだけで決定しない |

画面の例示用状態モデルはPATROL/WORK/COMBAT等に簡略化している。`CombatState`、`CargoState`、`EngineerState`、`SalvageState`等のゲーム内全状態を既に写像・接続できたという意味ではない。

## HUDの密度と優先度

| 優先 | 情報 | 扱い |
| --- | --- | --- |
| 最優先 | POWER LOST、回収不能、プレイヤーに迫る重大事象 | 通常マーカーを消しても集約警告を残す。機体消失・回収済みは対象IDを照合して解除 |
| 固定 | 注視・ピン留め中の機体 | 現任務、FLT/WPN/耐久、必要なら弾数・HEAT・不足理由。勝手に別機へ切り替えない |
| 作戦 | 戦線、敵数、交戦数、未充足、作業進捗 | 単位を戦線/任務にする。所属Wing数と一時群数を別集計 |
| 周辺 | 視認できる機体位置と短いID | 同一カメラの3D投影。遮蔽物の裏側は遮蔽記号、画面外は端の方位記号 |
| 低優先 | 定常作業、連続した完了報告 | 集約・抑制。常時点滅や多数機の入替表示を避ける |

プロトタイプの標準マーカー予算は8、大規模データは6、狭い表示は3、最小設定は2。詳細設定でも上限を置く。最大表示戦線は3、狭い画面は1で、残数は `+N FRONTS` として保持する。救難集約はこの枠外に置く。

実装する3Dプレビューは最大8機を表示する。役割別の実メッシュを使い、POWER LOST機を飛行サンプルに混ぜない。100/256機の試験は情報量・選択・集約の試験であり、その機数を同時描画した性能試験ではない。

ゲーム接続時には、順位がわずかに変わるたびに別機へ切替えないため、通常項目に最低表示保持時間と順位差の閾値を設ける。重大事象・対象消失・ピン変更は即時更新する。**この時間的ヒステリシスは今回の静的サンプル群では検証していない。** 値は実ゲームの移動速度と視認試験で決め、推測した値を既存仕様として固定しない。

## 投影と画面サイズ

投影はワールド座標を、機体描画と同じカメラのView/Projectionへ渡す。ラベルの位置だけYaw/Pitchの2D近似で算出しない。機体の補間時刻とカメラの描画時刻も合わせる。専用シェーダーの有無より、座標系、奥行き、遮蔽の整合が先である。

中央照準、固定パネル、ホットバー予約領域、他ラベルと衝突する詳細文字は別位置に置くか省略する。マーカー本体と文字の収縮を分ける。UIのすべての要素を拡縮行列で小さくして収めない。

- 本文は14pxを初期値とし16/18pxを選択可能。補助情報も12px程度を下限として扱う。
- 950px以下は指揮欄を切替表示へ、620px以下は地図・一覧・指揮を切り替える。
- 表は内部スクロールし、ページ全体を横にはみ出させない。機体一覧とページ操作は別領域を持つ。
- テキストを画像に焼き込むのは手持ち端末の固定サンプル画面のみ。操作HMI本文はテキストとして描画する。
- 高コントラスト、動作低減、色と記号の併用、タッチ操作の代替ボタンを用意する。

## 状態音声

HMI上の通知優先順位と字幕領域は設計した。発話は機体の確定した状態遷移に対する必要最低限の報告とし、毎tickや旋回の位相変化では発信しない。多数機の同一イベントはWing/任務単位へ集約し、重大な個体故障は個別に残す。

今回の音声設定は操作確認のみで、新しい録音・音声合成・ゲーム内再生は含まれない。音声サンプルがない状態を、音が鳴る実装として扱わない。
