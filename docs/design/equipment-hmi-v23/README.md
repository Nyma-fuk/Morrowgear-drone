## デザインの根拠

- 機体の低い輪郭、左右対称、埋込機能部、細い発光帯を機器にも引き継ぐ。巨大な外付け装飾で重量感を出さない。
- 材質をグラファイト、金属エッジ、暗い光学ガラス、控えめな安全色に統一する。素材アイテムの銅や基板の緑は機能を識別するために残す。
- モジュールは共通カセットの機能面、電池は層数、素材は外形で区別する。全部を色違いの箱にしない。
- 機器の厚みと、操作画面の背景面積は別問題。HMIに装甲の枠を描き込まず、地形と機体が主役になる余白を残す。
- 小さなHUDでは立体画像ではなく役割記号を使う。文字を極端に縮めて情報量を維持しない。
- 左右対称の対象は物理的な構造。LCDの文字、矢印、進行方向、動く走査点まで反転させない。

## 仕様と検証

[HMI仕様・実装境界](HMI_SPEC.md)、[アイテム・モデル仕様](ITEM_SPEC.md)、[検証記録](VERIFICATION.md)を参照。

今回の結果は、構造69姿勢、GLB読み戻し、HMIロジック117ケース、ブラウザー62確認で合格。重要な修正は、回収クランプの左右アニメーションがGLBで別クリップになる問題、ドラッグ入力が所属変更まで届かない問題、ドラッグ後の次操作を消費する問題、交戦数と複数選択詳細の固定表示だった。

ただし、全ユーザー操作列を網羅した証明でも、Minecraftでの見た目・性能・動作を保証する結果でもない。ゲーム移行には材質ベイク、可動階層の描画対応、保持姿勢、3×3機体と5×5Dockの衝突・保存互換、実クライアント画像照合が必要。

## 再生成

1. Blenderで `tools/drone-design/blender/build_equipment_hmi_v23.py` を実行する。
2. Blenderで `tools/drone-design/blender/verify_equipment_hmi_v23.py` を実行する。
3. `tools/review_equipment_hmi_v23.py` でアイコン・比較図・台帳を更新する。
4. `tools/build_hmi_symbols_v23.cjs` で記号を生成し、`tools/test_equipment_hmi_v23.cjs` を実行する。
5. ブラウザー操作を再実施し、スクリーンショットと `verification/browser-results.json` を更新する。
6. `tools/finalize_equipment_hmi_v23.py` で画像参照、寸法、非空白、検証結果を照合し、PNGと集計を作成する。

再集計だけでブラウザーを再試験した扱いにしない。手続き型材質を使うBlendとGLBの質感が完全に同じであるとの保証も行わない。
