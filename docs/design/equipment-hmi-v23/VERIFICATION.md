## 実施した操作

- ID/役割/電力順、検索、絞込全機、表示ページ、全機、Shift範囲、選択の維持。
- 0/1/8/9/24/100/256件で識別子・Wing8機制限をロジック確認。ブラウザーは0/24/100/256件を含む画面を確認。
- ポインターD&Dで満員Wingへ編入拒否、未所属への離脱、任務ありWingへ再編入。編入後のREJOINと次の画面操作を確認。
- ルートの点追加、順番変更、高度変更、送信待ち、受理表示。空・9点・非有限・無効高度はロジックで拒否確認。
- 通信断・権限なしで指示無効、送信後の選択変更・対象消失・版不一致・二重送信をロジックで確認。
- 輸送先満杯で画面上の拒否、回収計画で対象と出発Dockを確認。
- 迎撃戦線と対象ID、全Wing指示と個別指示の境界、回収対象消失、Dock登録参照をロジックで確認。
- 各画面の画像欠損、横はみ出し、ボタン内の横方向の文字溢れを測定。
- 390×844、960×600、1440×900、1920×1080相当のレイアウトを確認。1920は取得画像の右側がホスト表示幅で切れるため、提出用の全画面画像は1440を使用。
- 小画面で地図・一覧・指揮を往復。本文18px設定が機体一覧へ反映され、ボタンに横溢れがないことを確認。
- HUDの役割別メッシュ、上下を含む移動、カメラ左右・上下変更、奥行き、戦線集約、近接マーカー数、救難表示を確認。
- Dockアイテムの7方向切替、全アイテムのモデル・方向図・アイコン参照を確認。

## 発見して修正したもの

1. 回収クランプのGLB書き出しが左右別のアニメーションクリップになり、再読込時に片側だけ動いた。シーンクリップへまとめ、3姿勢の境界を再照合した。
2. ブラウザーのネイティブドラッグが、操作時に所属更新まで届かなかった。Pointer Eventsで入力経路を統一し、実ポインター操作で再検証した。
3. ドラッグ後のクリック抑制が残り、次の画面切替を消費した。抑制範囲と寿命を限定し、ドラッグ後の画面切替を確認した。
4. 多戦線の交戦数、採掘役割数、複数選択の任務・Dock表示に固定値や先頭機だけの値が混在した。IDに基づく集計と複数値要約へ変更した。
5. 回収計画と作業アンカーが見た目だけで、サンプル指示データへ残らない箇所があった。対象・搬送先・アンカーを指示のペイロードへ保存した。
6. LCDの構造対称化と文字のUV対称化が混同される危険を除き、LCD面を構造反転から分離した。

## 残る制約

- 構造対称と境界寸法は、全三角形の自己交差、空力、全アニメーション時刻のクリアランスまで証明しない。
- 7方向画像の存在・非空白と目視確認は、元のコンセプト画像へのピクセル完全一致を意味しない。
- 3Dキャンバスは最大8機。256機をゲーム内で同時描画した性能値ではない。
- キーボード・マウス・狭い画面の代替操作は確認したが、実スマートフォンのタッチ機種差やスクリーンリーダー全製品を実測していない。
- ブラウザーの標準フォントとGLB描画はMinecraftのフォント・MGM描画・発光・深度合成と同一ではない。
- 実ゲームへの新資産反映、既存ワールド移行、ネットワーク通信、全任務状態の写像、実際のDock在庫操作、音声再生は今回の試験対象外。

**この有限の試験集合が合格しても「バグがない」とは言わない。ゲームへ組み込む際は既存の機能試験を保ったまま、同じ視点・GUI倍率・機体数で実ゲーム画像と本設計を照合する。**
