# 参照画像に基づく共通機体の再構築 V10

## 結論と範囲

**現在も再現性は未合格。画像と一致した、全機種が完成した、とは扱わない。**

ユーザーが選んだ[共通機体の参照画像](../blended-wing-v5/concept.png)に対し、旧案V8/V9は胴体と翼のつながり、厚さ、開口部、翼端、質感を十分に再現していなかった。対称性とファイル正常性だけを確認しても、この問題は検出できない。

今回の成果は、画像の解析データ、実メッシュを使う比較工程、左右対称な共通機体の制作途中モデルである。参照画像は2Dのデザイン画像であり、元の編集可能な3Dメッシュが付属しているわけではない。

ライブのゲーム資産、アイテムID、当たり判定、ワールド、配布JARは変更していない。Minecraftでの見た目・性能・動作確認は実施していない。GLBには手続き型材質と同一の焼き込みテクスチャがまだないため、Blenderと同じ質感を保証しない。

## 画像から分かること

| 部位 | 画像で確認できる特徴 | 3Dへ移す際の扱いと残課題 |
| --- | --- | --- |
| 胴体・翼 | 広い後退翼と中央の盛り上がりが一体になっている | 独立した翼板を胴体に差す方式をやめ、一続きの上下面として構成。肩とノーズの断面はまだ照合が必要 |
| ノーズ | 幅のある面取り形状。発光バイザーは細い黒い溝に収まる | 発光帯と溝を別部品にする。参照の右側の折れ点は機体中心と同一ではない。投影された見た目の中央を対称軸と誤認しない |
| タービン | 左右2つの大きな開口、暗い内壁、独立したハブとねじれたブレード | 開口を実際に空け、厚みを持つブレードを生成。周囲の面と開口縁の高さを照合。画像で隠れたブレード枚数・下部支持構造は推定 |
| 肩の吸気口 | 黒い細長い開口とその外側の面が見える | 黒い三角形を貼るだけにせず、メッシュに凹部を作る。現在の開口形状と周囲の法線は未合格 |
| 翼端 | 翼面から曲がった先端、金属の縁、橙色の細い表示 | ミラーの同一構造で再現。左右の画像注釈が同じ物理的な角を指しているか未確定。片側だけ変形して帳尻を合わせない |
| 後部 | 小さく持ち上がった左右のフェアリング | 共通機体の一部として維持。画像で見えない排気口の奥行きは設計上の推定 |
| 外装 | 微妙に異なる面、継ぎ目、留め具、金属の端面 | 明暗をそのまま凹凸へ変換しない。反射、表面模様、面の向きの候補を分ける。材質再現は外形とは別に判定 |
| 底面・脚 | この参照一枚だけでは全構造が見えない | 他の承認済み案と機構上の整合から設計する領域。現在の共通モデルに脚・役割機構を完成品として組み込んでいない |

制作座標は右が+X、前が-Y、上が+Z、対称面はX=0。制作単位をMinecraftの1ブロックや実機の1mと同一視しない。構造の左右対称性と、透視画像上で左右が同じ大きさに見えることは別である。

## 解析と修正の手順

1. 元画像を変更せず保存し、1681×936の画素座標を共通の比較空間にする。解析入力のハッシュを結果に残す。
2. 外形を手動で粗く注釈し、GrabCutで背景と分離する。明るい金属の縁が背景と誤判定された箇所は前景の種を追加する。影は外形に含めない。最終輪郭の全面レビューは未完了。
3. 外形の二値画像とは別に、大津の方法による明暗二値化、輝度の4階調化、局所コントラスト補正とCannyの境界候補を保存する。二値化の白黒は高さではなく輝度を表す。
4. ハブ中心、顎センサー、翼端などの画像上の対応点を明示する。見えない深さは推定と記録する。輪郭注釈の6pxという値は暫定の作業上の幅であり、統計的に保証した信頼区間ではない。
5. 左右共通の形状パラメータとカメラを当てはめる。焦点距離、カメラ方向、投影中心を保存する。比較画像を縦横別々に引き伸ばしたり、画像だけ局所変形したりしない。
6. カメラを固定し、実際のメッシュ座標を補正する。外形の距離、対応点の距離、変形量への制約を併用する。タービンの領域は変形から保護し、X=0の連続性と左右対称性を維持する。
7. 外形だけでなく、翼の断面、胴体とのつながり、開口と内壁を構築する。面の分割は曲率を表すために使い、三角形ごとに無関係な材質を割り当てない。滑らかな面は法線を共有し、実際の鋭い角では分離する。
8. 同じモデルを通常材質、無彩色、隠面処理のあるワイヤーで描画する。ワイヤーを元画像へ重ね、面がどこに乗っているか確認する。簡易的な正面向き判定だけのワイヤーも履歴に残るが、最終比較画像には使用しない。
9. 同じモデルの正面、背面、上、下、左右、斜めの画像を確認する。正面の一枚だけに合う薄い模型や、不自然な裏側になっていないかを調べる。
10. 数値、目視、機構、材質を別々に判定する。共通機体が未合格のまま派生機やアイコンへ展開しない。

単一画像では、カメラと形状が異なっても同じ投影に近づけられる。今回の最適化は寸法への制約を含む仮説の調整であり、真の3D形状を測定したものではない。照明と材質が不明なので、陰影からの奥行き推定を正解として使用していない。

## 診断の読み方

初期の本体外形IoUは約0.855、対応点RMS誤差は約76.5pxだった。修正後の詳細値は最新JSONを正本とする。IoUは輪郭の重なりであり「3Dモデルの再現率」ではない。

今回の最終出力では、本体外形IoU 0.939、全パーツ外形IoU 0.936、全パーツの輪郭平均誤差8.10px、対応点RMS 26.5px。最大の対応点誤差は左翼端前側の68.5pxで、形状と対応点の双方を再確認する必要がある。画像空間の判定はFAIL。構造・比較処理の15試験はPASSで、結果は[診断試験記録](analysis/diagnostic-tests.json)に保存する。この2種類の結果を混同しない。

| 指標 | 意味 | 制約 |
| --- | --- | --- |
| 本体外形IoU | 本体の投影と参照の外形の共通面積÷和集合面積 | センサーなどの小部品を含まない。初期比較との継続用 |
| 全体外形IoU | Blenderが描画した全パーツのアルファから取った外形との比較 | 実際の外周に近い。内部の穴はこの指標では埋めて比較する |
| 輪郭平均・95%点誤差 | 双方向の輪郭間距離 | 局所的に大きなずれが平均に隠れるので差分画像も見る |
| 対応点RMS | 注釈した部位とモデル投影点の距離 | 当てはめに使った点でもあり、独立の検証データではない。翼端対応点に未確定箇所がある |
| ミラー誤差 | 実頂点と左右反転した頂点集合の最近距離 | 材質、部品の意味、全アニメーションの対称性を証明するものではない |

本体IoU≥0.95、輪郭平均誤差≤8px、対応点RMS≤12pxを暫定の数値基準として保持する。結果に合わせて基準を緩めない。この数値をすべて満たしても、マスクと対応点のレビュー、独立した開口形状の確認、材質・多方向・機構の承認は別途必要。

残課題は、翼端の角の対応と形状、ノーズと肩の面、吸気口の形状、タービンの埋まり方、パネルの密度と材質。隠れている底面を「参照どおりに復元済み」とはしない。基準形状が合格するまで役割別機構の統合とゲーム反映は保留する。

## 役割別デザインを戻す条件

- Scout: 少数の光学センサーと、側面全周の埋め込み走査帯。大きなカメラ群へ戻さない。
- Engineer: 下面の作業アーム。吸気口から出さない。収納時も輪郭を壊さない。
- Cargo: 実容積のあるベイ、開口扉、荷物。色違いだけにしない。
- Salvage: ウインチ、ドラム、ケーブル、吊り具。足裏と吊り荷の最低面を分けて検証する。
- Security: 下部の黒い半球型集約口、内蔵機関砲、上部のマイクロミサイル開口。交換兵装案は復活させない。
- Field: 支援用接続部と作業に対応した下面装備。Securityへ移したシルエット案を無断で戻さない。

コード内の役割関数は草案であり、このモデルには未接続。コマンドのrole指定はbaseだけを受け付ける。脚の展開、収納容積、扉と射出口、腕・吊り具の干渉を実際に検証してから役割別に有効化する。

## 再実行と試験

使用環境はBlender 5.2、Python 3系、NumPy、SciPy、Pillow、OpenCV。現在の画像解析依存は作業用のwork/visual-analysis-libsにも配置している。処理途中に旧画像と新メッシュを混ぜないよう、Blenderの完了後に比較を実行する。

```powershell
python tools/analyze_reference_family.py
# 保存済みのカメラ・形状・補正値を使用する再描画
blender --background --python tools/drone-design/blender/build_reference_family_v10.py -- --fitted --cage
python tools/fit_reference_projection.py --name latest --fixed-camera
python tools/build_reference_review_board.py
python tools/test_reference_reconstruction.py
```

カメラや補正値を再推定する場合は、補正済みのメッシュへ同じ補正を二重適用しない。まず`--fitted`だけのモデルを出し、対応する基準投影を保存してから補正を推定する。`fit_reference_surface.py`が参照する基準輪郭も同じ状態であることを確認する。日常の再描画で推定値を無条件に上書きしない。

自動試験の対象は、投影式とBlenderの一致、左右対称性、中心面の連続性、タービン変形の抑止、サンプル位置での変形の折り返し検出、有限な座標、正しい頂点参照、空でない描画、比較入力のハッシュ一致、指標計算と判定条件。試験PASSは「検証道具と限定的な構造検査が正常」の意味であり、再現性PASSでも全ゲーム試験PASSでもない。
