# 参照画像からの六面設計図とモデル照合

続き: [V13の断面修正と航空力学上の整合レビュー](../reference-airframe-v13/README.md)。
V13は比較候補であり、この六面図や元画像との一致を確定した最終モデルではない。

## 目的と判定

承認された斜視画像を基準に、立体モデルを修正する前の形状検討資料を作る。
既存モデルを六方向から描くだけでは、そのモデル自身の誤りを見逃すため、参照画像の観察とモデルの投影を分離する。

**現段階は未承認の寸法・形状仮説。画像との一致を確認済みとする資料ではない。**
六面図の寸法と断面の整合を確認した。画像に存在する正解の六面図を復元できた、実機として安定して飛べる、という意味ではない。
Minecraft のモデル・配布物・ワールドは変更していない。

## 観測と推定の区別

参照元は [承認画像](../blended-wing-v5/concept.png)。画像上では、左右の大型ダクト、流線形の胴体、翼端の折り上げ、埋め込み式のバイザー、肩の吸気口、後部フェアリングを確認できる。

一方、実寸、正投影の前後長、胴体の正確な厚み、翼の断面、底面、内部構造は一枚の斜視画像だけでは一意に決まらない。
六面図の翼幅比や断面は、見える形を解釈して置いた設計仮説であり、画像から直接取得した3次元測定値ではない。

図の青線はその設計仮説。橙色は特に未観測の内部・底面部品の仮配置、灰色は中心線または比較対象モデル。
青線だから確定、橙色だけが推定、という読み方をしない。
ダクト内の放射線はローター存在を示す略図であり、参照画像のブレード枚数・捻り角を確定したものではない。

特に、バイザーの折れ点と顎センサーの中心を、ともに機体対称面上の点だと決めつけない。
左右の見かけの翼端も、同じ物理的な角を見ているかを確認する。対応点の取り違えを、胴体の歪みで吸収しない。

## 六面と断面の整合方法

機体右を +X、前方を -Y、上方を +Z、対称面を X=0 とする。数値の単位はモデル作成用であり、メートルではない。

上面輪郭は片側の点列を反転して生成する。底面は比較しやすいように上面と同じく機首を上に置く。通常の第一角法・第三角法の配置を模倣した製図ではない。
左右側面は前後方向を反転し、同じ寸法を使う。正面・背面は同じ本体の投影外形を使うため、左右対称な外形自体は同じになる。

本体表面は前後方向の胴体上面・底面断面と、左右方向の翼断面を共通の規則で結ぶ。
正面・側面の外形は、その表面を投影した包絡線。表面の全ての見切り線や部品の遮蔽を描いた完成図ではない。
3つの断面は独立に描かず、同じ表面と上面輪郭を Y 座標で切り、タービン穴を除いて生成する。

後部 C-C 断面に離れた小片があるのは、後縁の切り込みにより、同じ前後位置で翼端と内側の翼が分離して見えるため。
機体の部品が浮いている、という意味ではない。

## 比較の読み方

比較図の灰色は V11 の `hull-mesh.json` を投影したもの。実際の候補メッシュを使い、比較のための個別拡縮・非線形変形はしていない。
灰色にはローター、吸気口周辺部品、バイザー、脚などの追加部品を含まない。図面側の断面は設計仮説であり、V11 の断面を重ねたものではない。

現時点では特に翼端の平面形・折り上げ位置、翼の前縁、胴体後端と厚みの差が見える。
ただし、青線と灰色の差を機械的にゼロにしても、元画像への一致にはならない。青線自体が仮説だからである。
元画像の視点への再投影と、部位ごとの観察に戻って採否を判断する必要がある。

## 検証結果と残る項目

15項目の図面生成・幾何整合チェックを実施した。左右輪郭・表面・正面投影の対称性、六面の共通縮尺、正の厚み、断面の輪郭内収容、断面からのファン穴除外、ファン円の輪郭内収容、ローターとリップの上下関係、比較 SVG の画像埋め込みなどが対象。
PNG の元画像注記、六面図、モデル重ね合わせも目視確認した。

これは画像忠実度やゲーム内品質の合格判定ではない。次の項目は未確定。

- 元画像の視点に再投影した場合の、翼端・ノーズ・タービンの同時一致。
- バイザーと胴体の接続、吸気口の奥行き、後部フェアリングの正確な断面。
- ブレードの捻り・厚み・実形状、外板の分割と陰影の対応。
- 脚展開時の高さ、収納時の干渉、役割装備の搭載、着艦時の下部クリアランス。
- 機器の実質量、重心、推力線、空力。見た目のバランスと実機の飛行安定性は別の検証。

## 今後の形状変更の手順

1. 元画像で、外形・段差・材質境界・影を分けて注記する。二値化は境界を見る補助であり、明暗を直接高さに変換しない。
2. 対応点と視点の解釈を検証し、六面図の寸法仮説を更新する。実寸が不明な間は翼幅比で比較する。
3. 同一寸法から全六面と断面を再生成する。特定方向だけを独立に変形しない。
4. 粗い立体を元画像と同じ視点へ再投影し、部位・輪郭・断面を照合する。輪郭の一致率だけで合格にしない。
5. 輪郭と量感が確定してから、バイザーの埋め込み、吸気口、ブレード、外板、脚の詳細を詰める。
6. 同じ立体から外板・UVの展開図を作る。曲面は継ぎ目なしに無歪みの平面へ開けないため、必要な分割線を定義する。
7. 役割別装備を搭載し、可動・収納・接地の整合を検証した後、ゲーム内表示を確認する。

この順序で、未確定な形状のまま表面ディテールを増やし続けることを避ける。

## 再生成

リポジトリ直下で、NumPy・OpenCV・Pillow を利用できる Python から `tools/build_reference_blueprint.py` を実行する。
生成処理は図面整合チェックに不合格があれば異常終了する。
現在の工具は Windows の Meiryo フォントと、既存の画像分析環境を使用する。ゲーム用ビルド処理とは独立している。
