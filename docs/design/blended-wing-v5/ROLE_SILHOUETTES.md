# 役割別シルエット改訂

最新の着陸・Scout走査・Security装着状態は[機構と状態の整合設計](MECHANICAL_STATE_CONTRACT.md)を参照。以下の多数カメラ構成と全Security共通の銃付き外観は更新対象。

## 最新修正: 吸気と装備支持を分離

[取付位置の修正版](outline-study/role-mounts-v4.png)。role-equipment-v3.pngでは吸気口に見える開口からアームや兵装が出ていたため、構造上の不整合として修正。Engineerは初回修正でも分離が不明瞭だったので追加修正した。

共通規則: 吸気・冷却流路を格納庫や支持部と兼用しない。Engineerの荷重は腕から肩軸、腹部横梁、中央胴体へ伝える。Securityは腹部専用兵装ポッド、Salvageは中央下面のウインチ支持枠、Cargoは中央荷室枠に接続する。装備支持と吸気口の間には連続した外装・隔壁を設ける。タービン直下の流路も塞がない。

修正画像は概念図であり、内部流路や収納容積を検証した断面モデルではない。モデル化時には吸排気経路、可動範囲、収納時の干渉、荷重支持、左右対称を確認する。ゲーム未反映。以下の旧画像の取付位置は採用しない。

## 最新提案: 役割装備と流線形を両立

[役割装備を戻した比較案](outline-study/role-equipment-v3.png)。ユーザー指摘により、輪郭差だけでは用途が伝わらないことを設計課題として追加。以前のFieldの均整の取れた翼形をSecurityのベースへ移す。極端に細いScoutと前方へ張り出したEngineerは取り下げる。

| ロール | 今回の提案 |
| --- | --- |
| Field | 短めの翼と簡潔な装備の汎用機。旧Securityの尖った形を転用しない |
| Scout | 太めの中央胴体、複眼カメラ、左右のセンサー窓、上面センサーフェアリングと対のアンテナ |
| Cargo | 本体と連続する荷室、開閉扉、荷物保持部を見せる |
| Engineer | 均整の取れた翼、収納式の左右作業アーム、中央の作業照射口 |
| Security | 旧Fieldの翼形を基準に、左右の機関砲と下面照射口。旧案の極端な機首・後部突起は不採用 |
| Salvage | 大型本体、腹部の実体ウインチ、中央ケーブルとフック、左右の支持脚 |

画像は装備を見せる展開状態の概念画。巡航時のアーム・フック収納、Cargo扉閉鎖、タービンとの干渉回避はモデルで定義する。装備を復活させても機体の左右対称を優先し、左右で異なる工具やセンサー配置にしない。機能追加・ロール変更や全兵器同時装備を決めたものではない。

以前の輪郭モデルの対称性検査は新しい画像や未作成のモデルへ継承しない。今回の画像の寸法・対称性・可動干渉は未検証。ゲーム未反映、承認待ち。以下は過去の提案記録。

| ロール | 流線形を維持する差 |

サイズ比、左右対称、下面機構、Dockや編隊との干渉は画像だけで確定しない。画像内の英文は仮コピーであり、航続距離などの性能変更を意味しない。ゲームには未反映。

| ロール | シルエット | 機能上の意味 |

## 確認・修正事項

- Field/Cargo/Engineerが遠方で似ないか、正面・上面・側面の黒い外形だけで比較する。輪郭に出ない腹部工具だけで差別化を完了しない。
- 概念図の小さな黒図には穴・線・発光色が残っている。最終識別試験では正本から純粋な外形マスクも生成し、装飾なしで判別する。
- Salvageの後方開口とウインチ・構造梁の関係、前後方向、実荷物の経路を同じモデルで確定する。概念画の斜め図と小上面図だけで一致としない。
- 3x3 Dockの外周、進入通路、縦積み、隣接Dock、接地、ローター回転域を検証する。大きい外観だけを既存の小さい当たり判定へ被せない。
- 全機体の間隔、異種混成Wing、回避、狭所、群の旋回、充電子機追従、Salvage牽引を再評価する。サイズ変更でナビゲーションや予約情報を不整合にしない。
- 既存の単一機体アイテム・ロール変更との関係を維持。装着変更直後に形状が変わる場合はDock内で干渉しないこと。新しい機体IDを外観のためだけに作らない。
- 小さいHUD記号とアイコンも承認された各ロール正本の外形へ合わせる。

ゲーム・機体サイズ・性能・アイテム登録は今回変更していない。派生形状の承認後に正本化と上記検証を行う。
