## 比較対象

- [既存Guard](../drone-family-a/reference-v5-nose-extended/guard/guard-hero.png): 従来の承認方向に沿うモデル。
- [不採用V4](../agile-family-v4/security/hero.png): 数値的な対称性は成立したが、魅力を失った試作。
- [新しい方向案](concept.png): 既存機の認識要素と、幅広・低背の翼胴一体形状を統合した概念画。

ユーザーはX-47の形が好みと指定。X-47A/Bのどちらかは未指定のため、今回はX-47Bを主な参考とする。Northrop GrummanはX-47Bを無尾翼の無人機として説明している。[メーカー資料](https://www.northropgrumman.com/what-we-do/aircraft/military-aviation-systems)、[米海軍の公式写真ページ](https://www.navy.mil/Resources/Photo-Gallery/igphoto/2002438380/)。公式写真の拡大画像取得は403となったため、その高解像度画像を寸法計測したとは扱わない。

実機の形状からの着想であり、空力・ステルス・推力性能をModへ再現したとの意味ではない。既存のホバリング、低速作業、着艦に合う独自のリフトタービンを残す。実機形状や塗装をそのまま複製する方針ではない。

## 失敗の分析

| 観点 | 既存機の良さ/課題 | V4で起きたこと | V5の修正 |
| --- | --- | --- | --- |
| 第一印象 | 幅広い翼と機械の密度。厚い肩部は重く見える | 細長い中央ブロックと4つの輪に分解され、一体感が失われた | 輪郭を幅広い一枚の翼として読み、中央だけ必要な厚みを持つ |
| 推進部 | 翼の中にダクトがあり、構造の一部に見える | 独立した円形ポッドが支持棒で付いて見える | 左右一対の開口を翼面へ埋め込む。外周の輪を主役にしない |
| ノーズ | 前方と側面へ続く埋込バイザー | ノーズを長くしただけで、巨大な上面が平板になった | ノーズは短く絞り、肩から翼端へ続く面構成で鋭さを出す |
| 重厚感 | 機能の密度と保護構造 | 支持棒と薄い部品により模型的になった | 翼根とタービン周囲で強度を表し、翼端は薄くする |
| 視覚的な整理 | 魅力はあるがフィン・段差が多い | 詳細を削りすぎ、役割の違いも裏側だけになった | 主面、機能の凹部、少量の小部品という階層へ整理 |
| 対称性 | 正本による検査が必要 | 頂点検査に合格しても格好よさは保証されなかった | 対称性を必須条件にし、その上で輪郭と機構の視覚評価を別に行う |

原因は「左右対称・低い・長い」という局所条件だけを満たし、全体の比率と既存の識別要素を失ったこと。V4に細かいテクスチャを追加しても根本解決にならない。

## 残す・変える・捨てる

**残す**: 黒鉛色と金属の明度差、前方から側面へ回る埋込バイザー、翼内の可視ブレード、中央下部の作業/兵装口、実用的な短い脚。

**変える**: 翼と胴体をつなぐ面、前縁の後退、翼端の折れ、上下面の厚みの配分。前方装甲の大きな箱は中央の低い保護面へ。

**捨てる**: V4の外付け四発リング、長い棒状ノーズ、役割に関係のない尾翼、外周を丸ごと光らせるリング、装甲面を覆うランダムな線。

## 正本モデルへ渡す契約

以下は画像から計測した確定値ではなく、次のモデル試作の目標比率。

| 項目 | 目標 |
| --- | --- |
| 全幅/全長 | 1.65〜1.9。現行Dockへの収まりは実ブロック縮尺で別途検証 |
| 胴体厚/全長 | 0.10〜0.15。脚と腹部装備は別計測 |
| 翼形 | 中央の厚い部分から薄い翼へ連続する後退翼。大きな垂直尾翼なし |
| 推進部 | 左右一対。開口の内壁、ブレード厚、固定支持部との隙間を明示 |
| ノーズ | 前縁と連続する短い先端。中央センサーは中心面上 |
| バイザー | 暗い窪みの中に細い発光面。前面から側面へ連続。外付け棒にしない |
| 翼端 | 概念画の立ち上がりは採用保留。基本は低い平面形状で検討 |

| 表面 | 大きい主面を残す。概念画の過剰な傷・細線は減らす |

X=0で片側から鏡面生成。中央部品、翼・開口・脚・発光面・装備原点・回転位相を検査する。左右逆回転のブレードは形状も鏡面にする。7方向と動作フレームを同じ正本から生成し、画像の左右を別々に解釈して造形しない。

## 全体デザインへの展開

共通機体を承認する前に、6ロールと23アイコンを同時量産しない。対象を減らすという意味ではなく、誤った共通形状を増やさないための順序である。

- Field/Scout: 共通の翼胴一体形状を最も素直に使い、センサーの機構で差を付ける。
- Engineer/Security: 腹部開口と埋込装備により区別。翼形を無関係な箱で潰さない。
- Cargo/Salvage: 中央下部の作業空間を拡張。荷物がある状態を含め脚・接地・視認性を確認する。二発で成立するかは別の造形検討事項で、全機二発を確定しない。
- Dock/機器/アイコン: 後退した面、埋込接点、大きい主面と少数の機能部という規則を共有。設備へ無意味な翼を付けない。
- UI/HMI: V4の操作・情報設計は継続。機体形状を画面へ装飾として大量に持ち込まず、後退した輪郭はマーカー等へ限定する。
- チャンクバスター: 幅広・低背と中央腹部照射口を引き継ぐ。小型機の単純拡大にはしない。

## 現時点の判断と残る承認

今回の概念画はV4より一体感と攻撃性が改善したと判断する。一方、左右の細部、羽根、下面、脚、翼端、Dockとの寸法は未合格。新しい正本モデルやゲーム用資産はまだ作成していない。

この方向の承認後、まず共通機1機だけを正本化し、既存機・不採用V4・新案を同じ投影/縮尺/照明で比較する。合格してから全ロール・全アイテムへ展開する。
