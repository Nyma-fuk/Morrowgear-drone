## 共通造形と機種差

幅広・低背、短いノーズ、翼胴一体、翼内のタービン、前方から側面へ続く埋込バイザーを維持する。機体の上に無関係な装置を積んで役割を表さず、下面・翼根の機能部へ収める。

| ロール | 固有部品 | 注意 |
| --- | --- | --- |
| Field | 最小限の中央サービス部 | 武装機の見た目にしない |
| Scout | 中央の複眼レンズと左右のセンサー | 大きい皿や片側アンテナにしない |
| Cargo | 低い荷室、シャッター、左右ラッチ | 接地余裕と収納可能容積はモデル段階で検証 |
| Engineer | 中央作業口と左右の収納工具 | 画像の橙色発光は採用せず、作業系の青緑に合わせる |
| Security | 対称の砲口/発射区画と中央照射口 | 使用可能兵装と装備表示を一致。AUTO以外へ全兵装を常時表示しない |
| Salvage | 中央ウインチ、荷物空間、強化脚 | 牽引最低面・接地・Dock適合を確認。画像だけで二発の機能成立を保証しない |

## 設備の制約

- Dockは支柱・壁なしで四方と上方から進入できること。画像の周縁の盛り上がりは低く抑え、脚と干渉させない。3x3と縦積みを維持する。
- サービスDockの3枠は前方中央1・後方左右2で左右対称と両立。子機格納寸法、回転中の干渉、灯具の個数と照度は未検証。
- コントローラーは表示面が手持ち時にユーザーへ向く。左右対称の本体と、右手/左手の表示変換は別に検証。
- チャンクバスターは後続機能の外観案のみ。船内、寸法、収納量、採掘、搭載機機能は未実装。二発の小型機を拡大しただけにならないよう、ベイ・構造・照射口・居住区の寸法を決めて再構成する。

## UI/HMIへの適用

機体の輪郭は小さなマーカーへ使う。画面を装甲で囲わず、地形、選択対象、指示、資源、作戦情報の読みやすさを優先する。機体所属と一時攻撃群を分離し、平常時のHUDは小さく、重大な変化だけを集約する。

[V4の全画面・操作仕様](../agile-family-v4/README.md)の機能範囲と、[通信設計](../DESIGN_RADIO_CARRIER_V2.md)の確定イベント・重要度・重複抑止規則は継続。今回の1画面の概念画が全UI実装を代替するわけではない。

## 画像レビューで判明した修正点

- ルート番号が2/2/3になっている。正しく1/2/3へ。画像から数値・座標・容量を実装へ転記しない。
- 下部HUDに不要な装甲フレームが描かれた。採用しない。バイザーは画面中央とホットバーを塞がない。
- UIのFUELは飛行電力と誤解されない表記へ。地図のkm目盛りは実際のブロック距離に合わせる。
- 英語コピー、追加ロゴ、台詞、装備数、弾数は仮。正式ブランドや音声の承認ではない。
- 回収ツールやモジュールの細部、レンズ配置、羽根に画像生成由来の左右差が残りうる。中央または対になる機構は正本で修正し、対称検査なしに合格としない。
- Engineerの橙発光は作業色へ変更。機種識別を色だけに依存させない。
- アイコンの32px/64px識別、手持ち、材質の実ゲーム照明、多数機、字幕の可読性は未検証。

派生案承認後は、共通機の正本化・7方向比較を先に行い、各ロールと設備・アイテムへ順に展開する。ゲーム反映前にはモデル、外観、保存・機能の各検証を分けて記録する。
