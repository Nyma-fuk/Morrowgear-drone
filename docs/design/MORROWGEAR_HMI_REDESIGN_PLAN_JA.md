# Morrowgear 全画面HMI再設計・実装・検証計画

作成日: 2026-09-24

状態: 設計提案。実装済み・実機試験PASSを意味しない。本書の作成ではゲームの変更・差し替え・操作は行わない。

## 1. 結論と設計目標

現状は機能が多数存在する一方、「誰に」「何を」「どこで」「なぜ実行できないか」「命令がどう処理されたか」を画面間で追跡しにくい。配色や装飾の更新だけでは解消しない。情報の範囲、選択、命令、結果確認を共通化したうえで全画面を再構成する。

最優先の利用目的は次の4つとする。

1. 全機・Wingがどこで何をしているかを把握する。
2. 個体・Wing・複数対象の任務や目的地を容易かつ確実に変更する。
3. 行動していない理由を理解し、その場から解決操作へ進む。
4. プレイ中は視界を守り、重要な変化だけに気づける。

警報だけを集める画面にはしない。正常に任務を遂行している機体も、全体一覧から常に探せるようにする。

## 2. 調査範囲と根拠

対象はJava版の現行クライアント実装、関連メニュー、既存HMI設計資料、共有された実ゲーム画像。ブラウザーのHTML案を実装の証拠として扱わない。全画面の実機操作を今回完了したわけではなく、以下の設計案は今後の実機検証を必要とする。

主な実装根拠は `src/client/java/jp/morrowgear/drone/client/` の `TacticalDashboard`、`TacticalScreen`、`VisorHudOverlay`、`DockScreen`、`SupplyNetworkPanel`、`CarrierScreen`、`OperationHistoryScreen`、`OperationSubtitleOverlay`、`HmiContainerScreen`。コンテナー契約は `DockMenu`、`CarrierMenu` も対象とする。

確認できた主な問題:

| 事実・観察 | HMI上の問題 | 改善方針 |
|---|---|---|
| コントローラーとバイザーの機体取得にプレイヤー周囲256ブロックの読み込み済み実体検索がある | 「全機」「ONLINE」が登録機体全体と誤解される | 登録全体・受信中・最終確認を区別 |
| 指揮画面ヘッダーのディメンション・リンク正常表記に固定文字列がある | 実状態と違う安心表示になり得る | 実データから表示、取得不能は不明 |
| クイックRETURNはプレイヤーへ戻す命令、Dock帰還は別命令 | 帰還先が読み取れない | 「プレイヤーへ集合」「Dockへ帰還」を分離 |
| クイックMISSIONは機体行を並べるページへ移動する | 任務を変更するつもりの操作と結果が違う | 任務選択を直接開く |
| 一部の送信通知はサーバー受付前に表示される | 成功・実行中と誤認する | 送信と受付と実行を分離 |
| Dockの状態・補給・在庫が巡回ボタンで分割される | 不足資源と補給元を比較しづらい | 機体要求とDock供給を同時表示 |
| 母艦の主操作が位置関係で移動と準備に変わる | 同じ位置の操作の意味が予測しづらい | 操作名と実行手順を明示 |
| 過去の実ゲーム画像では極小文字・広い余白・ラベル重なりが発生 | 数値上収まっても人が読めない | 実解像度で読み取り・操作検証 |

敵数については、ヘッダーがすべての生物を敵として数えているわけではない。`Enemy` 判定と戦闘側の脅威判定の一致は別途確認する。自動試験のPASS件数は使いやすさの証明には使わない。

## 4. 共通の情報・操作契約

### 4.1 情報を混ぜない

個体には「所属Wing」「本来の任務」「現在の行動」「一時離脱理由」「次の予定」「位置」「資源」を別項目として持たせる。

例: `Wing-02 / 東ルート哨戒 / Dockで補給中 / 機銃弾不足 / 補給後に哨戒へ復帰`。REJOINのような内部状態名だけで説明を終えない。

全体数は、所有・閲覧権限のある登録機体数、受信中機体数、最終確認のみの機体数を区別する。登録情報を提供するサーバー契約がない段階では「周辺で確認した機体」と表記し、全世界の機体一覧を装わない。

情報には安定したUUID、ディメンション、更新時刻、取得範囲、利用可能な操作を付ける。未読み込み・通信切断・破壊済みを同じ「不在」にしない。画面を開くためだけに遠方チャンクを強制ロードしない。

### 4.2 選択ルール

- 一覧と地図の選択を同期。クリックで単独選択、追加選択、範囲選択を提供する。
- Wing選択とWing内の一部選択を区別。「2 Wing・計12機」「Wing-02の3/8機」のように表示する。
- ALLは「登録全機」「このディメンション」「絞り込み結果」のどれかを明記する。初期値は指示可能範囲内の全件とし、画面外に隠れた選択数を示す。
- フィルター変更で選択を無断拡張しない。選択を絞り込む操作は明示的に行う。
- タブ移動・並べ替えで選択、スクロール、地図位置を維持。破壊・権限喪失は選択の無効化理由を表示する。
- 更新順に行が飛び回らない。手動ソートか安定ソートを使い、重要度変化はバッジで知らせる。

### 4.3 命令のライフサイクル

`下書き → 送信中 → 受付済み / 一部受付 / 保留 / 拒否 → 実行中 → 完了 / 中止 / 失敗` を別状態にする。

命令IDと対象UUID集合を固定して送る。サーバーは対象ごとの結果・理由・対象任務を返す。再送は同じ命令を重複実行しない仕組みを使う。通信タイムアウトは「結果未確認」とし、成功や失敗を推測しない。破壊命令を無条件に自動再送しない。

通常移動は `選択 → 地点指定 → 移動を指示`。習熟者向け直接操作は任意設定にし、初期操作でダブルクリックが危険な命令を即発行しない。地図のパン・選択・地点編集の入力を分離する。

「下書き取消」と「実行中任務の中止」は別操作。Escapeは下書き解除、次に画面を閉じる。補給設定等の未保存編集では破棄確認を行う。全停止と選択対象停止も区別する。

ボタンの描画、操作可能条件、クリック領域は同じ定義を使う。非表示・無効ボタンが入力を受けないことを試験する。

### 4.4 行動できない理由

飛行電力、レーザー電力、機銃弾、ミサイル、熱、機体・機構損傷を分離する。存在しない装備を0%警告しない。資源不足と任務不適合と予約待ちを別理由にする。

「出撃可能」は武器残量の平均から算出しない。実際のサーバーの任務別出撃判定・AUTO代替武器・飛行予備電力と同じ根拠を表示する。HEAT上昇を勝手にDock帰還理由にしない。

理由には解決操作を結ぶ。例: `機銃弾が不足 → Dock在庫を確認`、`予約待ち → 待機列を表示`、`帰還先消失 → 再割当状況を表示`。未実装の解決操作を押せるように見せない。

## 5. コントローラーの再構成

### 5.1 通常の指揮画面

左: 機体・Wing一覧。中央: 地図。右: 選択対象の詳細と任務操作。上: 薄い全体要約。下: 地図編集時だけ出る入力欄。通常時の大きな下部ボタン領域は廃止する。

地図は十分な幅を確保し、未選択時の右欄は縮める。空欄を飾りのパネルで埋めない。地形は淡く、味方・敵・目的地・経路を前に出す。凡例とレイヤー切替を設ける。

左の行には名前、役割、任務、現在行動、例外を表示。資源の全数値は選択時に展開し、通常行は不足資源だけを示す。Wingを展開すると構成機を確認できる。

右欄上部は対象名と選択数。次に現任務・目的地・現在行動・復帰先、その下に資源。操作は「移動」「任務変更」「Dockへ帰還」を軸に、対象が実行できるものを出す。プレイヤー集合・追従は同じ操作として混同しない。

### 5.2 任務とルート

任務一覧は、目的、実施場所、参加Wing・機体、進捗、停止理由を任務単位で表示。クリックで地図上の対象任務を選択し、変更できる。

ルート編集中は地図と点一覧を同時表示。各点の座標・高度、閉路、開始候補、航行方向を表示する。1点は周辺哨戒、2点は往復、3点以上は周回という意味をアイコンと短い名称で示す。

点の移動・挿入・削除・並べ替えを確定前に行う。編集中の案と実行中の経路を線種で区別。編集取消で実行中経路を失わない。

採掘・伐採は作業範囲、担当Engineer、調査共有、回収Cargo、搬送先が分かるようにする。役割不足は即失敗と決めつけず、実際に可能な縮小運用と不可能な部分を表示する。

### 5.3 Wing編集

8スロットのカードと未所属一覧を維持する。役割アイコン、名前、任務参加状態を表示。D&Dの移動先候補・満員・権限不足を事前表示する。

クリック選択後の「Wingへ移す」「離脱」「新規Wing」も用意し、D&Dだけを必須にしない。移籍はサーバー確定まで仮表示とする。満員なら全件成功を装わず、受付対象と拒否対象を示す。

所属変更と一時戦闘群・コホートの変更を混同しない。補給・戦闘離脱中でも正式所属を保ち、一時行動は補助表示する。任務中の移籍では引き継ぐ任務と合流予定を表示する。

## 6. バイザー・HUD

通常は小さな機数・例外要約と必要な近傍マーカーのみ。全体把握と命令はコントローラーへ任せる。視線中央、ホットバー、字幕、チャットとの競合領域を予約する。

注視が一定時間続いた個体を展開し、注視が外れても短い猶予を設ける。固定対象は視線で入れ替えない。遠方になった場合も最終受信時刻付きで保持し、最新位置と誤認させない。

複数戦線では「北側: 敵12・交戦5」「東側: 敵4・対応不足」のように集約。詳細は選んだ戦線だけ展開し、誰がどの敵に攻撃中かを短い接続線・対象ラベルで示す。全機の線を常時重ねない。

機数増加で位置・レイアウトを頻繁に切り替えない。固定領域内で個体→Wing→戦線へ集約し、増減の境界に猶予を設ける。手動で個体を固定した操作を自動集約で解除しない。

マーカーは補間された実体位置と現在カメラから投影し、画面端・背後・遮蔽物・距離を区別する。ラベルの位置調整と機体位置を示す点を分離し、点まで遅れて追従させない。

LOSTは破壊・回収・復旧で適切に消え、古いビーコンは最終確認として表示する。全距離可視性は同ディメンションの位置表示と異ディメンションの場所案内を分ける。サービスDockは空き枠、充電能力、利用中かだけを通常表示する。

## 7. Dock・補給網・回収

Dockは一画面で「接続機が必要とする量」と「Dockが供給できる量」を比較する。状態・補給・在庫のページ巡回を主動線にしない。

上段: 接続機・予約機・待機数。中央: 飛行電力、レーザー、機銃、ミサイルの要求と供給。下段: 用途別スロットとプレイヤー在庫。長い在庫詳細だけを別表示にする。

ゲージには分母の意味を明記する。Dock容量、機体満載分、未開封補給品、開封済み残量を混ぜない。補給品1個から何発・何電力に変換するかは実際の補給ポリシーから表示する。

補給先の予約、接近、着艦、補給、再出撃待ちを表示。資源切れなら「補給停止: ミサイルラック不足」とする。待機列と長期駐機で枠が空かない場合も説明する。UIから飛行判定を勝手に変更しない。

補給網は監視一覧を入口にし、編集時は補給元→Dock、最低在庫、優先度、担当運搬状況を一つの流れにする。現在の近傍容器選択・256ブロック制約・所有権条件を隠さない。最低在庫の単位がアイテム数か補給量かをポリシーと照合して確定する。

保存前には変更差分を表示。保存中の連打、古いサーバー状態による上書き、運搬中の経路変更を扱う。荷物が積載済みなら、停止が破棄を意味しないことを説明する。

回収画面は `発見 → 回収機手配 → 接近 → 吊り上げ → 搬送 → Dock待ち → 補給・修復 → 任務復帰` の実状態を表示。対象消失・Dock破壊・回収機電力不足の代替処理も追えるようにする。「回収完了」を任務復帰完了と混同しない。

遠隔閲覧からネイティブ在庫を無条件操作できる設計にはしない。距離・権限による操作可能範囲を明示し、必要なら現地へ移動する案内を出す。

## 8. 母艦

### 8.1 全体構成

入口は概要。常設の任務状態帯と「移動」「採掘」「攻撃」「貨物」「補給・子機」「船内」を用意する。診断は詳細メニューへ分離。狭い画面ではパネルを切り替えるが、操作名と順序は変えない。

### 8.2 採掘

地図でチャンクを選ぶと16×16の境界、チャンク座標、掘削開始高度、到達する下限、母艦現在位置を表示する。未観測地形の深さや回収量は推測値と明示し、正確な予測を装わない。

手順は `範囲選択 → 内容確認 → 採掘を指示`。移動が必要なら「対象へ移動して採掘」と明示し、内部的な移動・準備をユーザーに推測させない。実装が連続指示を未対応なら「対象へ移動」「到着後に採掘開始」を別操作として明示する。

実行中は移動、地形確認、充填、放出、掘削、収納、完了の実際に存在する段階を表示。実データがない演出段階をタイマーだけで完了扱いしない。残りの掘削対象と停止理由を表示する。

確認範囲・内容が変わったら確認を失効させる。中止によって止められる段階と、既に放出された攻撃等で止められない効果を明示する。UI改善を採掘挙動の成功と見なさない。

### 8.3 攻撃・移動

攻撃は対象と範囲を地図で確認し、敵性、距離、照射可否、巻き込みリスクを表示する。範囲攻撃と単体指定の違いを明示する。対象死亡後の再選定・終了方針は実際の戦闘仕様と一致させる。

移動は水平地点と絶対高度を一緒に設定し、地表との距離も取得可能な範囲で示す。指示後は向き、目的地、残距離、迂回・停止理由を表示する。到着不能を移動中表示のまま放置しない。

### 8.4 貨物・補給・船内

貨物は実際のアイテムスロットとページ位置、空き容量、満載による作業停止を表示する。持ち上げ中のページ変更、Shift移動、連打、再接続で複製・消失しないよう現行コンテナー契約を維持する。

補給では母艦自身と子機向けの資源を区別。子機4枠は各枠の機体、予約、接近、補給、発進を表示し、予約解除の影響を示す。

船内は乗る・降りる・招待権限を分ける。距離不足、母艦消失、船内所持品の回復は独立した状態として説明する。通常の利用画面に診断コードを並べない。

## 9. 設定・機器・字幕・履歴

設定は「表示」「操作」「通知」「アクセシビリティ」。文字サイズ、HUD密度、背景濃度、強い発光・点滅、色の補助表示を調整可能にする。設定変更はプレビュー可能で、既定値へ戻せる。

機器は用途別に分類し、日本語名、役割、対応機器、補給品の用途を表示。内部IDは詳細へ移す。クラフト案内は実レシピから取得できる場合だけ掲載し、手書きデータの乖離を避ける。

字幕は主体・出来事・必要行動を短く示す。正常な反復報告は既定で抑制。重要報告を件数集約し、切替が速すぎて読めない状態を防ぐ。操作画面中は画面内通知へ渡し、重要な結果を消さない。

履歴は対象・種類・重要度で絞り込み、対象位置や詳細へ移れるようにする。閲覧中に行をずらさず「新着N件」を表示。履歴を開いても元の選択と地図位置を失わない。音声追加は本計画に含めず、字幕と履歴を先行する。

## 10. 見た目・レイアウトの共通基準

- 基本は高コントラストの暗い操作面と細い構造線。HUDだけ透明度を高める。全面Blurは必須にせず、描画負荷を測る。
- シアンは選択・操作、赤は危険、アンバーは注意。資源種別は名称・アイコンでも示し、色だけで状態を伝えない。
- 装飾用の極小英語や省略語を主情報にしない。「帰還」「待機」のように曖昧な語は目的地・理由を付記する。
- 通常文字は1080p実ピクセル表示で概ね16〜20px相当を出発点にする。ただし字体と日本語可読性を実機で判定し、数値だけで合格にしない。
- フォントの縮小変換で帳尻を合わせず、整数倍率・画素位置を確認する。収まらなければ折り返し、列削減、パネル切替を使う。
- 1920×1080では地図の有効領域を主役にし、左右パネルは内容に応じて折りたたむ。1280×720では詳細を切替表示し、文字を縮めない。
- 操作対象は十分なクリック領域を持ち、ホバーで寸法を変えない。スロットはMinecraftの操作規則を維持する。
- 既存のモチーフや機体シルエットは活用するが、画面背景の装飾より機体・対象・行動の識別を優先する。

### 12.3 人が使えるかの受入基準

以下は今後測定する目標であり、達成済みの値ではない。

- 初見利用者が、画面を開いて約5秒以内に選択対象・現在任務・主要停止理由を説明できる。
- 通常移動は選択済みから2操作程度、任務変更は種類に応じた必須入力だけで完了できる。
- 補給待ちの機体について、不足資源と対応Dockを説明できる。
- 複数Wingのうち任意の1 Wingだけに命令し、他Wingに影響しないことを確認できる。
- 母艦の対象チャンクと破壊範囲を、実行前に利用者が説明できる。
- 支援なしで主要タスクを完了できるかを観察し、迷った箇所・誤操作・読めない箇所を記録する。
- 誤った破壊範囲や他人の機体への命令、アイテム複製・消失は1件でも不合格。

開発者だけの試験は操作知識による偏りがある。可能なら初見利用者を含める。参加できない場合は「初見での使いやすさ未検証」と明記する。

## 13. 懸念と対策

| 懸念 | 対策 |
|---|---|
| 大きな再設計で既存機能を消す | 現行操作→新しい入口→試験IDの移転表を作る |
| UI独自の出撃・敵性判定 | サーバー理由コードと既存判定を使う |
| 全機表示で強制ロード・通信負荷増大 | 登録情報と実体を分離。差分更新・更新頻度・購読範囲を設計 |
| 毎フレーム全機同士を比較 | 集約・ソート・衝突回避の計算頻度を分離し測定 |
| 画面変更で戦闘挙動まで変わる | 指示経路と表示変更を分け、挙動変更は別理由・別回帰試験 |
| 自動集約が操作対象を変える | 選択・固定は安定。集約は表示だけに適用 |
| 極小文字へ逆戻り | 最小可読性の実機画像と読取り試験を受入条件化 |
| 旧クライアント・サーバーとの差 | 未対応能力を検出し操作不可理由を表示。更新互換性を試験 |
| 遠隔情報から他人の位置を漏らす | サーバーで所有権・閲覧権限を絞る |
| 試験PASSが外観の完成扱いになる | 自動試験、通常UI操作、視認性、利用者評価を別判定 |
