# 母艦貨物庫のページ化

## 容量と保存

- `CarrierCargoStorage` は 64 ページ、各 54 スロット、合計 3,456 スロットの有限貨物庫。
- 全スロットが 64 個積載可能なアイテムなら最大 221,184 個。異種アイテム、積載上限 16 個、非スタック品では個数が減る。高さ 4,096 の全チャンクを必ず収納できる仕様ではない。
- 旧 `cargo` 配列の順序を保ち、従来の 54 スロットは先頭ページとして読み込む。新しい保存も同じ配列を使い、末尾の空スロットのみ省略する。
- `ItemStack.OPTIONAL_CODEC` で名前、耐久値などのコンポーネントを保持する。通常投入の `setItem` は `min(64, itemMax)` を上限とする。
- 対象の Minecraft 26.2 の標準 Container 上限は 99。母艦貨物庫はサーバー全体、ページ表示、クライアント表示の上限を明示的に 64 に揃え、独自コンポーネントで 99 個積載可能な品も 64 個までとする。通常の 64 / 16 / 1 個の品は標準と同じ上限になる。
- 旧 `CarrierInventory` は削除し、保存・収納試験も実際の `CarrierCargoStorage` に統一した。

## ブロック単位の差分収納

`plan` は空きスロット索引と同種アイテムの未満載スロット索引を使い、変更対象だけをコピーする。コンポーネントの異なる品は結合しない。同一ブロックのドロップが全量入らなければ、収納内容を一切変更せず `FULL` で停止する。

計画は作成元、更新番号、変更前の内容を保持する。別貨物庫への流用、古い計画、二重コミットは拒否する。`CarrierWork` はブロック除去直前に `canCommit` を確認し、単一サーバースレッド上で除去と差分収納を実行する。ワールドのチャンクと SavedData をまたぐディスク上の原子的保存まで保証するものではない。

補給品の検索は専用入力を優先し、貨物庫へのフォールバックでは `findFirst(Predicate<ItemStack>)` が使用中スロットのみを見る。Predicate は読み取り専用とする。貨物庫が全て使用中なら最大 3,456 スロットの検索になり、空きページがある場合の不要な走査を省く方式である。

## メニューとページ変更

- 表示・同期は貨物 54、補給 5、プレイヤー 36 の合計 95 スロットを維持。クライアントへ全 3,456 スロットを送らない。
- 経路は既存 `CarrierCommandPayload.Action.CARGO_PAGE` のみ。専用のページ変更 Payload は追加しない。
- `x=requestedPage`、`y=expectedStateId`、`z=expectedCurrentPage`。ページ番号は 0 始まり。
- 現在のメニュー ID、船 ID、所有者、アクセス権、stateId、現在ページ、要求範囲をサーバーで検証する。持ち上げ中のアイテムがある場合は変更しない。
- 許可時は新しい containerId のメニューを開く。ドラッグ状態をリセットし、旧メニューへのクリックを拒否する。失敗時は現在の表示範囲を再同期する。
- 同じ船のページ変更で貨物タブを維持する。表示を先読みで別ページへ付け替えず、サーバーのページを採用する。
- Shift 移送は現在ページだけを対象にする。プレイヤーからの投入は適合する専用補給入力を優先し、残りを現在の貨物ページへ入れる。

## 検査と計測

`CarrierCargoStorageTest` は旧保存、最終ページ、容量境界 221,184 個、アイテム上限、コンポーネント、同一入力の重複、部分収納拒否、stale plan、二重コミット、ページ境界、補給検索を検査する。`CarrierSavedDataTest` の収納試験も新 Storage を使用する。

`cargo.metrics()` の累積差分で、計画数、失敗数、候補スロット数、スタックコピー数、コミット数、変更スロット数、索引更新数、計画処理時間と最大時間、補給検索回数と検索スロット数を取得できる。全体同期や保存用の `snapshot()` は採掘の計画・コミット経路に使わない。

16,384 ブロックから各 1 個の同種品を収納する試験では、候補確認 16,384 回、コピー最大 49,152 回、差分更新 16,384 スロットを上限とする。これは演算量の回帰検査であり、実機の 2 ms 内完了を保証する値ではない。通常のページ切替・投入・取り出しによる全チャンク実証と全件 Gradle の実行結果は親タスクで確認する。
