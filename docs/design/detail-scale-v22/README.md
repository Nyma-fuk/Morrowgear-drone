# V22：機体ディテール・HUDアイコン・実寸Dock

## 今回の成果物と適用範囲

承認済みのV21一体型機体を正本として、6機種の表面ディテール、HUD用アイコン、5×5ブロックのDockを作成する。新しい画像生成で輪郭を描き直さず、Blenderの同一メッシュから比較画像・アイコン・GLBを出力する。

**このフォルダーはデザイン確認用。現在のゲーム用リソース、Entityの当たり判定、既存ワールド、LauncherのJARは変更していない。** 見た目だけ拡大し、衝突や着艦位置が旧寸法のままになる状態を避けるため、ゲームへの移行は後述の契約をまとめて適用する。

## デザイン

- 薄い主翼、左右対称の胴体、2基のダクテッドファン、機体に埋め込んだバイザーを維持する。
- ファンの整備リム・固定具、前部と翼面の点検パネル、開閉ロックと小さな安全表示を追加する。点検パネルは機体の曲面に沿わせる。
- 役割装備はV21を継承する。Scoutは埋め込み光学系、Cargoは一体型貨物庫、Engineerは格納式アーム、Securityは内蔵兵装と下面レンズ、Salvageは内部ウィンチを使う。
- 新しい常時発光線を増やして輪郭を埋めない。青系は通常の機体発光、安全表示は小面積のアンバーとし、戦闘・警告の状態色とは区別する。
- 回転するScoutの走査点は演出であり、一瞬ごとの左右対称性を要求しない。構造メッシュの対称性とは別に検証する。

## 寸法の定義

「3×3」は機体を正方形に引き伸ばす意味ではなく、**水平外形が3×3ブロックに収まる最大寸法**とする。6機種とも翼幅を3ブロックに合わせ、機種ごとの縦横比は維持する。脚と装備のアニメーションも外形の検査対象に含める。実測値は各機種の `validation.json` に記録する。

| 項目 | 設定 | 理由 |
| --- | --- | --- |
| モデルの単位 | 1 Blender unit = 1ブロック | 表示倍率と着艦寸法を混同しない |
| 機体の水平最大外形 | 3×3以内 | 指定サイズに統一しながら機種の比率を維持 |
| 機体の原点 | 水平外形中心・着陸時の足裏接地面 | 装備の厚みで着艦位置が浮かないようにする |
| Dock本体 | 5×5 | 機体の周囲に整備用の余裕を持たせる |
| 推奨配置ピッチ | 中心間7ブロック | 隣接する5×5Dockの間に2ブロックの間隔を確保 |
| 中央着陸面 | 高さ0.30ブロック | 低床の一体型デッキ |
| 接点上面 | 高さ0.3155ブロック | 着陸脚の接地先。胴体底面とは区別 |
| 支柱 | なし | 上方・側方から進入可能な外形を維持 |

5×5と7×7は別の本体サイズではない。今回は本体を5×5に決め、7×7は基地で並べる際の推奨配置範囲とする。

Dockの周辺設備を横切る際は、最下部の足裏が外周上面を十分に越える位置を通過し、中央に入ってから接点へ降下する。外周の高さだけでなく、機体の脚・展開装備・傾きも考慮する。図の静止した着艦姿勢の成立は、任意の姿勢で障害物を回避できることの証明ではない。

## HUDアイコンの使い分け

| 種類 | 用途 | 作り方 |
| --- | --- | --- |
| 立体アイコン | 機体詳細、所持品、ユニット一覧 | V22の正本メッシュを同じカメラから描画 |
| 機影アイコン | 地図、方位、Wing表示 | 正本モデルの上面投影のアルファを白い機影に変換。機首を上に統一 |
| 役割記号 | 近接HUD、小さなユニット表示 | 光学系・貨物庫・作業アーム・兵装・ウィンチを抽象化した左右対称の記号 |

Fieldは汎用支援を示す四隅と十字、Scoutは光学レンズ、Cargoは二段の貨物庫、Engineerは左右の作業アーム、Securityは盾と弾薬を示す3本の弾形、Salvageはウィンチと吊り具とする。役割記号はモデルそのものの投影ではなく、用途を読ませるための意味記号である。Securityに医療系の十字を使わず、Fieldとの見分けをつける。

PNGは24・32・48・64・128px、役割記号はSVG正本も用意する。小さい表示では立体画像だけで役割を識別させず、役割記号を併用する。HUDの文字を縮小して合わせる運用はしない。密集時はWing単位に集約し、個体表示を増やし続けない。

役割と状態を混同しないよう、白いマスクへ現在の状態色を適用する。たとえばSecurityであることだけを理由に常に赤くしない。通常・警告・戦闘・通信不明などの状態色は、既存HUD側の状態判定を使用する。

## ゲームへ移行する際の必須条件

現行コードで確認した前提は、機体Entityが幅1.45・高さ0.7、Dockが9個のパーツからなる3×3構造、着艦高度の基準が0.29である。新寸法を単独の表示倍率として適用しない。

1. **機体表示と当たり判定**：実メッシュの縮尺を正本にする。3×3の水平寸法、姿勢による外形、展開装備、地上の脚を考慮した衝突と経路探索を同時に更新する。貨物吊り下げ時は吊り荷を含めた最下部を使う。
2. **機構アニメーション・材質**：現行のMGM描画はローター中心の回転を扱う一方、V22のGLBにある脚・ハッチ・アームの可動階層をそのまま読み込む実装ではない。表示形式を変換するだけで可動機構が動くとは扱わない。GLBの再読み込み試験は形状・可動位置の確認であり、Blenderの手続き型ノードを含む材質の完全再現は保証しない。ゲーム側の表面質感は必要なテクスチャへベイクし、発光を分離して照合する。
3. **Dock配置**：新設は5×5の全25セルを事前検査してから配置する。設置失敗は無消費・部分生成なしとする。破壊時は中心と全周辺を1つのDockとして扱い、アイテムの重複ドロップを防ぐ。
4. **保存互換**：既存3×3Dockの中心ID・所有者・機体UUID・在庫・バッテリーを維持する。旧パーツIDを新しい座標に読み替えない。ロード時に勝手に周囲16ブロックを置換しない。旧版の寸法を保存データで識別し、明示的な改築時だけ空き領域を検査して拡張する。
5. **着艦・発艦**：全6役割、脚展開、上方進入、前後の側方進入、縦積み、狭い基地、隣接Dock、荷物牽引で検証する。旧サイズのDockへ新サイズ機が無条件に着艦できる扱いにしない。
6. **飛行・編隊**：分離距離、追従、円軌道、隊列参加、Recovery、戦闘中の一時群、充電子機の追従点を機体サイズと照合する。隊列の状態遷移やWingの所有権は外見変更で書き換えない。
7. **各作用点**：機関砲口、レーザー口、スキャン、回収ケーブル、軌跡、照明の位置を新しいモデル座標から変換する。表示だけ旧機体の位置に残さない。
8. **アイコン**：HUD・戦術画面・アイテムの用途ごとに必要なサイズを選ぶ。遠近投影、遮蔽、画面外表示、文字サイズ、既存の表示優先度を壊さず導入する。
9. **多数機の性能**：この正本をそのまま100機同時表示できると仮定しない。近距離用・遠距離用の形状とマテリアルを整理し、ローター・可動機構・発光パスを含めた負荷を実機で測る。アイコンは事前描画したPNGを使い、HUDのために機体を毎フレーム別描画しない。

現在の旧Dockを5×5へ無断拡張せず、まず見た目と寸法を確認する。次のゲーム実装では上記を完了したうえで、既存の戦闘・復帰・補給・航行・サルベージの回帰試験を実施する。

## 検証と限界

- 左右対称性：6役割の構造メッシュを11姿勢で照合する。走査点など `FX_` の動的演出は構造対称性から除く。
- 水平寸法：120フレームの展開・格納動作を検査する。保守的な境界箱で超過候補を検出し、候補は実メッシュで再検査する。
- 着艦：全6機種の接地、足裏と接点の範囲、Dock内への収まりを検査する。
- 表示：正面・背面・上面・底面・左右・斜め・装備展開・着陸の画像を確認する。
- 書き出し：GLBを読み直して、11姿勢の部品名と境界寸法を元のBlendと照合する。
- アイコン：透明度、画像端での切れ、サイズ、暗色／明色背景、実寸の24・32・48px見本を確認する。

結果は `output-checks.json`、`export-roundtrip.json`、`dock/fit-checks.json` および各機種の `validation.json` に記録する。これらは実ゲーム試験、航空力学の検証、全姿勢の連続衝突判定、人による大規模な識別性評価の代用ではない。

## 再生成

`tools/drone-design/blender/build_detail_scale_v22.py` をBlenderで実行する。次に `tools/drone-design/blender/verify_detail_scale_v22_export.py` をBlenderで実行し、`tools/review_detail_scale_v22.py` でアイコンと比較シートを生成する。V21正本は変更しない。

ゲームの `build` タスクはLauncherへの同期につながるため、このデザイン確認の手順では実行しない。

## 今回の結果

- 6機種の構造対称性と寸法検査：PASS。各11姿勢を照合し、水平外形は各120フレームを検査。
- 6機種の着陸位置・足裏と接点パッドの範囲：PASS。接点をX方向の±0.45ブロックに配置して脚の位置に合わせた。
- 6機種のGLB再読み込み：PASS。部品の境界寸法の最大差は約0.00000018ブロック。
- Dockの左右対称性・GLB再読み込み：PASS。外形5×5×0.41ブロック。
- アイコン105枚・役割記号SVG7点、画像端での切れ、参照元Blendが未変更であること：PASS。
- 6機種の9方向・状態比較、細部拡大、Dock上の着艦姿勢、アイコンの実寸見本を目視確認。

実ゲームへの導入・操作確認・当たり判定・既存セーブ移行の試験は未実施。上記のPASSはモデル／成果物の検査結果に限る。
