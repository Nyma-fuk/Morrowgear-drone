# 作戦通信・補給網・母艦の統合契約

更新日: 2026-09-22。実装中の契約書。記載した条件は、試験結果の記載がない限り検証済みを意味しない。

## 決定事項

- 作戦通信、自律補給網、チャンクバスターを同じ開発単位で統合する。
- 母艦の船内は専用空間とする。船体の移動と建築物の保存を分離し、母艦の識別子で結び付ける。外の景色を窓越しにそのまま表示する方式ではない。
- ミサイル1発の対エンティティ基本爆発ダメージを従来の50%とする。爆風半径や斉射数はこの調整で変更しない。防具等の後段処理、複数弾の重複によって最終HP減少率は異なり得る。
- 機関砲、レーザー、マイクロミサイルは専用補給アイテムを消費する。通常の鉄塊や花火を弾薬として直接消費しない。
- 既存Dockの27枠、保存済み装備、回収機、所有権を保持したまま専用画面へ移行する。
- UI、補給品、母艦の新しい外観および音声は見本提示と承認後にゲームへ反映する。モデル完成、コンパイル成功、実ゲーム検証を区別して報告する。

## 既存挙動を守る境界

1. 手動Wing所属と任務内の一時的な編隊を混同しない。補給配送・母艦利用はHomeDockや手動Wingを無断で変更しない。
2. 作戦通信はサーバーで確定した出来事を通知するだけで、状態遷移を指示しない。再接続時の一覧取得から大量の出撃通知を作らない。
3. 補給網はアイテムを物理的に積載したCargoが配送する。在庫を座標間で瞬時に転送しない。予約は在庫そのものではない。
4. プレイヤーの命令、戦闘、給電、救難、既存Cargo任務を新規配送が横取りしない。取り消し時には積荷を消去せず返送先を再評価する。
5. 飛行用電力と兵装用電力を別資源として扱う。飛行燃料があるだけで兵装用資源もあると判断しない。
6. 再出撃は残量、安全な復路、任務の生存、交代済み機の状態を確認する。不足物資を待つ理由を表示し、条件不成立を「補給中」とだけ表示しない。
7. 母艦の採掘は対象チャンクの確認操作を要する。岩盤・保護対象を除外し、インベントリ満杯、電力不足、所有者不在等の停止理由を保持する。
8. 母艦の対Mob照射は採掘処理を呼ばない。船内建築、内部収納、機体サービスは別の保存対象として識別する。

## 中断・消失・再読み込み

復帰時は保存した目標をそのまま信頼せず、対象の存在、所有権、世代、容量、アクセス可能性を再確認する。配送先消失は同じ所有者の代替受入先、元倉庫、保管待ちの順に扱い、積荷を落としたり別所有者へ渡したりしない。船体が失われても船内プレイヤーに退出先を提供し、船内保存物は暗黙に消去しない。

## 検証ゲート

| 対象 | 必須観点 |
|---|---|
| 補給品 | 残量1、満タン直前、複数枠、部分クレジット、再読込、旧アイテム不消費、他者操作拒否 |
| Dock画面 | 通常投入・取り出し・連打・Shift移動・ドラッグ・満杯・破壊・距離超過・GUI倍率 |
| 補給網 | 二重予約、競合Cargo、部分積載、満杯到着、配送中充電、倉庫消失、命令割込、再接続 |
| 通信 | 同時大量イベント、優先度、失効、重複、所有者分離、音声OFF、切断時破棄、履歴上限 |
| 母艦 | 採掘範囲境界、岩盤、収納満杯、停止再開、非破壊戦闘、所有権、二隻の船内分離、安全退出 |
| 継続性 | 既存Wing、ルート、戦闘復帰、補給後復帰、救難、既存ワールド更新 |

単体試験に加え、通常操作の実ゲーム確認が必要。未実施の画面・保存復元・大量運用はPASS扱いにしない。既存の全試験が通っても、新機能同士の組合せや失敗時の保存を追加で検討する。

2026-09-22時点。機能内部の実装とプレイヤーが使用できる完成状態を分けて扱う。

| 自律配送 | 設定要求、台帳、実Cargo積載、途中充電、荷物保持・返送、状態要求とクライアントキャッシュ | 設定・状況画面の接続、実際の航行と保存再開の確認 |
| 作戦通信 | サーバー観測、履歴保存、認証付き通知、クライアント受信、26種類の翻訳 | 声質承認、音声再生器、字幕・履歴画面の接続と聴取確認 |

母艦モジュールは、描画と専用画面が用意されるまで通常起動に登録しない。未登録アイテムのレシピは条件付きで読み飛ばす。設計図のPNGはMinecraftのスクリーンショットではない。

既存ランチャーの0.20.4は変更しない。SHA-256は `cba420d0fe652d95f0237522bd573bc0a87ecac9926ce4aad5c6a18f2b68266f`。新機能を途中状態のまま同じバージョンとして配布しない。

`launcher_release_ready=false` を設定し、通常のビルドによる自動差し替えも停止する。外観承認、実Screen・音声・描画の接続、版番号更新、必要な確認が完了するまで解除しない。試験失敗、check/testの省略、部分試験だけの場合も差し替えを許可しない。

母艦のV24外観と専用画面はユーザーから不採用とされた。理由は、外観が薄い流線型に偏り母艦としての重厚感に欠けること、画面が情報過多で採掘範囲の選び方と操作名が伝わらないこと。V25外観も厚く短い船体が過度に膨らんで見えるため不採用となった。V26ではF-22を輪郭の参考とし、長い飛行甲板・格納庫・双発の後部構造を一体化した攻撃空母を提案する。戦闘機の単純な拡大や、全体を均等に厚くする方法ではない。

V25の画面は、地図で範囲を選ぶ作業画面と貨物・補給画面を分離した未承認案として保持する。最新の外観への指摘だけを根拠に画面の採否を判断しない。専用の船内空間の採用判断は変更しない。新しい外観寸法は提案であり、登録寸法・衝突・搭乗地点・補給ベイの実装に無条件で転記しない。

通常操作のケースと証拠条件は [実ゲーム確認手順](OPERATIONS_V24_GAME_VERIFICATION.md) を参照する。全体のビルドが通った後も、未接続の画面・音声・母艦登録を「実装済みで遊べる」と報告しない。
