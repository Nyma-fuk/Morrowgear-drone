# Morrowgear 複合兵装・攻撃ウェーブ制御仕様

更新日: 2026-09-24  
対象: Morrowgear Drone Java Mod  
状態: 実装・自動検証・Minecraft実ゲーム検証済み

## 1. 目的

Security機がレーザー、ミサイル、機関砲の残存能力を有効利用しながら、次の不自然な挙動を起こさない戦闘制御を定義する。

- 選択兵器を使えないだけで、他兵器が残っているのにDockへ帰る。
- レーザー照射中、敵HPが減ったことを理由に機関砲へ切り替える。
- レーザー冷却に入った個体から編隊を抜け、円周スロットが再配置される。
- 8機同期中に1機の熱・電力・射線変化で全機の位置が跳ぶ。
- 機関砲掃射やミサイル斉射の途中で目標・兵器・軌道が変わる。
- Dock内で優先兵器を変更しても、古い補給理由が残って再出撃できない。
- 補給復帰機と交代機が戦線とDockを行き来する。

本仕様では、兵器判断を毎tick行わない。`攻撃ウェーブ`を最小のコミット単位とし、安全な境界でのみ兵器・目標・編隊を再計画する。

### 1.1 仕様の優先順位

本書は複合兵装、攻撃ウェーブ、レーザー群冷却、兵装補給、戦闘復帰に関する正本とする。過去資料に次の記述がある場合は本書を優先する。

- `SecurityLoadout`で使用可能兵器を一つに固定する。
- HEAT到達時に個体単位で別兵器へ切り替える。
- 選択兵器だけが不足した時点でDockへ帰還する。
- 全資源が一定割合まで回復するまで再出撃できない。

現行コードは本仕様へ移行済みである。今後の変更でも、既存実装の都合を根拠に本仕様を縮小してはならない。

### 1.2 2026-09-24実装範囲

- `SecurityLoadout`を搭載制約ではなく兵器ドクトリンとして扱い、選択兵器が使えない場合は残存兵器へフォールバックする。
- `LASER_COOL_ORBIT`、`GUN_BREAKAWAY`、`WAVE_ASSESS`を追加し、兵器変更をウェーブ境界へ限定する。
- レーザー群は固定スロットを保持したまま冷却し、再開条件または群単位の再評価条件が揃うまで円周軌道を維持する。
- Flight Power、Auxiliary Power、Laser Energy、Gun Ammo、Missile Count、Laser Heatを独立して保存・消費する。
- Auxiliary Power不足は空中回復を優先し、それだけを理由にDockへ帰還しない。
- セーブ再読込時の進行中攻撃は`REJOIN`から安全に再評価し、部分的な斉射や照射を再構築して二重発射しない。
- `WeaponServicePlan`を実際の兵装帰還判定へ接続し、熱や一時的遮蔽を資源枯渇として扱わない。
- 全兵器可用性8組合せ、群冷却、再装填、縮退出撃、保存互換、兵器別資源消費を自動試験で固定する。
- Minecraft自動戦闘シナリオ`adaptive_combat`で、複数レーザー群、ルート迎撃復帰、全兵器枯渇時の交代補給、冷却再交戦、機銃軌道、遠隔継続の7ケースを確認する。最終結果は`build/verification/mouse-free/20260924-201313-adaptive_combat.json`の`COMPLETE PASS 7/7`である。複数レーザー群の確認は群単位だけでなく、予定参加4機すべての`LASER_FIRE`遷移を要求する。
- 基地実運用回帰`base_laser`は4 Wing・レーザー8機・基地内ウォーデン1体を再現し、8機すべての`LASER_FIRE`遷移を要求する。旧48ブロック射程では第4高度レーンの2機だけが充填旋回へ残る不具合を再現し、64ブロックへ整合後の`build/verification/mouse-free/20260924-201215-base_laser.json`で`COMPLETE PASS 2/2`を確認した。

## 2. 用語と責務

| 用語 | 意味 |
|---|---|
| 搭載兵装 | 機体が使用可能な兵器集合。Security機は原則として3兵装を内蔵する。 |
| 兵器ドクトリン | `AUTO`、`LASER FIRST`など、選択優先度を示す。使用禁止とは限らない。 |
| Active Weapon | 現在の攻撃ウェーブで使用している兵器。 |
| Engagement Lease | 対象、参加機、作戦優先度を一定期間固定する契約。 |
| Attack Wave | 進入から攻撃、離脱または冷却までを一つにした中断不可の戦術単位。 |
| Formation Generation | 参加機、スロット、軌道、高度を固定した編隊世代。 |
| Service Plan | 不足資源を集合で保持するDock補給計画。単一の帰還理由ではない。 |

制御責務は次の順で分離する。

```text
Combat Theater Coordinator
  -> Engagement Lease
  -> Weapon Planner
  -> Attack Wave Coordinator
  -> Weapon Maneuver Executor
  -> Service Planner
```

上位層だけが下位層を切り替えられる。機関砲やレーザーの個別処理から直接`REJOIN`、Dock帰還、別兵器選択へ飛ばさない。

### 2.1 決定の一貫性

各機が同じ戦況から独自に編隊を再計算すると、tick順、チャンク読込、通信遅延で判断が分岐する。群制御の決定値はCoordinatorが一度だけ生成し、参加機は次の不変なSnapshotを参照する。

```text
planId
revision
targetId
waveId
formationGeneration
memberIds / reservedSlots
activeWeapon
phase
phaseStartedAt
expiresAt
```

- 同じ`planId + revision`の再受信は副作用を起こさない。
- 古いrevision、完了済みwave、異なるtargetの遅延更新を拒否する。
- 参加機は自分で人数を詰め直さず、欠員を空席として扱う。
- Coordinator消失時は新しい攻撃段階へ進まず、現在段階を安全終了して`WAVE_ASSESS`へ退避する。
- セーブ時は発射済み弾、消費済み資源、完了済みphaseを識別できる情報を保存し、再読込で二重発射・二重消費しない。

これにより、サーバーtick順や個体ごとの目標認識差が飛行軌道へ直接伝播しない。

## 3. 不変条件

実装は常に次を満たす。

1. 1機の飛行目標を所有する状態は、1tickにつき一つだけとする。
2. 攻撃ウェーブ中は兵器を毎tick再選択しない。
3. 目標HP低下だけでは、進行中の攻撃ウェーブを中断しない。
4. レーザーの熱は、Dock帰還または別兵器切替の直接トリガーにしない。
5. レーザー編隊の参加数とスロットは、Formation Generation終了まで詰め直さない。
6. ミサイルはロック確定後、現在の斉射を完了するまで新しい高優先度目標へ変更しない。
7. 機関砲は進入、直線掃射、離脱の途中で攻撃軸を再生成しない。
8. 飛行安全、機体損傷、プレイヤーの明示命令は、兵器コミットより優先する。
9. 使用可能な兵器が一つでもあり、飛行安全を満たす場合、兵器不足だけでDockへ帰らない。
10. サービス完了判定は現在のドクトリンではなく、実際の搭載兵装と任務要求から毎回再計算する。

## 4. 兵装と資源

### 4.1 搭載兵装とドクトリンの分離

既存の`SecurityLoadout`は単一兵器を固定する役割を廃止し、移行後は兵器ドクトリンとして扱う。

| 旧値 | 新しい意味 |
|---|---|
| `UNARMED` | 全兵器使用禁止 |
| `AUTO` | 状況に応じて自動選択 |
| `AUTOCANNON` | `GUN FIRST` |
| `LASER` | `LASER FIRST` |
| `MISSILE` | `MISSILE FIRST` |

Security機の3兵装は機体内蔵とする。外付け武器モジュール方式には戻さない。アップグレードは搭載有無ではなく、容量、冷却、照準、再装填性能を変更する。

完全固定が必要な試験・特殊任務には、通常ドクトリンとは別に`ONLY`制約を持たせる。

### 4.2 独立資源

| 資源 | 用途 | 枯渇時 |
|---|---|---|
| Flight Power | 飛行、帰還予備 | 安全帰還を最優先 |
| Auxiliary Power | センサー、照準、ハッチ、砲駆動 | 空中回復を試み、全兵器が使えなければ帰還 |
| Laser Energy | レーザー充填・照射 | ウェーブ境界で他兵器を再評価 |
| Laser Heat | 一時的な熱制約 | 円周軌道を維持して冷却 |
| Missile Count | 発射可能数 | 斉射終了後に他兵器を再評価 |
| Gun Ammo | 機関砲弾数 | 掃射終了後に他兵器を再評価 |

`Weapon Power`一つが全兵器を同時に使用不能にする構造は廃止する。Auxiliary Powerが不足しても、即Dock帰還ではなく、現在の攻撃コミットと空中回復可否を評価する。

## 5. 共通戦闘状態

```text
IDLE
  -> COMBAT_ENTRY
  -> WAVE_PLAN
  -> WAVE_INGRESS
  -> WEAPON_COMMIT
  -> WAVE_EXECUTE
  -> WAVE_RECOVERY
  -> WAVE_ASSESS
      -> WAVE_PLAN
      -> SERVICE_RTB
      -> REJOIN
```

### 5.1 再計画可能な境界

兵器・目標・参加編隊を変更できるのは次だけとする。

- `WAVE_PLAN`
- `WAVE_ASSESS`
- 目標死亡直後
- プレイヤーの攻撃中止
- 飛行安全または重大故障による緊急中断

照射、斉射、掃射中は再計画しない。

## 6. レーザーウェーブ

### 6.1 状態

```text
LASER_INGRESS
  -> LASER_FORM
  -> LASER_CHARGE
  -> LASER_FIRE
  -> LASER_COOL_ORBIT
  -> LASER_CHARGE または WAVE_ASSESS
```

### 6.2 Formation Generation

レーザーウェーブ開始前に次を固定する。

- 目標ID
- 編隊世代ID
- 予定参加数。最大8機
- 各機のスロット番号
- 円周半径
- 高度レーン
- 旋回方向
- 位相
- 共通照射開始基準
- 共通照射終了基準

照射中に1機が抜けても空席を残す。残りのスロットを7機用に再計算しない。再配置は次のFormation Generationでのみ行う。

### 6.3 途中参加

予定8機に対して4機だけ成立している場合も、8個のスロットを予約して4機から照射できる。後続機は割当済みスロットへ到着してから照射へ参加する。既存4機の位置は変更しない。

DPS計算は実際に同一目標へ照射中の機数を使用し、1機から8機まで単調増加させる。9機目以降は別目標または別レーザー群へ配分する。

照射位置への整列は無期限に待たせない。充填完了後60 tickまでは正規スロットまたは等間隔の群形成を優先する。120 tick経過後は、目標まで64ブロック以内で射線が安全なら照射を開始する。64ブロックは4群目の衝突回避レーンが高度28ブロックへ展開し、移動目標への収束中に旧48ブロック境界を一時的に越えることを考慮した値である。正規スロットからの距離は命中精度へ反映し、軌道追従自体は照射中も継続する。これにより同期火力を優先しつつ、交差交通や地形回避で1機だけ充填旋回へ永久拘束される状態を禁止する。

### 6.4 熱管理

照射前に各機の熱余裕とレーザーエネルギーから持続可能時間を求める。最低ウェーブ時間を満たせない機体は、Formation Generation確定前に除外する。

群の計画照射時間は次の最小値とする。

```text
目標撃破予測時間
群内最小熱余裕時間
群内最小レーザーエネルギー時間
最大連続照射時間
```

通常の熱閾値では個体離脱させない。計画停止温度へ近づいた時点で群全体が同じtickに照射を止め、同じスロットのまま`LASER_COOL_ORBIT`へ移行する。

緊急停止温度は故障時の最終保護にだけ使う。緊急停止した機体のスロットは空席とし、照射中の再圧縮を禁止する。

### 6.5 冷却

冷却はレーザーウェーブの一部であり、兵器再選択状態ではない。

- 目標ロックを保持する。
- 円周軌道を保持する。
- 高度、半径、位相、スロットを保持する。
- 別兵器へ個別切替しない。
- 冷却後は同じFormation Generationで再充填できる。

攻撃継続が必要な場合、別の機関砲群またはミサイル群を別空域から投入する。冷却中レーザー機を転用しない。

### 6.6 射線喪失

- 瞬間的な遮蔽では軌道を維持し、ビームだけを遮蔽物位置で止める。
- 共通の猶予時間内に射線が戻れば照射を再開する。
- 長時間遮蔽では群全体を`WAVE_ASSESS`へ移し、新しい高度・半径を次世代として計画する。
- 他機の接近や通過は、レーザー群の高度変更・Rejoin・スロット再計算理由にしない。

## 7. ミサイルウェーブ

```text
MISSILE_INGRESS
  -> MISSILE_LOCK
  -> MISSILE_SALVO
  -> MISSILE_EGRESS
  -> WAVE_ASSESS
```

- ロック確定後は現在の最大5発分の計画を固定する。
- 新しい高優先度目標は次のロック計画へ送る。
- 予約済みダメージを考慮し、過剰分の未発射ミサイルを減らす。
- 弾切れは斉射途中の軌道変更理由にせず、発射可能分を終えて離脱する。
- 発射済みミサイルは別目標へ飛び移らない。
- 目標死亡後の未発射分は次ウェーブへ戻す。
- 味方、基地、保護対象に対する爆発危険が高い場合はロックを成立させない。

## 8. 機関砲ウェーブ

```text
GUN_INGRESS
  -> GUN_LINEUP
  -> GUN_RUN
  -> GUN_BREAKAWAY
  -> WAVE_ASSESS
```

- ウェーブ中は共通攻撃軸、開始時刻、機体順序を固定する。
- 射撃は直線掃射区間だけで行う。
- 敵通過後の後方射撃を禁止する。
- 弾切れでもその場で反転せず、安全なBreakawayを完了する。
- 敵死亡時は射撃だけを止め、離脱軌道を完了する。
- レーザー群の予約空域を横切る経路は生成しない。

## 9. 兵器選択

### 9.1 使用可能状態の全組み合わせ

| Laser | Missile | Gun | 新規ウェーブ候補 |
|---:|---:|---:|---|
| 0 | 0 | 0 | `SERVICE_RTB`または増援待ち |
| 0 | 0 | 1 | Gun |
| 0 | 1 | 0 | Missile |
| 0 | 1 | 1 | MissileまたはGun |
| 1 | 0 | 0 | Laser |
| 1 | 0 | 1 | LaserまたはGun |
| 1 | 1 | 0 | LaserまたはMissile |
| 1 | 1 | 1 | 全候補を評価 |

これは新規ウェーブの表であり、進行中ウェーブへは適用しない。

### 9.2 選択要素

- 目標の現在HPと最大HP
- 装甲、移動速度、飛行状態、当たり判定
- プレイヤー危険度と敵固有脅威度
- 単体か群か
- 射線、遮蔽物、地形、味方、建造物
- 到達時間、攻撃準備時間、予測撃破時間
- 各兵器の残量と補給希少度
- 予約済みダメージ
- 成立済みレーザー同期数
- 使用可能な別攻撃群
- 現在のEngagement Lease

兵器には継続ボーナスを与えるが、ウェーブ境界でのみ比較する。候補が現在兵器より明確に有利でなければ同じ兵器を継続する。

### 9.3 代表選択

| 状況 | 第一候補 | 条件・例外 |
|---|---|---|
| 高耐久単体 | Laser | 安定射線と熱余裕がある |
| 高速・飛行目標 | Missile | 巻き込み危険が低い |
| 多数の弱敵 | Gun | 複数戦線へ分散する |
| 密集した高脅威群 | Missile | 保護対象への爆発危険がない |
| 低HP通常敵 | Gun | 新規ウェーブの場合のみ |
| 味方に近い敵 | Laser | 射線が安全である |
| 遮蔽物の多い敵 | MissileまたはGun | レーザー群は再配置を検討 |
| 接近中の緊急敵 | Gun | レーザー充填が間に合わない場合 |

レーザー照射中に敵HPが低下してもGunへ切り替えない。照射を継続して撃破する。

## 10. 目標と戦況の変化

| 事象 | 進行中ウェーブの扱い |
|---|---|
| 目標HP低下 | 継続 |
| より高脅威の敵が出現 | 予備機へ割当。現在群はウェーブ完了後に再評価 |
| 目標死亡 | 攻撃出力を停止し、安全な回復・離脱状態へ移行 |
| 目標が非敵性化 | 即時射撃停止。軌道は安全に終了 |
| 目標がチャンク外へ移動 | 一定猶予後にウェーブ終了。盲目的に追跡しない |
| プレイヤーが危機 | 予備戦力を優先投入。進行中ウェーブは原則維持 |
| 味方機が撃墜 | 空席を維持し、次ウェーブで再編成 |
| 他群が接近 | 空域予約で回避。レーザー群をRejoinさせない |
| Dock破壊 | 戦闘を継続可能なら継続。帰還時に動的再割当 |

## 11. サービス帰還

### 11.1 帰還条件

次の優先順位で判定する。

```text
重大損傷
  > Flight Power帰還予備
  > 全搭載兵器の持続的使用不能
  > 予防整備
```

Laser Heatだけでは帰還しない。一時的な射線喪失、充填待ち、冷却待ちも帰還理由にしない。

### 11.2 Service Plan

不足状態を集合で保持する。

```text
FLIGHT_POWER
AUXILIARY_POWER
LASER_ENERGY
MISSILE_AMMO
GUN_AMMO
REPAIR
SUBSYSTEM_MAINTENANCE
```

優先兵器をUIで変更した場合、Service Planを即座に再計算する。古い`LASER_ENERGY待ち`などを出撃阻止条件として残さない。

### 11.3 再出撃

全資源100%を必須にしない。次を満たせば出撃可能とする。

- 機体と推進系が飛行可能
- 往復予備を含むFlight Powerがある
- 現在の戦況に有効な兵器が一つ以上ある
- 元のEngagement Leaseまたは復帰任務が有効

戦闘継続中は`DEGRADED SORTIE`を許可する。例えばレーザーが空でも、ミサイルまたは機関砲が有効なら出撃できる。

## 12. 任務復帰

戦闘開始時に、元任務、Wing、Cohort、ルート進捗、Dock予約を保存する。戦闘ウェーブや補給でこれらを上書きしない。

- 目標が残る: 必要戦力を再評価し、不足時だけ戦線復帰する。
- 交代機で充足済み: 帰還機は交代機の元任務を引き継ぐか、自身の元任務へ戻る。
- 元任務が終了済み: 同Wingの現在任務へ再解決する。
- Wingが消滅: 有効なDock、警戒、プレイヤー追従の順でフォールバックする。
- Dockがない: 安全旋回しながら動的Dock割当を待つ。`STANDBY`停止へ落とさない。

## 13. 表示と通知

HUDとコントローラーには、集約`WPN`だけでなく次を表示する。

- 搭載兵装
- 優先ドクトリン
- Active Weapon
- Gun Ammo
- Missile Count
- Laser Energy
- Laser Heat
- Attack Wave状態
- Formation Generationと同期数
- 出撃不能理由
- Service Plan

通知は状態変化時に一度だけ送る。

```text
MG-021 / LASER WAVE COMMIT / 4 OF 8
MG-021 / LASER COOL ORBIT / SLOT HELD
MG-021 / WAVE COMPLETE / LASER ENERGY DEPLETED
MG-021 / WEAPON SHIFT / LASER -> MISSILE
MG-021 / DEGRADED SORTIE / MISSILE AVAILABLE
```

冷却開始を`WEAPON SHIFT`として通知しない。

## 14. 異常系

| 異常 | フォールバック |
|---|---|
| 対象Entity消失 | 射撃停止、ウェーブ終了、元任務再解決 |
| 所有者不在 | 攻撃開始禁止。進行中攻撃を安全終了 |
| 編隊リーダー離脱 | Formation Generation中はスロット不変。制御代表だけ委譲 |
| セーブ・再読込 | ウェーブを安全な`WAVE_ASSESS`から復元し、発射を重複させない |
| Dock満杯 | 予約Queueまたは上空保持。任務を消さない |
| Dock破壊 | 動的再割当。古いDock座標をサービス条件に使わない |
| 補給資源不足 | 使用可能兵器で縮退出撃、または理由付き待機 |
| 通信断 | 新規目標変更を止め、現在ウェーブを安全終了して事前設定へ復帰 |
| 同一目標への過剰攻撃 | 予約ダメージを差し引き、後続攻撃を別目標へ回す |

## 15. 検証マトリクス

最低限、次を自動試験と実ゲーム試験の両方で確認する。

### 15.1 資源組み合わせ

- Laser / Missile / Gunの使用可能8組み合わせ。
- 各兵器がウェーブ途中、境界、Dock内で枯渇するケース。
- Auxiliary Powerだけが不足するケース。
- Flight Powerだけが帰還予備へ到達するケース。

### 15.2 レーザー

- 1、2、4、8機での円周移動、等間隔、DPS単調増加。
- 異なる熱量の機体を含む開始判定。
- 途中参加しても既存スロットが移動しない。
- 予定参加機の一部が定位置へ収束しなくても、最終期限後に安全な射線から照射へ移り、充填旋回へ残留しない。
- 個体緊急停止後も残存機を再圧縮しない。
- 冷却中にGun/Missileへ切り替わらない。
- 他群通過で高度、状態、目標が変わらない。
- 遮蔽時にビームだけが遮蔽物で止まり、壁越しに描画されない。
- 敵HPが残り僅かでも照射を継続して撃破する。

### 15.3 ミサイル

- 1から5発のロック予約と過剰発射抑制。
- 高優先度目標出現後も現斉射を完了する。
- 目標死亡後に未発射弾を消費しない。
- 発射済み弾が別目標へ不自然に転向しない。

### 15.4 機関砲

- 弾切れ時も後方射撃せずBreakawayを完了する。
- 敵死亡後に攻撃軸を急反転しない。
- レーザー空域を横切らない。
- 衝突回避を含め速度が1tickで不自然に変化しない。

### 15.5 Dock・復帰

- Laser優先で帰還後、Missile優先へ変更して即時再判定できる。
- Laserが空でもMissile/Gunがあれば帰還しない。
- Dock資源不足でも有効兵器があれば縮退再出撃できる。
- Dock破壊後、新規Dockで補給・再出撃できる。
- 交代機と復帰機が戦線とDockを往復しない。

## 16. 実装順序

1. `SecurityLoadout`から搭載兵装とドクトリンを分離する。
2. 単一`serviceReason`を`Service Plan`へ置き換える。
3. `Engagement Lease`と`Attack Wave`を導入する。
4. レーザーFormation Generationを固定し、熱を群単位で処理する。
5. ミサイルと機関砲をウェーブ境界方式へ移行する。
6. Dock再出撃判定を「任意の有効兵器」基準へ変更する。
7. HUD、コントローラー、Dock UIを新しい資源と状態へ対応させる。
8. 保存データ移行、全単体試験、マウス不要の実ゲーム試験、画面確認を行う。

この順序を崩して、現行`weaponFor()`へ条件分岐だけを追加してはならない。編隊、補給、復帰が別々の判断を続けるため、同じ不具合が別状態で再発する。

## 17. 個別射撃経路と閉所戦闘

### 17.1 責務分離

群制御は、目標、攻撃ウェーブ、武器、空域、Wing所属、スロットを決める。個体制御は、その決定を変更せずに、現在の地形から合法な射撃位置を探索する。

```text
群制御: target / weapon / wave / airspace / slot
個体制御: ingress / firing aperture / line of sight / swept clearance
射撃許可: 射程 + 射線 + 安全性 + 武器固有包絡線
```

円形隊形やCAS軌道の完成は、射撃精度と同期火力を高める理想状態であり、射撃許可そのものではない。自機に安全な射線があれば、その機体は他機の到着を待たずに射撃できる。

### 17.2 候補点

`WeaponFiringRoutePolicy`は地形を変更せず、次の候補だけを生成する。実際のブロック衝突、チャンク読込、射線、敵性、ダメージは`ServerLevel`側で再検証する。

- Laser: 通常上空円、側方円、高低差を抑えた洞窟内円、縦穴用の軸上点。
- Missile: 水平24から64ブロック、目標より8ブロック以上高い発射点。上部ハッチの射出空間も必須。
- Autocannon: 目標を通過する複数の進入軸。固定点でホバリングせず、目標の先にある離脱点へ向かう前方射撃区間を作る。

有効候補は10tick保持して再探索の振動を防ぐ。維持中の候補にはヒステリシスを与え、同等の別候補へ毎tick切り替えない。

### 17.3 解なし

120tick以内に合法な候補が見つからなければ、その兵器だけを180tick保留し、`WAVE_ASSESS`で別兵器を評価する。目標、Wing、元任務は破棄しない。完全密閉室に対して壁越し射撃、地形破壊による射線生成、永久ホバリングを行わない。

### 17.4 実ゲーム検証

`firing_routes`シナリオは次を実際のMinecraftワールド内で生成して確認する。

1. 入口付き洞窟: 2機のLaserが別々に射撃口を取得し、対象HPを減らす。
2. 入口付き洞窟: Autocannonが前方進入で命中し、天井を着弾線として誤認しない。
3. 縦穴: Laserが機体を収容できる軸上経路から照射する。
4. 完全密閉室: Missile探索を打ち切り、弾薬と対象HPを変化させず再計画する。
5. Multi-Wing壁面戦: 2群4機がWing所属を維持し、個別経路から全機射撃する。

このシナリオに加え、`base_laser`で4 Wing・8機同期、`adaptive_combat`で複数群・交差交通・補給復帰、`combat_cas`で屋外CASを回帰確認する。
