| 機種 | 胴体と装備の関係 | 飛行・収納状態 | 動作を見せる部分 |
| --- | --- | --- | --- |

| SCOUT | 機首の厚みの中に左右の光学系、頬の面に埋め込んだセンサー窓 | 独立したカメラポッドを廃止 | 外周走査帯と移動する走査点 |

### 一体型の定義

装備を隠す箱を別途取り付けることではありません。`H01_ContinuousLiftingBody` 自体の下面を再成形し、その内部に必要な空間を作っています。
上面の `Z >= 0.05` は変形せず、下面へ向かって連続的に変形量を増やしています。左右のファン周囲では変形量をゼロへ落とし、流路を保持します。
扉・センサー窓・開口縁は、変形後の外皮を参照して曲面に沿わせます。

SALVAGE は機首を不要に厚くしないため、下面の増積を他機種より後方から始めています。吊り点を中央に置く理由は、回収荷重を前端の張り出しに持たせないためです。ただし、実質量を割り当てた重心・強度計算は実施していません。

## 配置と可動部

座標は形状設計用の Blender 座標で、`+X` が右、`-Y` が機首、`+Z` が上です。Minecraft 内のブロック数や実機のメートル寸法ではありません。以下は機種別全体スケールを適用する前の値です。

| 対象 | 配置・構成 |
| --- | --- |
| ファン | 中心 `X = ±1.91, Y = 0.01826677`。V19 のブレード・ハブ・開口を継承 |
| Cargo下面扉 | 正側 `X = 0.028〜0.59, Y = -1.94〜0.77` を基本に、反対側を厳密ミラー |
| Engineerアーム根元 | `X = ±0.67, Y = -1.45, Z = -0.25`。左右の収納室から前下方へ展開 |
| Security機関砲 | `X = ±0.72, Z = -0.27`。胴体前面との交点を使い、開口と内部銃身を配置 |
| Securityミサイル庫 | `X = ±0.10〜0.58, Y = -1.15〜0.56`。左右4本ずつ。後方のインテークとは別区画 |
| Securityレーザー | `X = 0, Y = -1.00`。半径 `0.30` の黒い半球レンズを下面へ一部露出 |
| Salvageウインチ | ドラム中心 `(0, -0.23, -0.32)`、半径 `0.20`、幅 `0.80` |
| Salvageケーブル導出点 | `(0, -0.45, -0.65)`。プレビューの繰り出し長は `0.045〜2.10` |
| 着陸脚 | `X = ±1.13, Y = ±1.65` の4点。Cargo・Salvageは伸長量と足裏を増やす |

構造物と可動装備は左右対称です。Scout の走査点の移動と照射口の発光は表示演出であり、構造物の非対称性ではありません。

### プレビューの時間軸

各機体に1本の確認用アニメーションを収録しています。

- フレーム `1〜20`: 着陸脚を伸ばし、役割装備を収納。
- フレーム `40`: 飛行状態。脚・役割装備を収納。
- フレーム `40〜80`: 役割装備を展開。
- フレーム `80〜100`: 展開状態を維持。
- フレーム `120`: 装備を収納し、着陸脚を伸ばす。

これは形状・左右対称・書き出しを確認するためのアニメーションです。Modの飛行状態、ミサイル発射数、採掘、サルベージ制御へ接続した実ゲーム動作ではありません。

## 検証

自動検証結果は、各機種の `validation.json`、全体の `output-checks.json`、`export-roundtrip.json` を参照してください。

### 今回の実測結果

- 6機種それぞれ11時点の形状検査と、GLB再読み込み後の11時点比較がPASS。
- 左右反転対応点の最大誤差は `0.0000016094` 未満。
- 着陸時の装備・胴体と地面との最小隙間は `0.3192` 以上。
- 収納室・センサー窓・ミサイル庫の計45本の奥行きプローブがPASS。新設した収納室のないFIELDは、この検査の対象点が0本です。
- GLB再読み込み後の部品外接範囲の最大差は `0.0000007153` 未満。
- 各機種13枚の全体図と1枚の機構拡大図を生成し、全6機種の方向別ボードを目視確認。

数値の単位は本書の形状設計用座標です。見た目の採用判断と実ゲーム確認は別です。

| 観点 | 検査内容 | 限界 |
| --- | --- | --- |
| 左右対称 | 各機体11時点で、評価後の頂点を左右反転して対応点を照合 | 浮動小数点の許容誤差を含む |
| 着陸 | 4足の接地面が同じ高さで、収納した装備と地面に隙間がある | Dock全体・他機体との実ゲーム当たり判定は別途必要 |
| ファン | 脚の頂点が所定のファン流路へ入らないこと | 空力・推力・構造強度の解析ではない |
| 胴体 | 溶接後のメッシュが閉じており、体積が正であること | 可動部すべての連続時間の干渉保証ではない |
| 収納室の開口 | 曲面上の複数点から内部へレイを飛ばし、設計した奥行きまで胴体が残っていないこと | 扉や装備そのものは、開口検査の遮蔽物には含めない |
| 出力画像 | 13方向・状態の全体図が非空、枠内、同一解像度、再生成済みであること | 構図の検査であり、参照画像への忠実度の自動判定ではない |
| 書き出し | GLBを読み直し、11時点の各部品の外接範囲を元のBlenderモデルと比較 | 材質・ゲーム描画・全頂点の完全一致を保証する検査ではない |

開口部については、最初の試作で曲面の縁だけから切断形状を作ると、張り出した胴体下面が開口内に残る問題を発見しました。切断形状の入口・奥面の両方を曲面に沿った細かいメッシュへ変更し、開口奥行き検査を追加しています。
胴体の陰影は変形後に法線を再計算し、面積と角度による重み付けを適用しています。

## ファイルと再生成

各機種フォルダに `airframe.blend`、`airframe.glb`、13方向・状態の全体図、機構拡大図、`all-views.png` を保存します。
旧案との比較画像は、旧モデルを新案と同じカメラ設定でレンダリングして作成します。

リポジトリルートからの再生成手順:

```powershell
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' --background --python-exit-code 1 --python tools/drone-design/blender/build_integrated_family_v21.py
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' --background --python-exit-code 1 --python tools/drone-design/blender/build_integrated_family_v21.py -- --compare-v20
& 'C:/Program Files/Blender Foundation/Blender 5.2/blender.exe' --background --python-exit-code 1 --python tools/drone-design/blender/verify_integrated_family_v21_export.py
python tools/review_integrated_family_v21.py
```

確認用スクリプトは V20 の形状・出力検査を再利用し、V21 の開口と胴体再成形の検査を追加しています。
参照元の V19・V20 モデルは上書きしません。

## ゲーム反映前に必要な確認

- 今回の外形・役割表現の承認。
- 最終的な機体寸法とDockの空間、収納・展開中の干渉、モデル原点の整合。
- アーム、扉、ウインチ、走査点、射出口の実ゲーム状態への割り当て。
- 発射位置、ビーム起点、回収ケーブル接続位置と実ロジックの整合。
- 材質のゲーム向け変換・必要なテクスチャのベイク・発光・LOD・多機体時の描画性能。
- カメラ距離別の役割識別性と、昼夜・上下左右からの実ゲーム確認。

今回のPASSを、ゲームへの反映済み・飛行力学の妥当性・実機としての製造可能性の証明として扱わないでください。
