## 最優先の改訂条件

ユーザーの追加指示により、下記3方向比較は採用候補としていったん取り下げる。共通方針は「民生用途だが軍用機寄りの重厚感と威圧感を持つ、左右対称の機械」。民生カメラドローン風の軽さ・可愛さ・細い脚を基準にしない。

[重厚感の方向見本](design-heavy-symmetry-v3.png)を作成したが、羽根位相や細部に左右差が残るため対称性検査は未合格。上面・正面の寸法整合も未検証。生成画像は質感の参考に限定し、正本モデルの代わりにしない。

### 対称性の受入契約

- 機体ローカル座標でXを左右とし、X=0を対称面に固定する。片側を作成して鏡面生成し、左右を別々に手作業で造形しない。
- 外装、ダクト、ブレード、脚、兵装取付、センサー、発光部、質量感を左右一致させる。中央部品は中心面へ固定。片側だけ突出した装置は禁止。
- 部品ごとに鏡面対応名と変換を持ち、対応頂点、面、法線、境界寸法、取付原点を検査する。許容誤差はモデル単位で1e-5を暫定値とし、書出し時の量子化を踏まえて確定する。
- UV・発光マスク・パネル線も対称にする。文字は反転文字にせず、同位置に正読文字を配置する例外を明示。汚れや傷による非対称を無断で追加しない。
- 左右対のローターは鏡面の羽根形状と逆回転・対応位相を使う。左右を独立乱数で回さない。アニメーションの複数時点でも比較する。
- 実飛行のロール・旋回姿勢や外部照明は画面上の左右差を生むため、幾何検査と分離する。形状検査は中立姿勢、正投影、左右均等照明で実施する。
- 7方向の静止画とローター回転・脚動作・照射の連続フレームを同じ正本から出す。モデル→ゲーム用書出し→実ゲームで対称性が維持されることまで確認する。
- 全デザインとは機体だけでなくアイテム、Dock、子機、母艦の共通造形へ適用すること。UIの操作配置まで機械的に左右対称にするのではなく、UIは操作性を優先し共通素材・色・記号を使う。

正本からの形状案と音声サンプルを承認するまでは、現行ゲーム資産を差し替えない。

## 開発順序と承認

1. 既存の給電・回収を含む共通描画の回帰確認と並行して、全体デザインの方向を承認する。
2. 正本モデル、全アイテム、UI、状態演出、音声の見本を作り、個別の反映前承認を得る。
3. 通常プレイで撮影・修正・再試験。既存ID、性能、Wing境界、保存、任務復帰の仕様は外観変更に混ぜない。
4. チャンクバスターを技術試作、保存安全性、掘削、母艦、居住の順に進める。巨大モデルを作っただけで機能成立とは扱わない。

## 音声通信の提案

人間の雑談・感情演技ではなく、無人機による短い状況報告。既存作品の台詞・音源・特定声優の声を模倣しない。日本語、平坦で明瞭、軽い通信帯域処理。声の高さだけでロールを区別しない。

### 発話対象

内部状態の全変更を読み上げるのではなく、全状態を「発話・集約・無音」に分類する。サーバーで確定した意味のあるイベントを使い、HUDの表示文字列や毎フレーム値を発話トリガーにしない。

| 実装上の状態・イベント | 発話例 | 規則 |
| --- | --- | --- |
| FOLLOW / WAYPOINT / ORBIT / SECURITY_PATROL | 「ウイング2、巡回開始」 | 新命令の確定時のみ。同じルートの毎周回・各点通過は無音 |
| COMBAT / EMERGENCY_INTERCEPT / FLARE_ENTRY | 「ウイング2、迎撃に移行」 | 同じ交戦へ複数機が入る場合は一報に集約 |
| LASER_CHARGE / LASER_FIRE / GUN_RUN / MISSILE_APPROACH / MISSILE_EGRESS | 「レーザー、照射開始」 | 注視対象・選択部隊を優先。毎パス・毎射・充填し直しを連呼しない |
| RAM_APPROACH | 「機体07、緊急攻撃」 | 重大イベント。一度だけ |
| REJOIN | 「ウイング2、任務復帰」 | 実際に元任務へ戻った時点。復帰を試みた段階では完了と言わない |
| SERVICE_RTB / RETURN / DOCKED | 「機体07、補給へ帰還」「補給完了、再出撃」 | 着艦と補給完了を区別。資源不足なら完了と言わない |
| POWER_LOSS | 「機体07、飛行電力喪失」 | 蓄電0後に機体が発話するのでなく、リンク側が検出した警報として通知 |
| FIELD_OPERATION / SCANNING / SCOUT_SURVEY / WORKING / PLANTING | 「調査開始」「掘削開始」 | 作業セッション単位。ブロックごとは無音 |
| FieldOperationState.COMPLETE / BLOCKED | 「作業完了」「作業停止、経路閉塞」 | 原因を取得できた場合のみ具体化。不明なら「作業停止」 |
| WAITING_DATA / ENGINEER_WAITING_INTEL / ENGINEER_LOCAL_SURVEY / TRANSIT | 原則無音 | 長時間停止・指示失敗のみ集約報告 |

| ENGINEER_SUPPORT / APPROACH / REPAIRING / MATERIAL_LOW | 「整備開始」「整備資材不足」 | 開始と継続不能のみ |

### 混雑・再接続・設定

提案初期値: 所有者ごとに同時1発話、通常発話間隔4秒、同一意味の抑制15秒、部隊集約窓1秒、通常キュー上限8件、通常イベント有効期限8秒。重大警告は通常発話を中断可能とし、同じ警告の繰返しを抑制する。100機の発進を100発話にしない。値は音声サンプルと実機試験後に調整する。

優先度: 電力喪失・喪失/危険 > プレイヤー防衛・作戦失敗 > 選択部隊の開始/復帰 > その他完了。再生直前に対象、所有権、任務世代、現在状態を再検証し、古い報告を捨てる。再接続時の全状態を新イベント扱いにしない。音声キューはゲーム制御の優先度キューとは独立し、動作を待たせない。

通信音声は所有者の無線チャンネルとして再生し、飛行音・射撃音の3D距離減衰と分離。離れた機体を目の前の大音量の発声にしない。字幕に発信機/部隊、短文、必要なら位置を添える。名称は字幕で任意名、音声は安定した短い番号。クラウドTTSやプレイ中の外部送信を必須にしない。音声OFF/重要のみ/標準、独立音量、字幕を用意。初期案は「重要のみ」。

試験: 再読込、次元移動、対象死亡、命令上書き、状態往復、補給資源不足、100機同時遷移、複数戦線、所有者分離、音声OFF、期限切れ、割込、欠損音源、字幕長文。音声ファイルが再生されたというログだけで聴感PASSにしない。

## チャンクバスターの機能契約案

### 船体・船内

大型空中母艦。着陸はせず、腹部の大口径照射口と収納部、小型機サービスベイを持つ。寸法・格納機数・速度・資源・レシピは未決定。

推奨初期方式は「ワールド内の可動外装Entity + 船IDに紐づく専用船内空間」。内部に置いたブロックと収納を保持し、外装の移動中も船内で生活する。これは実ブロックが外のワールドを船と一緒に移動する方式とは異なり、外の地形を窓からそのまま見たり、船内機械が外のブロックへ直接作用することを保証しない。ユーザー承認前にこの方式へ決めない。

実ブロックを移動させる方式を選ぶ場合、プレイヤー接地、ブロックEntity、液体、レッドストーン、他Mod、回転座標、保存、衝突を扱う別の技術検証が必要。対応ライブラリは現行Minecraft版との互換性を調査してから選定する。

乗艦は船直下の限定転送ゾーンから行い、所有者/許可者、入力クールダウン、行先の空きを確認。照射中は乗艦ゾーンと危険区域が重ならない設計にし、兼用する場合は照射を停止する。下船は安全な地表または明示された安全地点へ。船の移動・破壊・次元変更・ログアウト時も虚空、溶岩、窒息位置へ転送しない。安全位置がなければ下船を拒否して理由を出す。

### 掘削と回収

- チャンク単位は水平16x16。負座標も正しくチャンク境界に丸め、事前に範囲と高さを表示する。
- 「岩盤まで」は岩盤を破壊せず、その上の破壊可能ブロックを対象とする案。岩盤、保護領域、他人の設備、破壊不可ブロックは除外。岩盤のない次元は下限高さ等の別ルールを確認する。
- サーバーが対象と進捗を確定し、上から層/区画順に処理。tick当たりブロック数、時間予算、チャンク読込数を制限する。全範囲を一tickで壊さない。
- 通常のドロップ契約・保護イベントを尊重する。コンテナ内容、特殊ブロック、液体、落下ブロック、経験値の扱いは個別試験で確定する。
- 内部収納へ回収。破壊、ドロップ確定、搬入、進捗更新の重複防止を設計し、満杯では停止。再起動で再ドロップ・消失を起こさない。単なるEntityインベントリ保存だけでクラッシュ安全を保証しない。
- 採掘照射は範囲内生物へのダメージを伴うため、友軍/プレイヤー保護、射線遮蔽、警告・起動確認、緊急停止を必須にする。
- 対生物モードはブロック破壊OFFを初期推奨。掘削モードと被害判定を分離し、範囲・照射時間・資源・誤射保護をUIへ表示。高出力でも無制限貫通や毎描画フレームのダメージにしない。

### 母艦運用とUI

船固有UIに航路、採掘対象チャンク、進捗、内部収納、電力、兵装、搭載機、サービスベイ、乗艦許可、緊急停止を分離表示。開いただけで破壊を開始しない。

船の所有権・ベイ予約・小型機帰属Dock・一時補給先は別データ。母艦への回収がWing所属や元任務を上書きしない。移動中の着艦は相対位置・相対速度を使う別試験が必要。船が消えた場合は代替帰還先または回収待ちへ遷移し、古い座標へ飛び続けない。

保存キーは船UUID。外装、船内、収納、所属機、作業範囲、進捗世代を対応づける。破壊・復旧・アイテム化時に同じ船内を二重生成しない。プレイヤー不在時の航行/採掘/読込は予算と停止規則を先に確定する。

### 技術試作の順序

1. 外装の空中保持、所有権、保存と再読込。見た目と当たり判定を分離して検証。
2. 船内方式の選定、乗下船、安全復帰、ブロック設置と保存。
3. 1チャンクの保護付き掘削、収納満杯停止、再開、クラッシュ復旧。
4. 複数チャンクの予算制御、液体/洞窟/他Modブロック、無人時の規則。
5. 腹部演出とダメージモード、安全装置。
6. 小型機ベイ、母艦移動中の帰還・補給・再出撃、複数プレイヤー。

各段階を通常プレイと保存/復帰試験で閉じる。大規模掘削を既存ユーザーワールドで無確認実行しない。
