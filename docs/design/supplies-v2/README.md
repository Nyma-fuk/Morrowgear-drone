# 補給品 V2 正本とアイコン

ユーザーが承認した新しい補給品画像を、独立した Blender ポリゴンモデルとして再構成しました。旧 `supply-carrier-v24` の 3 アイコンは今回採用していません。

承認画像は `reference.png` に原寸で保存しています。原画像の `LASER CELL` 表記は変更していませんが、アイテムの表示名は **兵装電力セル / Weapon Energy Cell**、識別子は `laser_cell` のままです。レーザーだけでなくガン駆動・ミサイル射出を含む兵装電力を補充します。

## 構成

| 識別子 | 容量 | 承認画像から維持した特徴 |
| --- | --- | --- |
| `autocannon_magazine` | 120 発 | 開いた給弾箱、蓋の持ち手、見える弾列、チタンの角補強、アンバー帯 |
| `laser_cell` | 1000 兵装電力 | 縦長の矩形セル、左右の保護枠、埋め込みのシアン表示窓、上面の 2 電極 |
| `micro_missile_pack` | 5 発 | 上段 3 本・下段 2 本、短太の段付きカプセル、赤系の識別帯、持ち手付きラック |

給弾箱内部の弾列は視認性のための代表表示であり、外から 120 発すべてが見えるという意味ではありません。セルとラックは共通 X=0 の Mirror で左右対称に構成しています。給弾箱は筐体が対称、弾列の送り方向とアンバー表示は意図的な非対称です。

正本は Blender `+Z=上、-Y=正面`。アイコン用の相対寸法であり、新しいゲーム内 entity サイズや補給量を定義するものではありません。補給量の処理は既存 backend 側です。

## カプセル形状への更新

最新ラック revision は `SUPPLIES_V2_CAPSULE_01`。ユーザー承認後の弾体変更に合わせ、`src/client/java/jp/morrowgear/drone/client/MissileRenderState.java` 内の `MissileCapsuleShape.HULL` と同じ 11 断面、8 角、全長 0.80、最大径 0.38 を正本で再構成しました。先端は半径 0.11 の平面、後端は半径 0.10、中央には段差と識別帯の凹溝があります。ゲーム側の弾体 `+Z` を正本の `-Y` に対応させています。

外枠と上段 3 本・下段 2 本の配置、容量は維持し、旧尖頭形状と外付けカラーは除去しました。収納中の固定状態なので排気や発射煙はありません。赤い帯は同じ位置・半径で、点滅しない識別色として描画しています。給弾箱・兵装電力セルの正本および出荷資産は変更していません。

`reference.png` は最初の承認画像をそのまま保存しており、そこに描かれた尖った弾体だけは後続のカプセル承認に置き換わっています。旧ラックは `micro_missile_pack/before-capsule/` に保存し、`micro_missile_pack/capsule-comparison.png` に変更前後を掲載しています。

## 出力

各識別子のフォルダに以下を保存しています。

- `<id>.blend` / `<id>.glb`: 正本と交換用モデル。
- `hero.png` / `front.png` / `rear.png` / `top.png` / `bottom.png` / `left.png` / `right.png`: 同じモデルの 7 方向。
- `contact-sheet.png`: 7 方向の一覧。
- `icon-16.png` / `icon-32.png` / `icon-64.png` / `icon-128.png` / `icon-1024.png`: 同じ正本から直接描画した RGBA アイコン。
- `validation.json`: 境界、面数、鏡像、容量、参照画像・正本のハッシュ、各サイズの非空・非クリップ・RGBA 検査。

`approval-icons.png` は 3 種の全体と 128 / 32 / 16 ピクセルの原寸比較、`reference-comparison.png` は承認画像との比較です。シートは Blender 内の画像平面で描画しており、Python による画像加工は行っていません。

ゲーム側には `src/main/resources/assets/morrowgear_drone/` 以下の `items/<id>.json`、`models/item/<id>.json`、`textures/item/<id>.png` を追加しています。使用画像は正本の 128×128 RGBA と同一です。承認画像そのものを切り抜いてアイコンにしてはいません。

## 検査と範囲

`verification.json` で 3 モデルの GLB 読み戻し境界、正本のハッシュ、アイテム定義の参照先、出荷画像と正本 128 ピクセル画像の一致を検査します。ミサイルは 5 つの指定位置に正面から ray を通し、独立したカプセル前端が所定の `Y=-0.50` に存在することも確認します。弾体形状を参照した Java ファイルの SHA-256 を記録し、検査時の変更を検出します。

再生成時は `staged-runtime.png` を候補とし、GLB 読み戻しと全アイコン検査に成功してから 128×128 RGBA を出荷先へ切り替えます。`published-assets.json` に今回切り替えたファイルを記録します。

16 ピクセルでは細かな弾体や留め具の判別に限界があります。開蓋の横長箱、細長いシアンセル、2 段ラックの外形と色のまとまりを識別点としています。

これはアイテム用の正本と資産追加です。3 種の新しい MGM4、手持ち専用 renderer、可動機構は追加していません。母艦 V27 資産は別フォルダの完成版を維持しています。Gradle、ゲーム起動、インストール、コミット、push はこの作業では実行していません。

## 再生成

リポジトリ直下で実行します。

```powershell
& '../work/blender-portable/blender-5.2.0-windows-x64/blender.exe' --background --python-exit-code 1 --python tools/drone-design/blender/build_supplies_v2.py
```

`-- --only autocannon_magazine` / `laser_cell` / `micro_missile_pack` / `sheets` / `verify` で工程を限定できます。

`-- --only capsule` はラックのみを再生成し、共通比較シート・ラック 7 方向シート・最終検査・検証済みアイコン出荷まで実行します。他 2 種の正本・資産を再生成しません。

## 参照の解釈

原画像は斜め視点 1 枚と縮小アイコンの提示です。背面は既存 V23 装備と同じ graphite / titanium の材質構成で、整備パネル、排熱溝、固定部を補完しました。正本の幅をそれぞれ 1 とすると、給弾箱は開蓋・持ち手込みで約 1.44 の高さ、セルは約 1.56 の縦長、ラックは約 1.10 の高さです。独立した形状を優先し、3 個の同型箱にはしていません。

給弾箱の蓋は背面ヒンジを中心に 68 度開いた固定状態です。セルは残量窓が点灯した状態、ラックは 5 発搭載の状態です。いずれもアイコン用の固定状態で、閉蓋・取り出し・発射アニメーションは今回の出力に含めません。
