# Scout走査の表示契約

更新日: 2026-09-21。V22機体向けのクライアント描画だけを対象とする。

## 360度走査の意味

「360度レーザーカーテン」は、幅42度の薄い扇状光と走査先端が、100 tickで全方位を一周する表示を指す。360度全周を同時に覆う円筒状の壁ではない。回転位相は機体の`ageInTicks`から求める。

生存中・飛行中・給電中の実Scoutだけに表示する。着艦、接地、水中、溶岩中、電力喪失時には表示しない。走査表示から脅威報告、ダメージ、任務や検出結果を新しく生成しない。

## 発光と遮蔽

- `MorrowgearRenderTypes.energyBeam()`を再利用する。共有シェーダーや戦闘演出は変更しない。
- 環境光に依存しない弱いシアンの発光とし、夜間でも見えることを狙う。扇面の最大アルファは11/255、走査先端は76/255を維持する。シェーダーの横断方向・端点の減衰で輪郭を柔らかくする。
- Minecraft 26.2の逆深度比較`GREATER_THAN_OR_EQUAL`を使い、遮蔽を尊重する。深度への書込みは無効だが、深度テストは有効。最前面への移動、深度比較の無効化、強制的な透視表示は行わない。通常の霧も維持する。
- 地形・流体までのレイクリップ後、その手前にあるMobの境界まで終点を短縮する。崖など終点距離が大きく違う区間やMob接触部を扇面でつながない。
- 始点は毎フレームの補間済み機体位置・姿勢に追従する。地形側の終点のみをtick単位でキャッシュする。

## 負荷上限

- 描画距離64ブロック未満。距離44から64でフェードアウトする。
- 距離に応じて9/6/4本のレイ、1/2/4 tick間隔で終点を更新する。
- 前回の走査起点から0.75ブロック以上動いた場合は、次のtickから早期更新できる。同じ機体で同じtickに繰り返しレイを投げない。
- キャッシュは24機、全体で最大216レイ/tick。Mob境界の候補は1回の更新につき16体まで。

## 検証範囲

`ScoutScanVisualPolicyTest`で表示条件、扇の回転、距離別負荷、キャッシュ周期、高速移動、レイ予算、地形優先を確認する。`FlightVisualClientContractTest`で補間始点の接続、発光パス、深度比較、霧、低アルファの維持を確認する。

これらは自動試験であり、夜間の明るさや実ゲームの遮蔽表示を目視で合格とした証拠ではない。今回はGUI操作、再起動、インストールを行わない。昼夜、壁の手前・奥・部分遮蔽、高速旋回、複数機での実画面確認は最終バッチ反映後の確認項目とする。
