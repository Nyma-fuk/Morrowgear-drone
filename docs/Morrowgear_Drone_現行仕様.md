## 2. 製品の目的

Morrowgear: Drone Commandは、所有権を持つ常駐型ドローンをワールドへ展開し、個体・グループ・全機を統合戦術管理画面から指揮するためのFabric Modである。

現在の中核機能は次の6点である。

- 立体ドローンの展開、追従、待機、帰還、周回、Dock帰投
- 複数機を対象にした集合、隊形移動、地点上空の円形哨戒
- 実ワールド地形、機体、航路、Dockを重ねた統合戦術管理画面
- 生物追跡、脅威評価、Securityの自動迎撃と混成兵装管制
- Scout走査、Engineer作業、Cargo回収を連携した複合フィールド任務
- 最大8機の手動Wing編集と、複数Wingを独立制御する大規模群制御

## 3. 追加アイテムとレシピ

### フィールドコントローラー

- 右クリックまたは`K`キーで統合戦術管理画面を開く。
- レシピは銅インゴット、アメジストの欠片、レッドストーン、残響の欠片、試練の鍵を使用する。

### フィールドドローンユニット

- 右クリックで所有ドローンを1機展開する。
- サバイバルでは使用したユニットを1個消費する。
- レシピは鉄インゴット、銅ブロック、レッドストーンブロック、ブリーズロッド、ダイヤモンドを使用する。

### ドローンDock

- 対象面へ使用すると、水平な`3×3`のDockを一括設置する。
- 設置先には`3×3`すべての空間が必要となる。
- レシピは鉄ブロック、銅ブロック、ロードストーン、レッドストーンブロック、ブリーズロッドを使用する。

## 4. ドローン本体

### 基本特性

- 最大体力: 24
- 通常飛行速度上限: 0.44 block/tick
- 長距離追いつき速度上限: 0.96 block/tick
- Dock帰還巡航速度上限: 1.08 block/tick
- ノックバック耐性: 0.8
- 重力無効、落下距離を毎tickリセット、落下ダメージ無効
- 所有ドローンは永続化対象で、通常のMob距離消滅を行わない
- 機体IDは`MG-DRN-XXXXXX`形式で自動採番する
- 所有者UUIDと所有者名を保持する。シングルプレイではプレイヤーID変更時の所有権復旧を行う

### 立体表示

- 本体、前面センサー、十字アーム、4基のローター、着陸脚を持つ立体モデル
- 飛行中は4基のローターが交互方向に回転する
- Dock着艦中はローター回転を停止する

### 光源

- 飛行中は機体位置へ光源ブロックを追従配置する
- 機体から下方8ブロック以内に接地面がある場合、地表側にも補助光源を配置する
- Dock着艦中は機体光源と地表補助光源を除去する
- 複数機が同じ光源を共有している場合は、他機が使用中の光源を消去しない

## 5. 操作モード

| モード | 動作 |
|---|---|
| 待機 `STANDBY` | 現在位置で制動する。Dock上では完全停止する |
| 追従 `FOLLOW` | プレイヤー周囲へ機数に応じて分散し、視界を避けて追従する |
| 帰還 `RETURN` | プレイヤー近傍の固定オフセットへ戻り、到着後に待機へ移る |
| 周回 `ORBIT` | プレイヤーを中心に半径5ブロックで周回する |
| Dock帰投 `DOCK` | 割り当て済みDockへ進入し、着艦後に待機へ移る |
| 地点任務 `WAYPOINT` | 集合旋回、隊形移動、地点哨戒の3段階を実行する |

追従、帰還、地点任務、防御行動では緊急テレポートを使用しない。プレイヤーの高速移動やテレポート後も、機体は速度上限の範囲で目標まで飛行して復帰する。Dock着艦時のみ、最終進入で着艦点から0.22ブロック以内へ到達した機体を正確な停止座標へ固定する。

## 6. 群制御

### 常時衝突回避

- 各機は半径2.1ブロック以内の同一所有者ドローンを検出する。
- 近い機体から離れる分離ベクトルを飛行制御へ加算する。
- 分離補正の最大値は0.18で、急激な弾き飛ばしを抑える。
- 目標位置がブロック内の場合は、最大5ブロック上へずらして空間を確保する。

### 追従隊列

- プレイヤー周囲32地点の空き状況から空間開放度を0～1で評価する。
- 天井までの空間、空が見えるか、水・溶岩の近接、昼夜、プレイヤー水平速度、機数を入力として追従プロファイルを算出する。
- 開けた場所では、半径、高度、上下間隔、旋回速度、進行方向への前寄せを連続的に変化させる。
- 水・溶岩が近い場合は基準高度を1ブロック引き上げる。高速移動時は半径と前方間隔を広げ、旋回速度を落とす。
- 夜間は前方配置を増やし、光源機能が進行方向を照らしやすくする。
- 天井余裕3ブロック以下、または開放度0.42未満では旋回を停止し、左右と上下へずらしたコンパクトな縦列へ縮退する。
- 開放空間へ戻ると縦列から立体旋回へ自動復帰する。
- 複数選択で追従を指示した場合は、選択機へ共通の追従コホートIDを割り当てる。プレイヤーに最も近い機体だけをランク0の固定リーダーとし、残りをランク1以降の僚機とする。
- 追従開始時はリーダーを旋回先導機とし、後続機はランク順に同じ円弧を追う。事前に縦隊へ集合せず、120tickかけて追尾列から均等な円周配置へ展開する。
- 追従へ切り替える際は、以前の地点任務や生物追跡で保持していたコホートID、リーダーID、合流先を破棄する。各機が旧コホートの単独リーダーとして残ることを禁止する。
- リーダーの短時間Recoveryでは権限を維持し、頻繁な交代を防ぐ。Recovery開始から100tick以上経過して`RECOVERY-3`の場合、またはRecoveryが240tick継続した場合に権限を失効させる。
- 権限失効時は健全機のうちプレイヤーに最も近い機体へ正式移譲する。同距離の場合はバッテリー残量が多い機体、さらに同条件なら機体ID昇順を優先する。
- 選挙処理は健全機のうち機体IDが最小の1機だけが調停し、コホートID、リーダーID、全参加順位を一括更新する。
- 旧リーダーはRecovery側の僚機へ降格する。復旧しても自動復権せず、新リーダーの隊形へ再合流する。
- コホート所属機を削除する場合は、機体破棄より先に権限と参加順位を更新する。削除対象がリーダーなら即時に後継を選び、僚機なら既存リーダーを維持して順位だけを詰める。
- 削除時に健全機が存在しない場合は、Recovery段階が低い機体、プレイヤーに近い機体、バッテリー残量、機体IDの順で暫定リーダーを必ず選ぶ。

### 地点任務の隊形

| 任務機数 | 移動隊形 | 基本間隔 |
|---:|---|---:|
| 1機 | 単機 | - |
| 2機 | 縦列 | 前後2.4ブロック |
| 3～6機 | デルタ | 前後2.4、左右2.4ブロック以上 |
| 7機以上 | 星型 | 5方向、リング間4.0ブロック基準 |

隊形内では機体ごとに最大約0.85ブロックの高度差を付ける。先導機は任務IDのハッシュから選ぶため、展開順が最初の機体へ固定されない。後続機が担当スロットから11ブロック以上遅れた場合は、先導機の前進目標を現在位置から1.2ブロック先へ抑え、編隊の分断を防ぐ。

## 7. 地点指示の制御プロセス

### 7.1 指示受付

1. プレイヤーが個体、グループ、または全機を選択する。
2. 地図をダブルクリックするか、機体行を地図へドラッグする。
3. クライアントは画面座標をプレイヤー中心のワールド`X/Z`座標へ変換する。
4. 選択全機へ共通の`missionId`、予定機数、隊列インデックスを付けて送信する。
5. サーバーは機体の所有権と、指示地点がプレイヤーから各軸512ブロック以内であることを検証する。
6. 地表高度を取得し、各機を地点任務モードへ移す。

### 7.2 発艦と移動式合流

1. 地点移動、追跡、複数点ルートでは、Dock発進機を含む全選択機を最初から`MISSION_MOVING`へ置く。
2. Dock機は着艦点から発進し、飛行中の機体は現在位置から目的地へ向かう。プレイヤー中央の固定集合点へ戻らない。
3. 分散している機体は、目的地へ進むWingリーダーの後方スロットを移動式合流点として使用する。
4. 発進遅延、充電中、チャンク未読込、Recovery中の1機を理由に、正常機やScoutをプレイヤー中央で待機させない。
5. 保存データから読み込んだ旧`MISSION_MUSTER`状態は互換性のため処理できるが、新規地点・ルート指示では生成しない。

### 7.3 隊形移動 `MISSION_MOVING`

1. `missionId`が同じ機体を所有者単位で収集し、隊列インデックスと機体IDで並べる。
2. 任務IDごとに選出した機体をリーダーとして目的地点へ向かわせる。連続する任務で同じ展開順の機体へ固定しない。
3. 後続機は、リーダーの進行方向を基準に縦列、デルタ、星型の担当スロットを追従する。
4. 各機は比例制御で速度を調整する。通常応答率は0.36、目標直前では減速する。参加機が未合流でも、予定総数から決めた完成隊形のスロットを維持する。
5. 全参加機が同一コホートの通常隊列へ合流した後に限り、到着判定半径へ入った機体を地点哨戒へ移す。未合流機がいる間は先導隊を目的地直前で低速待機させる。
6. 飛行中の機体へ編隊任務を再割り当てした場合、後方に生成された隊列スロットへ戻らない。現在位置から目的地へ前進しながら横・高度方向を補正し、後続機の接近に合わせて通常隊列へ収束する。
7. Dock発進機が混在する場合、発進機だけが集合旋回を行う。すでに飛行中の機体は集合地点へ戻らず、新しい目的地への移動を継続する。

### 7.3.1 分散収束 `MISSION_CONVERGING`

1. 監視地点などへ散開している機体間の最大距離が、機数から算出する収束開始閾値を超えた場合に使用する。
2. 分散収束は地点哨戒へ直接移るための移動方式ではなく、通常の隊形移動へ入る前処理とする。
3. 任務設定時点で目的地までの直線距離が最も短い機体をリーダーに選ぶ。同距離の場合は機体IDの昇順で決定し、結果を再現可能にする。
4. リーダーはコホートの参加順位0を保持し、目的地へ向かって前進する。未合流機にも完成隊形の固定参加順位を予約し、`MISSION_CONVERGING`に置く。
5. 未合流機は、任務開始時の固定インデックスとリーダーのインデックスから決めた完成隊形の予約スロットを移動式合流点とする。開放空間ではデルタ・縦列・星型、地下や狭所ではコンパクト列を使用する。
6. 予約順位は収束中に変化しない。リーダーへの距離順を毎tick再計算しないため、接近中の機体同士で目標スロットが入れ替わらない。
7. 正常な未合流機が全て予約スロットから2.8ブロック以内へ入るまで`MISSION_CONVERGING`を維持する。全機の到着を確認した同じserver tickで、固定順位を保ったまま全対象を`MISSION_MOVING`へ一斉昇格する。
8. 合流中の先導隊は低速を維持し、一部の後続機が到着しただけでは加速しない。同期合流が成立した直後から、全機に通常の最高巡航速度を許可する。
9. 未合流機がいる状態で目的地まで18ブロック未満になった場合、先導隊の速度上限を0.22 block/tickへ下げる。全機合流前は地点哨戒へ遷移しない。
10. 通常隊形が分断された場合は凝集している隊列のリーダーとコホートIDを維持し、外れた機体だけ同じ固定スロットへの分散収束へ戻す。
11. 複数コホートが合流する場合は参加済み機数が多いコホートのリーダー権限を維持する。同数の場合はコホートIDで決定する。
12. 予約スロットまで16ブロック以上ある機体は最大1.08 block/tick、8～16ブロックでは0.78～1.08の可変上限で高速接近する。
13. 8ブロック以内では制動を開始し、7ブロック以内ではリーダー速度へ距離比例の接近速度を加える。3ブロック以内ではリーダー速度への同期を優先し、スロット通過を防ぐ。
14. Recovery中の機体は同期合流の成立判定から一時的に除外する。正常編隊は任務を継続し、Recovery解除後の機体を同じ同期方式で再合流させる。
15. 13機以上の任務は、任務IDと目的地を共有したまま最大8機のウイングへ分割する。各ウイングは固有のリーダー、コホートID、固定順位を持つ。
16. 合流完了、先導速度、分断復旧はウイング内の機数と隊形実寸で判定する。別ウイングの未合流機を理由に正常なウイングを加減速させない。
17. 複数ウイングは移動中に単一コホートへ強制統合しない。地点到着後に共通の哨戒円へ統合する。
18. 複数ウイングは任務開始地点から目的地へ引いた共通航路軸を使用し、左右8.5ブロック、高度3.4ブロックを基準とする独立アンカーへ滑らかに分散する。
19. `MISSION_CONVERGING`は任務開始時の初回集合だけに使用する。いったん`MISSION_MOVING`へ移行したウイングは、スロット距離や一時的な障害物回避を理由に`MISSION_CONVERGING`へ戻さない。
20. 巡航中に予約スロットから7.0ブロック以上遅れた僚機は、`MISSION_MOVING`を維持したまま`CATCH-UP`速度制御へ入る。3.5ブロック以内へ復帰するまで最大1.08 block/tickを許可する。
21. リーダーはCATCH-UP機を待つための減速や停止を行わず、通常の最高編隊速度で任務を継続する。CATCH-UPは個体航法の補正であり、任務フェーズではない。

### 7.3.2 ハイブリッド群制御と自律復旧

1. 中央側は`missionId`、目的地、参加機数、隊列インデックスという任務意図を共有する。
2. 各機は経路探索、衝突回避、停滞検出、復旧、到着判定を個別に実行する。
3. 1機の停滞や経路探索失敗は他機の個別航法を停止させない。ただし隊列未完成のまま任務完了へ遷移することは許可せず、先導隊は低速前進または目的地直前で待機する。
4. 停滞を検出した機体は、`RECOVERY-1`の局所迂回、`RECOVERY-2`の広域側方・上方退避、`RECOVERY-3`の樹冠上脱出を順に試す。
5. 復旧中もテレポートは使わず、飛行可能な局所目標へ向けて通常の飛行制御を行う。
6. 安定した前進を検出すると復旧段階を解除し、現在の任務へ復帰する。
7. 戦術UIの機体一覧と任務一覧には復旧中の段階を`RECOVERY-n`として表示する。

### 7.3.3 Wing指揮権と一時離脱

1. 永続的なWing所属と、その瞬間に隊形航行を先導する飛行指揮権を別の状態として扱う。サービス帰還や戦闘迎撃へ一時離脱しても、機体のWing、任務ID、ルート、Dock所属は失わない。
2. 現リーダーがDockへのサービス帰還、緊急迎撃、または通常戦闘へ移行した場合、その機体をWingの航行・到着判定・ルート進行の参加機から一時的に除外する。残存機は離脱機を待たず、現在の任務を継続する。
3. リーダー離脱時は同一コホートの健全な残存機から、現在の任務目標に最も近い機体を後継にする。同距離では飛行用バッテリー残量、既存参加順位、機体IDの順で決定する。
4. 指揮権委譲ではコホート自体を作り直さず、コホートIDとWing所属を維持したままリーダーIDと参加順位を一括更新する。これにより航路、旋回層、任務進捗を中断しない。
5. 新リーダーが有効な間は再選挙を行わない。旧リーダーが充電または迎撃を終えて復帰しても自動復権させず、空いている末尾スロットから僚機として滑らかに再合流させる。
6. 一時離脱中の機体にも周回ルートの現在ポイントを同期する。復帰機は古いポイントへ逆行せず、Wingが現在航行している区間へ合流する。
7. 複数Wingの共通任務では、各Wingの有効な飛行リーダーをルート到着判定へ使用する。物理的に不在の旧リーダーIDを到着待ちの条件に残さない。
8. Wing全機が帰還または迎撃で一時離脱した場合は新規リーダーを作らない。最初に任務へ復帰した機体が既存任務を引き継ぎ、以後は通常の安定指揮規則を適用する。

### 7.4 地点哨戒 `MISSION_ORBIT`

1. 指定地点の地表基準位置から6ブロック上を旋回中心とする。
2. 旋回半径は`max(5.4, 機数×3.4÷2π)`で決める。
3. 各機を円周上へ均等配置し、機数が増えるほど機体間隔を保つため半径を拡大する。
4. 旋回速度は0.038 rad/tickとする。
5. 同じ地点へ再指示するまで旋回を継続する。
6. 旋回円周とその内外0.9ブロックを16～32方向で走査し、最も高い衝突地形から2.6ブロック以上離れた共有旋回面を使用する。
7. 旋回面は任務単位で共有し、20tickごと、または中心が3ブロック以上移動した場合に再評価する。
8. 必要な上昇は即時反映する。下降は1ブロックの不感帯と4回連続の安全確認を経て、1回0.35ブロック以下で行う。
9. 旋回中の局所回避は同じ旋回面での左右回避を優先し、横方向の退路がない場合だけ上昇する。
10. 12機以下では予定総数分の円周スロットを任務開始時から予約し、参加数が増えても先着機のスロット番号を変更しない。
11. 13機以上では、到着判定と旋回進入をウイング単位で行う。各ウイングは3.8ブロックずつ高度を離した独立円軌道を使用し、単機ごとの断続的な円周再配置やウイング間結合を行わない。
12. ウイング内に正常な`MISSION_CONVERGING`機が残る場合、リーダーを含む一部の`MISSION_MOVING`機だけを哨戒へ移さない。初回集合と到着の両方が成立した時点でウイング単位に進入する。
13. Recovery中の未合流機だけが残る場合は、割当機数の60%以上が到着していれば正常機による先行哨戒を許可する。Recovery機は復帰後に同じ旋回層へ追加する。
14. 既に同一ウイングの一部が哨戒中の場合、後着した`MISSION_MOVING`または旧状態の`MISSION_CONVERGING`機を保存済み旋回位相へ直接参加させる。
15. 複数ウイングの旋回半径は下層ほど広く、上層ほど狭くする。1層あたり0.65ブロック、全体で最大7.2ブロックの半径差を設け、全層で円錐型の外形を形成する。旋回進入中も完成後と同じ層半径を使う。

#### 旋回進入 `MISSION_ORBIT_ENTRY`

1. 隊形移動中のコホートが到着判定へ入ると、リーダーの現在位置から旋回開始角を算出し、全参加機で共有する。
2. リーダーを最初の旋回者とし、後続機は参加順位ごとに約3.4ブロック相当の位相差で同じ円弧を追う。
3. 旋回前に縦隊へ整列したり、集合地点へ戻ったりしない。移動隊形のまま円軌道へ接続する。
4. 50tickの進入中に位相差を広げる。前半で必要な間隔の約75%を形成し、後続機をゆったり待たずに進入順で円弧へ並べる。
5. 遅れて到着したRecovery機は、すでに成立した哨戒隊の共有旋回位相へ後着参加する。

### 7.5 生物追跡任務

1. 地図上の生物マーカーをダブルクリックするか、選択機をマーカーへドラッグする。
2. サーバーは対象が生存中の`LivingEntity`で、指示者本人ではなく、512ブロック以内にいることを検証する。
3. 地点任務と同じ集合旋回、隊形移動、到着後の円形監視を使用する。
4. 目的座標は対象の現在位置へ毎tick更新される。対象が移動すると編隊も飛行して追従する。
5. 対象が死亡、消滅、または別Dimensionへ移動した場合は、最後に保存した座標を監視地点として維持する。
6. 対象が地下にいる場合は対象直上の地表から2.4ブロック上を安全観測点とする。岩盤や地形を通過して対象本体へ接近しない。
7. 対象が水中または溶岩中にいる場合は、`WORLD_SURFACE`から求めた液面上2.4ブロックを安全観測点とする。深さにかかわらず流体内へ潜航しない。
8. 安全観測点のX/Zは対象位置へ毎tick追従する。編隊が到着判定半径へ入ると旋回進入を開始し、`TARGET WATCH`へ遷移する。

### 7.6 脅威評価

所有者ごとに1tick 1回だけ周辺状況を評価し、同じ所有者の全機で結果を共有する。評価範囲は生物が水平24・垂直12ブロック、飛来物が32ブロックである。評価値は次の二軸へ分離する。

| 評価値 | 算出要素 |
|---|---|
| 敵固有脅威 | 最大体力、攻撃力、防具値、移動速度を主成分とし、Warden、Wither、Ender Dragonなどの特殊能力を補正する。名前や固定一覧だけに依存しないため、同じMinecraft属性を持つMod追加Mobも自動評価する |
| プレイヤー危険度 | プレイヤーとの距離、現在プレイヤーを標的にしているか、直近10秒以内に攻撃したか、飛翔体が身体領域へ命中すると予測されたかを評価する |
| 群集補正 | 2体目以降の敵数に応じ、敵固有脅威とプレイヤー危険度の両方へ加算する |
| 環境補正 | 夜間、低ブロック光量、空が見えない地形、暗い出現可能面をプレイヤー危険度へ加算する。ただし生存する攻撃対象がなければ迎撃しない |

表示用合成スコアは`敵固有脅威×0.72 + プレイヤー危険度×0.58`を0～100へ制限し、従来どおり`LOW 0-5`、`GUARDED 6-13`、`HIGH 14-27`、`CRITICAL 28以上`へ分類する。

### 7.7 脅威連動方針

脅威度によるプレイヤー近傍への集合、防御壁形成、飛来物への身代わり配置、近接敵の押し戻しは廃止する。脅威評価は警告表示、Scoutデータリンク、Securityの迎撃対象と投入数の決定に使用する。脅威度だけを理由として、追従・待機・帰還・周回・地点任務中の非選抜機がプレイヤーへ接近したり、現在の隊形を変更したりすることはない。

プレイヤー周辺で検出した生存中の敵は所有者単位の戦闘ネットワークへ共有する。選抜されたSecurityのみが元の任務またはDockから離脱して標的へ向かい、交戦終了後は元の状態へ復帰する。飛来物だけを検出し、攻撃可能な発射主体を特定できない場合は、機体をプレイヤー前方へ移動させない。

### 7.8 Security交戦管制

Securityはプレイヤー周辺の脅威ネットワークまたは警戒範囲内の敵を標的として、サーバー権威の交戦処理を行う。攻撃へ投入する機数は敵固有脅威、プレイヤー危険度、敵数、標的体力、利用可能なSecurity数、交戦損耗から算出し、最大8機とする。任務中の全Securityを無条件に呼び戻さず、非選抜機は元の警戒・護衛任務を維持する。

#### 7.8.1 迎撃トリガー

| 優先層 | トリガー | 検出条件 | 迎撃対象 | 更新周期 |
|---:|---|---|---|---:|
| 1 | プレイヤーへの直接危機 | プレイヤーを標的にしているMob、直近10秒以内の攻撃者、または身体領域へ命中予測された飛翔体 | 攻撃者。飛翔体は生存中の射手を特定できる場合に限り射手 | 1 tick評価、10 tick配信 |
| 2 | プレイヤー周辺の敵 | プレイヤーから水平24・垂直12ブロック以内の`Enemy` | 脅威スコアが最も高い生存Entity | 1 tick評価、10 tick配信 |
| 3 | 展開中Scoutの発見 | 周回、フィールド任務、Waypoint、Entity追跡中のScoutから水平28・垂直14ブロック以内 | 最寄りの敵対Entity | 10 tick |
| 4 | Security警戒範囲の接触 | 指定アンカーの警戒半径・上下12ブロック以内 | アンカーに最も近い`Enemy` | 5 tick |
| 4 | 複合フィールド任務のGUARD接触 | 作業・搬送中心からフィールド半径・上下12ブロック以内 | 作業中心に最も近い`Enemy` | 5 tick |

暗所、空が見えない地形、将来スポーン可能面は脅威度と投入判断を補正するが、生存中の攻撃対象Entityが存在しない限り、それ単独では`INTERCEPT`や`COMBAT`を開始しない。射手を特定できない飛翔体だけを理由に攻撃対象を捏造しない。

#### 7.8.2 優先順位と投入数

1. `PLAYER-GUARD`報告はScout報告より常に優先する。同一優先層では脅威スコア、報告時刻、Entity IDの順で決定する。
2. 有効な緊急迎撃対象は、各機が持つ通常のSecurity警戒・フィールドGUARD対象より優先する。
3. 迎撃候補はRecovery中またはバッテリー15%未満の機体を通常は除外する。プレイヤー危機で通常候補が0機の場合に限り、Recovery中でないバッテリー5%以上の機体を緊急投入する。
4. 候補内では、報告元と同じWing、待機中、飛行中、バッテリー残量、任務拘束の少なさ、対象までの距離、Unit IDの順で評価する。内部配点は同Wing `+120`、待機 `+70`、非着艦 `+35`、バッテリー最大 `+30`、任務中 `-25`である。
5. 必要機数は`ceil((敵固有脅威×0.72 + プレイヤー危険度×0.58 + 損耗圧力×0.85) / 14)`を基本とし、1～8機へ制限する。Warden級や高体力・高火力のMod追加Mobには通常Mobより多く投入する。
6. 実際の攻撃参加数は敵数、標的の体力、利用可能機数からも再計算し、両方式の大きい値を採用する。既に同じ標的と交戦中の機体数を下回らない。
7. 交戦中の生存標的はロックし、地形回避による到着遅延や10 tickごとの再評価だけでは`COMBAT`を解除しない。標的死亡、消失、Recovery移行、兵装継続不能など明示的な終了条件で解除する。
8. 交戦中は参加機の体力低下率、飛行電力消費、兵装電力消費、撃墜数を標的別に記録する。これらを損耗圧力へ変換し、増援数を動的に再計算する。

#### 7.8.3 戦闘空域共有

同一所有者・同一Dimension・同一標的へ向かう一時攻撃要素は、Wing、迎撃／警戒／フィールドの戦闘チャンネル、兵装種別から一意な要素キーを作り、全要素の予約座標を共有する。要素キーを決定的に並べ、次の空域を割り当てる。

- レーザー要素は群内の等角度間隔を維持しつつ、要素間で旋回高度を2.25ブロック、半径を1.35ブロック、位相をずらす。
- レーザー軌道が天井や地形へ接触する場合は、群全スロットが衝突しない共通の上方シフトを選ぶ。各機が別々の高度へ逃げて等間隔を崩すことはしない。
- 機関砲CAS要素は要素間で八の字の進入軸、位相、高度帯を分離する。異なるWingが同じ中心線と交点を同時通過しない。
- ミサイルは要素ごとに進入方位と発射高度を分離する。
- `FLARE_ENTRY`、攻撃離脱、`REJOIN`も同じ空域割当を使い、兵装状態の前後だけ同一座標へ収束しないようにする。
- 群内スロットと群間空域は別に管理する。群内の等間隔制御を群間分離で崩さない。

攻撃参加機は`FLARE_ENTRY`で機体のシアン発光部と短い飛行軌跡を赤橙色へ切り替えてから兵装状態へ遷移する。エネルギーは機体内部で生成するため、機体から外へ伸びる放射線は表示せず、機体下部の発光レンズと小さな内周リングだけを脈動させる。兵装状態へ入った時点で既存の軌跡を消去し、`GUN_RUN`、`LASER_CHARGE`、`LASER_FIRE`、`MISSILE_APPROACH`、`MISSILE_EGRESS`、`RAM_APPROACH`では航行軌跡を描画しない。`REJOIN`では戦闘終了とWing復帰を示す短いグリーン軌跡へ切り替える。曳光線、充填発光、レーザー光線、ミサイル排気は兵装固有エフェクトとして継続する。

| 兵装 | 状態と挙動 |
|---|---|
| 機関砲 | `GUN_RUN`。同じ標的を担当する機銃機だけでCAS要素を編成し、遠方進入点で70 tickの隊形成立時間を確保してから、全長約104ブロックの八の字を先頭機から順に時間差で追従する。遠方高高度から降下し、目標付近の低高度直線区間で機首前方へ毎秒10発で線状に掃射し、反対側へ上昇離脱する。発射後の弾道は再誘導しない。着弾ごとに音量と音程を調整したVanilla爆発音と小規模爆発を発生させる。地形損傷は着弾ごとに最大1ブロックで、硬度0.5以下は毎射、1.5以下は3射に1回、3.0以下は8射に1回、3.0超・破壊不能・Block Entityは破壊しない |
| 高出力レーザー | `LASER_CHARGE`で敵胴体付近を円形に周回し、機体中心下部の射出口を標的へ向ける。エネルギーは機体内部で生成するため、充填中は外部から射出口へ向かう線や標的への予告線を表示しない。射出口レンズ、内周、中心核だけを充填率に応じて高輝度化する。充填完了後は同一照射群の全機同期を優先する。最初の成立機から24 tick以内に全機が軌道スロットと射線条件を満たせば一斉照射し、未成立機が残る場合は24 tickで75%以上、60 tickで成立済み機から照射を開始する。遅延機は自身の条件成立後に既存照射へ合流する。発射後は敵頭上の円軌道を維持し、標的が死亡するか照射可能時間へ達するまで照射を続ける |
| 誘導ミサイル | `MISSILE_APPROACH`で発射位置を確保し、射出後に上昇して標的上空からトップアタックする。地形は破壊せず、搭載弾数だけを消費する |
| 体当たり | `RAM_APPROACH`。弾薬とレーザー余力がなく、所有者の体力が低い場合に限る最終迎撃である。速度に応じて標的へダメージを与え、機体自身も衝撃ダメージを受ける |

機関砲の曳光線とレーザーは既存パーティクル列ではなく、クライアント側の専用`RenderPipeline`とエネルギービーム用シェーダーで描画する。ビーム面はカメラ方向へ追従するリボンジオメトリとし、透明度を反映する加算合成、深度書き込み無効の専用エフェクト層でワールドへ合成する。交戦管制が確定させた射出口と標的の間では、地形との微小な深度交差によってビーム中央だけが欠落しないよう、ビーム本体の連続性を優先する。フラグメントシェーダーは半径方向のソフトエッジ、両端の短い減衰、時間で流れるパルスと微細ノイズを生成し、視点角度や距離による板ポリゴン感を抑える。

機関砲弾は射口から照準点までの全長線ではなく、約2ブロック長の有限な曳光弾としてフレームごとに前進させる。高出力レーザーは低透明度の熱層、赤色プラズマ外層、橙色内層、白熱コア、周辺フィラメント、着弾二重コロナを重ねる。レーザー旋回は通常航法と隊形反発から分離し、円周上の次tick位置から接線速度を先読みする専用制御を使う。速度上限は0.46 block/tickとする。CAS飛行も通常航法と隊形反発から分離し、各編隊スロットの次tick位置を先読みして速度上限0.92 block/tickで共通航路を維持する。命中、遮蔽物、ダメージ、弾薬、熱量はサーバー側で判定する。機関砲は240発、ミサイルは4発を標準搭載し、レーザーは照射で熱量が上昇する。HEAT 900以上ではレーザーだけを停止し、機体は任務空域に残って自然冷却する。900未満まで冷却すると再び交戦候補へ戻る。HEAT単独ではDockへ帰還しない。Dock着艦中も弾薬補充、冷却、飛行用バッテリーと兵装用電力の充電を並行する。

レーザーは充填開始時の敵個体を照射終了までロックする。別の敵が近づいた場合や、機関砲・別の一時戦闘群が航路を横切った場合も目標ID、照射群、旋回スロットを変更しない。対象が死亡するか敵性を失った場合のみロックを解除する。

敵1体へ割り当てる攻撃機数は、敵個体の脅威、プレイヤー危険度、敵の体力、接触数、交戦中の損耗・飛行電力・兵装電力消費から1〜8機で決定する。8機は敵1体あたりの安全上限であり、Wingの総数とは別である。Dockサービス中の機体を代替した増援機は、必要戦力を満たしている限り交戦を継続する。サービス完了機は増援機を押し出さず、増援機が離脱した哨戒・ルート・地点・フィールド任務を引き継ぐ。損耗などで戦闘群に欠員が生じた時だけ再投入される。

GUN_RUNの八の字航路は、敵の実座標へ瞬時に追従させず、1tickあたり水平0.72、上下0.35ブロックを上限とする安定化機動中心を使用する。敵の実座標は照準へ使用する。敵との水平距離が9ブロック以下になった場合は固定方向へ25ブロック離脱し、高度を9ブロック上げる。17ブロック以上の間隔を確保した時点で元のCAS航路へ戻る。離脱中は最高1.14 block/tick、通常GUN_RUNは最高0.92 block/tickとする。高速移動または瞬間移動する標的には機体スロット許容誤差を最大8ブロックまで段階的に広げ、移動予測を加えた胴体照準を使用する。低速標的には従来の地表掃射線を維持する。

機関砲弾は射出口から照準点までの線分上で最初に衝突したEntityまたはブロックを実着弾点とする。生物へ直接命中した場合は投射物由来の直撃ダメージ2.4を与える。着弾点ではこれと独立して半径1.55ブロックの小規模爆発を発生させ、爆心の1.25から距離に応じて0.25まで減衰する爆発ダメージを与える。遮蔽物で爆心から見通せない対象には爆発ダメージを与えない。直撃と爆発は異なるDamageSourceとして扱い、地形破壊は従来どおりブロック硬度と射撃間隔に応じて制限する。

戦闘標的が死亡、消滅、または投入数再評価によって担当外になった機体は、兵装状態から直接`IDLE`や通常待機へ落とさず、`COMBAT REJOIN`へ移行する。戦闘開始時の`WAYPOINT`、`FOLLOW`、地点警戒、フィールド任務、Wing、コホート、周回ルートを保持し、迎撃用の一時目標だけを解除して元の航行へ復帰する。旧リーダーを含む復帰機は現在のWingリーダーへ僚機として合流する。Dockから直接発進した迎撃機だけはDockへ帰還する。再合流表示は24tick維持し、その後に戦闘状態だけを`IDLE`へ戻す。この復帰モードは保存され、交戦中のワールド再読込でも失われない。

飛行用バッテリーと兵装用電力は独立して保存する。飛行用バッテリーはホバリング、巡航、最高速の順で消費量が増える。サービス帰還中は急な隊形補正を行わない効率巡航として、遠距離でも巡航消費3を適用する。0%では推力を失って水平速度を減衰させながら緊急降下する。機関砲は1射2、レーザー充填中は満充填へ達するまで1 tickあたり2、レーザー照射は1 tickあたり3、ミサイルは1発80の兵装電力を消費する。満充填後の同期待機中は兵装用電力を消費しない。標準照射可能時間は129 tickであり、8機編成が同期照射へ入りやすい余力を確保する。兵装電力0%では攻撃を中止して再合流するが、飛行用バッテリーが残っていれば帰投できる。旧バージョンの保存機体に`WeaponPower`がない場合は100%として読み込み、既存アイテムや飛行用バッテリーを変更しない。

兵装別Security機への分離を次期外観仕様とする。機関砲機、レーザー機、ミサイル機は固定搭載兵装、機体シルエット、発光部、アイコン、クラフト用モジュールを分ける。既存Security機の消失を防ぐため、従来機は自動兵装型として互換維持し、兵装固定データと新規アイテムは外観案の承認後に追加する。

## 8. 飛行制御

- 目標距離から要求速度を算出し、現在速度へ滑らかに合成する
- 通常巡航速度上限は0.44 block/tick、長距離追いつき速度上限は0.96 block/tick
- 分散収束の遠距離最高速度は1.08 block/tick。近距離ではリーダー速度へ同期する
- 通常応答率は0.36、Dock最終進入時は0.46
- 直接脅威への迎撃速度上限は0.95 block/tick、`HIGH`以上の防御移動は0.82 block/tick
- Dock帰還は遠距離で1.08 block/tickまで加速し、24ブロック手前から0.28 block/tickへ連続的に減速する。最終着艦は0.14 block/tick
- 複数点ルートは18ブロック手前から次区間へ曲率を付ける。頂点の6.5ブロック圏へ入るか、前区間を82%以上進み曲線の横ずれが22.5ブロック以内になった時点で次区間へ引き継ぐ。曲線が頂点を迂回してもポイント1で停止しない
- ルート目標の水平変化を1tickあたり3.5ブロック、高度変化を0.45ブロックへ制限し、目標座標の飛びを防ぐ
- ルート操舵は水平加速度0.055、上下加速度0.032を上限とし、速度ベクトルを連続的に変化させる
- 長距離高度計画は停止上昇を行わず、最大30ブロック先を見ながら水平移動と上昇・下降を同時に行う
- 目標から0.35ブロック以内では速度を35%へ落とす
- 水平方向の移動ベクトルへ機首方位を合わせ、1tickあたり最大6度で旋回する
- 停止中は速度を22%ずつ減衰し、微小速度をゼロへ丸める

### 航行軌跡の表示規則

| 状態 | 表示 | 目的 |
|---|---|---|
| 単機・Wingの地点移動、複数点ルート、通常隊形移動、RETURN | シアン | 航路と進行方向の可視化 |
| `MISSION_CONVERGING`、`CATCH-UP` | 高輝度シアン | 合流・追いつき機の識別 |
| サービス帰還、Dockへの充電・補給帰還 | アンバー | 任務離脱と帰投理由の識別 |
| `COMBAT REJOIN` | グリーン | 交戦終了後のWing復帰を表示 |
| `FLARE_ENTRY` | 赤橙 | 戦闘モードへの移行を表示 |
| 待機、着艦、地点旋回、作業・警戒旋回 | なし | 常設円軌道による画面占有を防ぐ |
| 機関砲、レーザー、ミサイル、体当たりの攻撃中 | なし | 兵装固有エフェクトと標的の視認性を優先 |

状態が別の表示色へ切り替わる場合は旧軌跡を消去し、異なる意味の色を一本の線へ混在させない。`NONE`状態へ入った場合も航行軌跡を即時消去する。複数点ルートでは旋回中に一時減速しても既存軌跡を維持し、実際に移動しているtickだけ新しい制御点を追加する。

### 障害物回避と機体保全

- 通常の目標位置へ直進できるかを0.45ブロック間隔で機体当たり判定ごと検査する。
- 直進経路が塞がっている場合はMinecraft標準の`FlyingPathNavigation`で3次元経路を探索する。
- 通常追従対象が地下や樹冠下にいる場合は、空中を直線で突き抜けず、読み込まれた空間内の通行可能ノードを辿る。生物追跡任務では地下対象の直上地表を安全観測点とする。
- 経路飛行中も速度要求は直近ノードではなく最終目的地までの残距離から算出し、長距離移動が小刻みな減速の連続にならないようにする。
- 現在ノードから最大6ノード先、かつ9ブロック以内を調べ、衝突と流体侵入なしで直行できる最遠ノードまで短縮する。
- 経路ノードの到達半径は1.6ブロックとし、微細なノードごとの旋回と停滞を抑える。
- 移動目標が4ブロック以上変化した場合、または30tick経過した場合に経路を再計算する。追跡対象の小さな動きでは既存経路を維持する。
- 経路飛行時の応答率は0.48とし、最終目的地へ接近した時点で通常の減速制御へ戻る。Dock接近と最終着艦には適用しない。
- 水と水際には高い経路コスト、溶岩、火炎、ダメージ地形には進入禁止コストを設定する。葉は通過せず迂回を優先する。
- 一般目標が浅い水中・溶岩内にある場合は流体外へ持ち上げる。生物追跡任務では深度に依存せず`WORLD_SURFACE`上2.4ブロックを観測点とし、潜航しない。
- 直進と標準経路の両方が使えない場合は、前後左右、斜め、上昇、下降を組み合わせた3次元局所候補を採点する。通常は高度維持を優先するが、天井や上部障害物に拘束された場合は下降経路も選択する。
- 目的地まで10ブロック以上あり直進できない場合は、左右8、14、22、34、50、72ブロック、上下最大68ブロックの候補を段階的に評価する。現在位置から候補、候補から目的地まで機体サイズの衝突回廊が通る経路を優先する。
- 戦略迂回は選択した左右方向とウェイポイントを最大160tick保持する。目的地が近づいても障害物の角を回り切る前には破棄せず、目的地への直線が開いた時点で解除する。
- 戦略迂回中は個体間分離ベクトルを一時停止し、機体同士の反発で迂回線から押し戻されることを防ぐ。障害物通過後は通常の編隊維持へ戻る。
- 候補点が未読込チャンク、ワールド上下限、機体サイズで通れない空間、水・溶岩を含む場合は採用しない。
- 水・溶岩への接触、水平・垂直衝突、または30tick相当の停滞を検出すると、通常目標を一時中断して最大45tickの退避を行う。
- 退避中は機体サイズの衝突回廊が通る乾いた空間を優先し、上昇だけでなく横・後方・下降も評価する。復旧後は元の追従、Regroup、編隊移動、作業、Dock帰投へ戻り、テレポートは使用しない。

## 9. Dock

- Dockと機体は1対1で割り当てる
- 新しい機体の展開時、64ブロック以内に未使用Dockがあれば自動割り当てする
- 同じDockを別機へ割り当てると、以前の割り当てを解除する
- 上空から着艦点まで機体サイズの衝突回廊が空いていれば、Dock中央の5ブロック上から垂直進入する
- 上空が塞がれている場合は、Dockの前後左右4方向を評価し、外側待機点から入口ゲート、着艦点まで連続して通過できる経路を選ぶ
- 側面進入はDock外側4.5ブロックの待機点、入口から1.55ブロックのゲート、中央着艦点の3段階で行い、斜め横断による着艦未完了を防ぐ
- 最終着艦以外のDock接近にも共通3次元ナビゲーションを適用し、屋根、床、壁、樹冠を迂回する。全方向が物理的に閉鎖されている場合は安全位置で待機し、経路が開くまで再評価する
- 着艦座標はDock中央、高さ0.29ブロック。V2の中央着艦面に合わせ、機体下面が浮いて見えない位置へ固定する
- 着艦時はDockの向きへ機首を固定し、プレイヤーを追尾して向きを変えない
- `3×3`のどの構成ブロックを破壊してもDock全体を撤去し、Dockアイテムを1個ドロップする

### サービス・補給

- Dockサービスは無償回復ではなく、Dock Block Entityが保持する電力・修理材・弾薬を消費する
- 飛行用バッテリーは共通蓄電から充電する。残量が要求量未満でも、電力入力スロットに電源アイテムがあれば次の1個を消費して蓄電へ加算する
- 兵装用電力は1ポイントの回復につき共通蓄電を2消費する
- 修理材は銅インゴットで耐久4、鉄インゴットで8、Morrow Alloyで20を回復する
- 機関砲弾は鉄塊1個から24発、ミサイルはロケット花火1個から1発を補充する
- レーザー熱量は着艦中に自然冷却し、HEATだけを理由に帰投は行わない
- 必要資源が不足した場合はサービス状態を維持し、データリンクへ`DOCK WAIT / REPAIR MATERIAL`、`DOCK WAIT / AMMUNITION`、`DOCK WAIT / POWER SUPPLY`と、飛行電力・兵装電力・弾薬の現在値/必要値を表示する
- 通常再出撃は飛行電力90%、兵装電力90%と兵装別の標準搭載量を要求する。Operation Aegisが高脅威または損耗中の戦線で戦力不足を検出した場合は、飛行電力65%、兵装電力65%と使用可能な兵装を満たした整備中機を戦術配分へ戻す
- 整備中も最新のOperation Aegis戦況を受信する。帰還前とは別の高脅威が出現した場合も、新しい戦線割当を受けて緊急再出撃できる
- 修理、飛行用充電、兵装用充電、弾薬補給が完了すると、保存していた任務または交戦へ復帰する。既に必要戦力が満たされている場合は増援機を押し出さず、空いた任務を引き継ぐ

### 浮遊サービス充電Dock

- ソーラー式の浮遊サービス充電Dockは飛行用バッテリーだけを非接触充電する。修理、兵装用電力、弾薬は通常Dockで行う
- 1基につき同時充電は最大3機とし、満員時は低残量機を優先する待機列を構成する
- 待機機は充電機の軌道と干渉しない、より広く高い保持円を旋回する。表示状態は`SOLAR HOLD / QUEUE n`とする
- 充電枠が空くと待機列の先頭を自動昇格し、充電子機が対象機を追従して充電ビームを照射する
- 通常Dockへ安全に帰投できる場合、満員の浮遊Dockは機体を不必要に拘束しない。通常Dockが実質的に到達不能な場合だけ待機列を退避先として選ぶ
- HUD上部へ`GRID 基数:使用中/容量`、待機数`Qn`、低残量数`LOWn`を集約表示する

### 基地防衛作戦

- `/morrowgear_base create`は80×80の防護基地、32基のDock、4個Wingを生成する。各Dockには演習用の電力セル16、鉄インゴット32を格納し、機関砲Dockへ鉄塊64、ミサイルDockへロケット花火16を追加する
- `/morrowgear_base defense`または基地コンソールの`DEFENSE`から自動防衛作戦を開始する
- 作戦は`ALERT`、24体の`CONTACT`、サービス猶予、48体の`ASSAULT`、サービス猶予、76体の`SIEGE`、完了の順で進行する
- 基地センサーは基地中心から水平72、上下28ブロックの敵対Entityを検知し、プレイヤー近傍センサーを待たず既存のFleet Threat Networkへ共有する
- 敵は四方の戦線から出現し、HUDへ作戦段階、残存敵数、波数、北・東・南・西の戦線状況を統合表示する
- 各波の間は7秒のサービス猶予を設け、帰投、充電、修理、再武装、増援交代を実際のDock資源で処理する
- 全波排除後は`SECTOR SECURE / DEFENSE OPERATION COMPLETE`を通知して終了する

## 11. 保存と更新互換性

機体は次の情報をワールドへ保存する。

- 所有者UUID、所有者名、機体ID、グループID
- モード、飛行用バッテリー値、兵装用電力
- Dock座標、着艦状態、進入段階
- 目的地点、任務ID、予定機数、隊列インデックス、任務段階
- 追跡対象UUID、最新の脅威スコア
- 集合中心、任務開始tick
- コホートID、固定リーダーID、参加順位、現在の移動式合流座標
- 役割、Cargo搬出元・搬入先、Cargo内部アイテム、搬送状態
- フィールド任務種別、アンカー、半径、進捗、Security警戒範囲
- 機体光源と地表補助光源の位置

Dockは所有者UUID、所有者名、設置方向を保存する。機体・アイテム・ブロックの登録IDはバージョン更新で変更しない方針とし、既存ワールドの機体消失を防ぐ。

範囲採掘などの共有走査台帳はセッション単位である。再起動時は不完全な台帳へ作業を再接続せず、対象機を安全に待機へ戻す。Waypoint、Cargo経路、Security警戒、所有権、役割、Wing、Cargo内容は復元する。

未読込チャンクに含まれる走査位置は完了扱いにせず保留し、チャンク読込後に再走査する。Engineerは対象チャンクが読み込まれるまで採掘を待機する。同じ任務IDが再利用されても、任務種別、中心、半径が異なる場合は古い共有走査台帳を破棄して新しい条件へ置換する。

フィールド任務のY座標はクライアント側の地図表示値をそのまま使用せず、サーバー側の実地形から決定する。鉱石採掘は地表から16ブロック下、範囲除去と森林作業は地表直下を基準とする。

Engineer単独任務では水平半径3～4ブロックの局所調査だけを行う。Scoutが同じ任務IDへ参加している場合、Engineerは広域走査を行わず`ENGINEER / DATA LINK`で待機する。Scoutは指定された全領域を走査し、鉱石、幹、葉、除去対象ブロックに加えて、空間、固体、流体の調査結果を共有台帳へ記録する。走査完了後、Engineerは共有された任務領域内の全対象を処理する。

鉱石採掘、範囲除去、森林作業にはEngineerが必須である。Scoutは広域走査、Cargoは回収と搬送、SecurityはGUARDとして作業・搬送護衛を担当する。Engineerを含まない選択では作業命令を有効化しない。

### 複合フィールド任務の役割別状態

| 役割 | 状態 | 動作 |

| Scout | `SCOUT / WORK ORBIT` | Engineer作業完了まで作業円上空を旋回する |
| Scout | `SCOUT / CARGO ESCORT` | 作業完了後、搬送中のCargoへ随伴する |

### 任務編隊の適用範囲

編隊制御における「全参加機」は、同一所有者が一度の地点指定または追跡指示で選択し、同一の`missionId`を割り当てられた機体を指す。所有中の全ドローンや、別の哨戒ポイント・別任務に割り当てられた機体は含まない。

分散状態では目的地に最も近い参加機をリーダーにする。リーダーは目的地へ進みながら合流率に応じて速度を制限する。後続機は移動するリーダーの後方スロットへ収束し、合流した順に固定ランクを得る。合流済み機だけでも逐次隊形を形成し、未合流機はJOIN状態のまま空きスロットへ接近する。全参加機が合流した時点で完成隊形となり、最高速度で目的地へ向かう。

目的地到着後は、収束中の遅延機によって哨戒任務全体を停止させない。完成編隊は全機を一括して地点哨戒へ移す。未完成の場合も、到着済みコホートが参加機の60%以上に達するか、未合流機がRecovery状態なら到着済みコホートを地点哨戒へ移す。遅延機は同じ任務とコホートを維持し、哨戒中のリーダー側へ飛行して合流後に地点哨戒へ遷移する。

### 飛行姿勢

- ヨーは水平方向の実移動ベクトルへ向け、速度に応じた最大旋回角で追従する。
- 前進加速では機首を下げ、上昇では機首を上げる。
- ロールは機体の右軸を基準にし、左右の移動方向と一致させる。
- Dock着艦中は水平姿勢へ戻す。
